# 会话输入、技能设置与启动更新检查

适用版本：**0.4.3**。原有模型、工具、历史和授权保持；平台及真实账号限制见更新说明。

## 边执行，边补充

Agent 思考、输出或运行工具时，输入行继续显示，可以编辑。进入 `/setup`（终端里也可运行 `koder setup`），选择「回答中的输入方式」。

- **引导模式（默认）**：回车提交的是当前任务的补充。当前请求继续执行，补充在现有回复或工具批次结束后的下一个安全模型步骤进入同一回合。不会为了补充而取消、重放已完成操作。已发出的 HTTP 请求无法事后修改；“已接收”不等于模型已经处理。
- **排队模式**：回车保存为下一回合，按先后顺序执行。终端显示「排队 N」和最多三条短预览，每条最多 64 个字符。当前任务继续。

设置保存为 `sessionInputMode`；未配置或值无效时采用 `steer`。斜杠命令交给原命令分发器，在下一回合处理。外部引擎、执行已结束或当前步骤无法接收补充时，会明确提示转入队列。不会创建第二个 Agent 会话。补充收件箱上限为 32 条、每条 16,384 字符、合计 65,536 字符；沿用原步数限制，补充可能增加一次付费模型调用。

忙时按 Esc 或 Ctrl+C 可以停止。整行输入下列词语也可以，英文忽略大小写：`/cancel`、`/stop`、`/abort`、`停`、`停下`、`停止`、`取消`、`中断`、`打断`、`别做了`、`先停下`、`stop`、`cancel`、`abort`、`never mind`、`scratch that`。这些词开头、后接标点时，先停止，再把后半句追加到原队列。例如「停下，改为只解释原理」会排队「改为只解释原理」。原队列顺序保留；句中提到“如何停止服务”等文字不会触发停止。

审批出现时，审批提示暂时接管输入行。之前排队的任务不能回答审批；未发出的草稿另行保留，必须在提示出现后重新回答。停止不代表撤销已经完成的外部操作，仍遵守原回执与结果核对规则。

## 技能开关

在「设置 → 技能 / Skills」里选择具体内置方法、生态技能、兼容/打包技能或本机资源合集，开启或关闭。开启资源合集会明确提示：允许将选中的资料片段发给用户配置的模型。涉及独立授权的个性化功能继续由「记忆与灵魂」管理；本菜单不授予账号、学习、工具或系统权限。

「一键关闭全部」需要确认，关闭当前发现的可开关项目，保留文件、来源说明和已有未知禁用 ID。以后新导入的技能仍需单独管理。若加密合集无法打开，会显示原因，不会把部分关闭说成全部关闭。

复用 `growthSkillEnabled`、`disabledSkills`、`disabledPortableSkills` 与合集 `modelAccess`。从 `/setup` 修改后，当前聊天下回合生效；其他正在运行的会话重开后生效。不删除文件、不新增云同步；原 `koder growth on|off`、技能和资源命令继续可用。

## 每次启动检查更新

已接受许可、由安装器管理的交互式 `koder` / `koder chat` 每次启动都检查一次原官方 CLI 更新清单，不受“六小时内已检查”缓存限制。显示检查开始、当前最新/发现更新或检查未完成。之后的定期检查继续使用原缓存。这检查的是受管 CLI 发布通道，不会扫描任意第三方软件或依赖更新。

`KODER_AUTO_UPDATE=0` 或 `koder update auto off` 同时跳过自动扫描和安装。非 TTY/CI、未接受许可、非受管安装及显式镜像覆盖继续按原规则跳过；手动 `/update --check` 仍可使用。检查不阻塞输入，沿用八秒时限；失败不会宣称“已是最新”。

安装仍等待原空闲条件：没有执行中的任务、队列、草稿及待处理输入字节。原 EULA、安装器校验、激活和重启规则保留。

## 十项手动核验

使用独立安装目录与测试工程；真实模型可能计费，本地自动测试使用自有桩接口。

1. 开启自动更新，六小时内连续打开两次聊天。每次分别显示一次检查开始及结果。
2. 设置 `KODER_AUTO_UPDATE=0` 后启动。应无自动扫描和安装；`koder update auto status` 显示进程覆盖状态。
3. 在 `/setup → 技能` 关闭一个兼容技能。重新打开确认仍关闭，`/skills show <id>` 应报 `SKILL_DISABLED`；再开启可恢复读取。
4. 选择一键关闭全部，先取消确认无变化，再确认。所有已发现的可开关项目应关闭，文件仍在。
5. 设置输入方式为排队，退出并重新打开 Setup，仍显示排队；再切回引导核对。
6. 排队模式运行慢任务，中途提交两条消息。观察排队 1/2 与预览；回合结束后按顺序执行两条任务。
7. 引导模式运行慢任务，中途补充要求。当前请求不取消；后续模型请求或会话记录包含补充，仍属同一回合。无密钥测试还核对相同控制器。
8. 忙时提交「停下」或 `stop`，应停止；再测 `stop, say NEXT`，应停止并排队 `say NEXT`。
9. 两种模式分别测试 Esc 与 Ctrl+C。取消后聊天仍可用；若有待批准操作，取消不能执行它。
10. 写文件审批出现前排队一条任务，并保留另一份未发送草稿。审批必须等新回答；预敲内容不能批准。拒绝后核对文件未写、队列和草稿保留。

本地终端与桩接口验收不能代替 Windows Console/ConPTY/IME 实机、真实模型质量、账号及生产安装验收。实际命令、历史失败与未验范围以交件记录为准。

## 0.4.9 输入可靠性更新

忙碌时也可按 / 打开菜单，选择后仅填草稿，回车按当前引导/排队设置提交。菜单打开时 Esc 先关闭菜单，再按 Esc 可停止任务；Ctrl+C 始终停止当前任务。审批接管输入时菜单暂停，预先排队的文本不算批准。

本地引导等待会话准备完成，并在下一安全模型边界使用。远程引导等待常驻服务实际回执；拒绝显示 STEER_NOT_RUNNING、STEER_TURN_FINISHING、STEER_INBOX_FULL 或 STEER_RECOVERY_ONLY，再排队。接收状态未知显示 AGENTD_STEER_NOT_ACCEPTED，不自动重复提交；核对当前结果后再补充。没有引导端口的外部引擎仅排队，Setup 会说明。

取消词必须是整行，或后接标点再附后续任务；stop a server 是普通任务。stop, say NEXT 先取消，再将 say NEXT 加到原 FIFO 队列。

请先运行 koder --version 和 koder doctor。旧 0.3.0 没有这些模块，不能通过改设置补出；升级后再验收。新包不能改写尚未升级的旧包开屏。0.4.4-candidate.2 仍是旧候选，不代表已安装最新发行版。本轮不替用户安装本机版本。

无密钥回归覆盖真实 readline、CLI/harness 和本机 IPC；Windows Console、ConPTY、IME 及用户原生终端手测仍须分别记录。
