# Koder CLI 0.4.8

本版修复当前聊天开启软件自动更新失败，加入自然语言开关，并保留完整 0.4.7 模型发现和既有功能。Windows 与 macOS 使用同一版本化运行包。

0.4.8 修复了聊天中开启自动更新时的 `createAutomaticUpdater is not defined` 错误。原来配置已保存，但当前窗口无法重建更新器；现在会在本窗口检查新版，等待任务、排队输入和草稿处理完后自动安装，并恢复会话。

## 开启和关闭

在 Koder 聊天输入以下任意一种：

```text
/update auto on
开启自动更新
帮我开启 Koder 自动更新
```

也可以在系统终端运行 `koder update auto on`，再进入 `koder`。不需要配置模型来切换这个本地设置。关闭用 `/update auto off` 或“关闭自动更新”，查看用 `/update auto status` 或“查看自动更新状态”。同一窗口关闭后再开启也会立即重新检查。

## 何时安装

官方受管安装版在交互会话启动时检查一次，运行中每六小时检查。任务进行中、输入排队或有未发送草稿时等待；后台下载不会占住任务输入。安装器和运行包均校验，安装完成才请求重启。退出会话会取消所属更新作业，不会在无终端时凭空启动另一套更新服务。

`ask`、plan/report/enhance 只读模式仅查看状态，不开启安装。`KODER_AUTO_UPDATE=0` 明确禁止当前进程自动更新；即使保存设置为开启，状态也会同时说明环境覆盖。CI、无交互终端、非受管源码启动不会后台安装。许可文本改变需重新阅读和同意。

如果网络或校验失败，保留原安装和错误状态，不声称已经更新。可稍后重试或使用 `/update`；这与本版修复的开关初始化异常不同。软件自动更新和 Setup → 模型 → 自动获取最新模型是独立设置，后者不会替换软件或擅自切换当前模型。

## 从旧版获得修复

0.4.7 及近期旧版可先运行一次 `koder update`，然后核对 `koder --version` 为 0.4.8。这一步用于安装旧版尚不具备的修复；升级后开启自动更新无需再次手动更新。若更早更新器拒绝超过 100 MB 的包清单，请从官网下载当前安装器覆盖升级，保留配置和历史。

本轮 57 项更新回归通过，涵盖真实聊天命令、自然语言、本地安装器子进程、开关切换、不中断输入、许可变更和会话恢复。测试使用隔离临时目录与协议桩；Windows 原生控制台与实机安装仍是独立未验项。
