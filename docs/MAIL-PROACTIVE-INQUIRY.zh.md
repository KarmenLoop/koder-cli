# 收信主动问询与授权码输入

适用版本：0.4.3。Windows 输入修复与问询已进包；原生设备及真实邮箱验收边界见文末。

在 `/setup → 邮箱与收信提醒 → 绑定邮箱` 输入客户端授权码或应用专用密码。输入会显示星号，支持粘贴、退格、Ctrl+U 清空和 Ctrl+C 取消。不会显示原文，也不会把授权码放入聊天历史或后续任务队列。Windows 粘贴边界和退格控制字符不会成为密码的一部分。不要把授权码贴入聊天消息或命令参数。

绑定成功后，按顺序启用：

```text
/mail model on
/mail inquire on
```

第一项允许邮件进入所选模型，确认词为 `allow-mail-model`。第二项开启主动问询，确认词为 `allow-mail-inquire`。也可以在 Setup 中分别操作。两项都不会开启 `/mail auto`，更不会授予自动发送权。收信提醒也必须开启；关闭模型读取或收信提醒会同时停用主动问询。重新开启提醒不会偷偷恢复问询。

## 收信后怎么处理

Koder 或 `koder mail watch` 运行时，每 30 秒使用原有 IMAP/POP 收信连接检查一次；当前 0.4.10 可用 /mail monitor on 授权后台检查，详见 [发送与后台提醒](MAIL-DELIVERY.zh.md)。有明确选择、需要回复或正在跟进的邮件，才会给出短提示。普通低相关来信保持沉默；广告和验证码不进入问询或模型摘要。验证码仍通过本地 `/mail code <id>` 显式查看。

例如客服问“换货还是退款”，你会看到选项 A、B。当前聊天中可回复 `B`、`选 退款`，或 `其它：先退款，也提一下包装破损`。助手只起草回信，展示 From、To、Subject、Body。邮件正文、选项文字和引用都属于不可信资料，不能替用户授权发送或修改设置。

- `发送` / `send`：打开完整最终预览，随后仍需输入 `send` 确认。`--yes` 不跳过此步骤。
- `改：补充要求`：按照新的要求重新起草。
- `取消` / `忽略`：关闭当前问询。
- 任意不符合这些短操作的输入仍作为正常任务，不会被邮件吞掉。

多个问题同时出现时，使用带邮件 ID 的命令准确选择：

```text
/mail inquiries
/mail choose 9:1 B
/mail choose 9:1 --text "先退款，不评论包装"
/mail send-inquiry 9:1
/mail dismiss 9:1
/mail followups
```

只有当前聚焦的问询会接收 A/B。发送取消时保留草稿；模型需要补充信息时回到待选择；账号切换、邮件变化、Reply-To 与 From 不一致或授权撤销时拒绝继续。SMTP 结果不确定会明确提示核对已发送邮件，禁止自动重发。成功的发送收据已保存但问询状态尚未落盘时，恢复会依据收据补记跟进，不再提供重复发送。

## 安静时段、上限和跟进

```text
/mail inquire on --inquire-limit 5 --follow-up-days 14 --draft-language auto --quiet-hours 23:00-08:00
/mail inquire off
```

默认每天最多 5 次问询/相关轻提醒，跟进 14 天，草稿按来信语言选择中文或英文。支持显式指定其它两字母语言代码。明确选择的识别目前覆盖中英文换货/退款、是否确认及分行 A/B 选项；不能可靠提取选项时仅提示查看，不编造用户决定。不会为了新信默认调用模型；用户选择后才调用现有 BYOK 模型起草。

安静时段内的待选择问题保留在加密存储中，可以通过 `/mail inquiries` 主动查看；下一次非安静时段检查时补提示一次，仍受日上限限制。已有日上限用尽后新邮件保留在收件箱，可能不创建问询；使用 `/mail check`、`/mail read` 手动处理。邮件状态与另一个终端共用原有私有文件锁，同一邮件 ID 不会生成两份待选择问题。

重新打开聊天也遵守安静时段与当前授权。只恢复已提醒过的待处理项；因安静时段或预算仍未提醒的邮件，继续交由原轮询判断，不能靠重新打开窗口绕过限制。同一线程正文未变化的重复来信不会再次询问已经做过的选择。

发送成功后按 References、In-Reply-To、规范化主题和对方地址关联后续邮件。对方表示退款完成或已发货时，提示“邮件称已处理，尚未独立核实”。不会把对方来信当作支付/物流已完成的独立证据。超过期限结束自动加权，不继续重复催问。

设置与问询、草稿、跟进均复用当前账号作用域内的加密邮件存储，不新建明文邮箱数据库。`policy.json` 中的 `proactiveInquiry`、`inquireMinScore`、`maxInquiriesPerDay`、`followUpDays`、`draftLanguage`、`quietHours` 由确认后的设置命令维护；普通配置文件不能替代确认授予邮件读取或发送权。

## 后台与验证边界

前台 chat、`mail check`、`mail watch` 复用原收信连接。未开启常驻时，关闭它们会停止查收。0.4.3 可用 `koder activate` 开启用户级常驻；在 Setup → 常驻与主动提醒中另行打开邮箱可见性，同时保留邮箱通知、问询和模型读取授权。后台只问询，不自动发信。

宿主的日上限、安静时段与邮箱自身规则共同限制提醒。系统通知默认隐藏私人正文；调用被接受不等于已在屏幕显示。通知点击续接尚未实现，使用 `koder mail inquiries` 回到待处理项。更多步骤见 [常驻教程](ALWAYS-ON.zh.md)。

本机验收使用合成邮箱、真实本地 TLS IMAP/SMTP、加密文件与脚本模型；没有读取个人邮件或向真人发信。Windows 10/11 实机 ConPTY/IME、真实邮箱服务及真实模型草稿质量需要分别验收。macOS PTY 和模拟 Windows 字节序列通过不等于 Windows 实机通过。
