## 为什么有文件仍然没有完成

50 题复考先前的 `out 48/50` 是目录产物覆盖率，不是正确率。文件数量、`FULL` 标签、模型回复“完成”或单独一个 `SKIP.md` 都不能证明满足题意。验收需要分别核对必要输入、文件清单、实际自检回执和内容质量。

本轮检查定位了以下具体缺口，并在现有实现中修复，没有增加平行执行器或重复 Skill。

| 缺口 | 修复行为 | 仍不能代表什么 |
| --- | --- | --- |
| 按完整百万 token 窗口预留每次费用，小请求也被过早停止 | 在原剩余预算内计算本次输入上限，主会话和子任务真正按此投影；保留完整输出预留、已花费用和并发预留 | 不是降低价格、重置费用或无限请求 |
| 本地预检没有发请求，却被归为 API 故障或未知费用 | 仅对有“请求未发送”证据的本地失败释放该次预留 | 传输后的未知账单仍然是未知 |
| 有答案但没有验算；先检查再改文件还能复用旧结果 | 现有 `delivery_check` 增加只读声明式检查，终局重新读文件；原始数字数组变更不能刷过 | 不自动证明算法、文学或领域结论正确 |
| 验算参数第一次无效，正确重试后仍被永久判失败 | 无效参数保留诊断，实际求值的约束参与最终重验 | 已求值的失败约束不能通过换宽松预期抹掉 |
| 模型抄错可选文字锚点，修正后旧断言持续阻挡收官 | 先实际读回未变的文件，再精确引用旧调用及索引、更正理由；保留旧错误和更正证据 | 只适用于失败的可选文字锚点，不可修改数值约束、通过的断言或用户交付合约 |
| 修复建议有记录，但没有进入下一次模型请求 | 补件和截断恢复指令送入同一任务的实际请求末尾 | 不重置根任务、期限、取消或费用 |
| 截断恢复提示持续干扰后续正常步骤 | 恢复提示只作用于下一次完整回复；已用恢复次数继续保留 | 不执行残缺工具参数，也不无限重试 |
| 自检后只读 `ls` / `cat` 被当作文件修改 | 仅对确认成功、通过既有风险分类的有限只读命令保留自检；文件哈希仍须一致 | 未知命令、写入、重定向没有豁免 |
| 多章稿件字数达标但从未读回正文 | 有逐章长度合约的多章交付，要求读回当前正文；修改后重新读回，并反馈视角、人物、时刻、因果、章节引用核对项 | 读回是可观察动作，不是语义正确证明 |
| 源码中新增工具存在，打包内核缺少对应模块 | 将运行时动态选择的验算模块加入原内核打包入口，并在脱离桌面源码的包中执行一次真实工具调用 | 不代表全部平台已经实机验收 |
| 新任务建立后立即重复保存同样的学习恢复节点 | 项目创建时绑定真实会话，把已落盘的创建节点作为初始检查点；并发编辑或恢复旧任务仍走原检查点逻辑 | 不关闭学习、事务日志、来源检查或 fsync |

## 怎样使用验算

普通问答不强制创建文件。对需要交件的任务，明确输出目录、必需文件、原始输入和验证要求，例如：

> 根据当前工作区的数字输入计算汇总，保留原数据；将结果写入 out/report/，从输入重新计算并核对结果，最后返回文件路径和实际验证结果。缺少数据时说明缺什么，不自行补造。

候选的 `delivery_check` 支持三种声明：

- `json-number`：从 `sourcePath` / `sourcePointer` 指向的数字数组计算 sum、mean、min、max、product、count，比较目标 JSON 字段。CSV 或对象表应使用真实验证脚本。
- `json-equal`：`expectedJson` 使用 JSON 字符串保留数字、布尔、数组等类型，避免接口规范化后把数字误变字符串。
- `text-includes`：核对文字锚点。它不能判断跨章因果、人物关系或事实真伪。

若只是模型自己抄错可选锚点，用 `read_file` 读回同一文件后，可在检查中传 `corrects: {callId, index, reason}`，引用原来失败的工具调用和索引。宿主确认原文件摘要未变、原检查确实失败、读回内容一致且新文字实际存在，才接受更正。`correctedChecks` 保留旧文字、理由和读回摘要。这不是修改用户必含文字的授权；数值条件和冻结合约不提供此接口。

已有合约验证脚本时，优先运行它并做内容审阅；宿主已检查的清单、摘要和字数不再要求模型逐项复制成第二套断言。发现独立缺陷才补充检查，避免验证本身变成耗尽预算的循环。

每次最多 32 条声明，单文件最多 200 KB，总读取最多 1 MB；终局最多重验 32 条不同的已求值约束。限制的是检查器的数据范围，不是任务工具次数。数值为 IEEE-754，容差显式声明。该工具只读，不执行用户提供的代码，不替代命令审批。

多章任务在 `taskDeliveryEvidence.writingReview` 中给出 `readBack`、`pending`、`notChecked`。当前单次 `read_file` 范围内的正文必须以实际工具结果读回，不能用模型自报代替；超出读取范围仍明确列出未检查。任何一次读回都不自动获得“内容质量通过”标签。

失败经验进入已有的本地学习存储，只保存过程规则和原因码。后续同类任务需要新的真实验证，才能提升经验状态；不保存答案或金标，不自动上传云端。本地遥测默认开启，仍可在 Setup 关闭。

## 真实模型验收

固定 MiniMax-M3.1-Flash，没有切换更大模型。完整输入对照 Q901 / Q902 是独立的链路测试，不能加到原 SELECTED-50 的分数里。每题沿用取消、权限、360 秒或题设期限和 2 CNY 的本地估算预算；估算价格不是官方报价或账单。

| 对照 | 实际结果 | 质量边界 |
| --- | --- | --- |
| Q901 数值交付，第三轮 | 6 个要求文件落盘，退出 0；31 次模型请求，实际校验进程退出 0；汇总 2947，独立复核清单摘要 | 完整输入的数值链路通过，不是原卷成绩 |
| Q902 三章写作，第四轮 | 9 个要求文件落盘，退出 0；26 次模型请求，实际校验进程退出 0；正文统计 1045 / 1067 / 1033 | 只通过文件、字数与指定检查；人工读稿仍发现人数、时刻和章节引用矛盾，未通过内容质量验收 |
| Q902 三章写作，第五轮 | 9 个文件和三章读回均齐；44 次模型请求后原费用预算停止，退出 3 | 模型将“十一个小时”抄成“十一小时”，修正锚点后旧断言仍阻挡收官；这次失败促成可追溯的锚点更正修复，未计为成功 |
| Q902 三章写作，第六轮 | 第 2 次请求发生 `MODEL_STREAM_INTERRUPTED`，没有完整服务商用量；保存 SKIP，退出 3 | 未验证修复后的真实模型完整交付；保留未知费用预留，停止付费重试，不据此填写 0 用量或成功 |

在 Q902 暴露矛盾后，已补上多章正文读回机制；第五轮又暴露自检纠错死循环。各轮结果单独保留，不用一次结构通过覆盖旧失败。

原 SELECTED-50 的后续隔离运行保存了 **50/50 out、50 个 SKIP、0 个 checked**。其中至少 34 题可检测到任务正文缺段；其余题也不能据此认定输入完整。原十题同样保留 SKIP 结果。缺失的公式、数据、原文或任务段不能靠编造或读取金标补齐。因此 **原卷质量门槛尚未通过，候选不作为达标正式版发布**。

## 回归范围

本次 `npm run test:headless-meta` 为 **161 项通过、0 失败**，覆盖文件清单、短路径、拒权、取消、费用、截断、只读观察、验算、经验、正文读回以及实际 CLI 退出状态。内核预算/验算 **18 项通过**；验算集成与任务指导 **38 项通过**。这些集合有交叉，不能相加当作唯一测试数。

学习初始化、账户切换、会话恢复、真实进程中断与事务恢复的定向回归为 **43 项通过、0 失败**。其中原有一条测试曾将关闭技能后的未执行调用期望为成功，现按实际 `SKILL_DISABLED` 返回未完成（退出 3）；关闭后不生成学习库的断言保留。

独立打包内核的功能测试通过，在没有桌面源码的临时目录内执行完整回合及验算工具。启动性能仍未达标：首次本地模拟模型请求原测约 2.68 秒，单独复查约 3.10 秒；去掉重复初始检查点后，本次测量约 **2.40 秒**，仍高于原有 1 秒门槛。单次计时存在波动，不作为稳定提速比例；没有放宽断言。CPU 采样显示学习库初始化、事务日志和会话持久化的 `fsync` 占据明显耗时；本轮只减少重复提交，保留持久化与恢复验证，进一步优化仍待完成。因此不能说“打包测试全部通过”。隔离夹具不计入考试分数。

Windows、Ubuntu 实机和真实邮箱仍是 **NOT_RUN**；这次没有操作测试用户邮箱、开启后台服务或替代 beta 专员验收。修复的 macOS 本地执行证据不能外推到所有平台。

## 更新入口

在系统终端运行 `koder update`，或在 Koder 对话中输入 `/update`。也可说“版本更新”或“更新版本”：精确的更新意图进入同一个受管更新器，读取官方版本清单，沿用现有校验、安装与恢复流程；无需模型临时搜索 GitHub 安装包。

“不要版本更新”、引用他人的更新文字、讨论项目版本号都不应触发安装。`ask` 及只读聊天模式只检查，不安装。`koder update auto status` 可查看自动更新状态。没有新正式版时，不会把本文中的候选补丁当作最新可安装版本。

本轮只修改 GitHub 文档和私有源码，没有改官网生产内容、DNS、仓库可见性、历史、stars 或许可。
