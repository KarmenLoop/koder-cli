# Koder CLI 0.4.18：实际调用修复

Windows 和 macOS 安装入口同步至同一版。运行 `koder update`，结束当前会话后重新打开，再运行 `koder --version`，应显示 `0.4.18`。官网提供 PowerShell、CMD 和 macOS 安装入口，已有配置与历史继续保留。

## 这次具体修了什么

1. **MCP 长操作提前中断**：过去即使任务还在工作，SDK 约 20 秒、外层传输约 30 秒就可能截断结果。现在获批 MCP 工具调用默认可等待 180 秒，外层留出收尾与回执时间。连接诊断仍快速失败；取消仍有效，结果未知的操作不自动重放。这是单次工具等待时间，不是整个任务的工具次数上限。
2. **邮箱重启漏提醒、待提醒队列积满**：前台不再只处理本次新邮件，也会恢复已保存的待提醒事件。busy 时先排队，真正打印后才确认消费；显示失败、退出前尚未显示的事件继续保留。积满 1000 条后可以排空并恢复收件处理。
3. **下载 Skill 后入口不完整**：GitHub 下载的 Skill 进入 Setup 技能清单，可以单独关闭、重新开启，也纳入“一键关闭全部”。唯一短名称可以用于 `$名称`、`--skill 名称` 和 `skills show 名称`。Agent 调用仍使用准确 ID，重名要选完整 ID；本地包优先，读取与启用均不授予电脑权限。

## 手把手检查

更新后用 `koder mcp list` 查看已有连接，再用 `koder mcp test <连接名>` 检查发现。给 Agent 一个已授权、可核对结果的任务；取消时仍应停下。遇到 UNKNOWN 请核对服务端实际结果，不要重复提交。

邮箱用 `koder mail status` 查看连接与待提醒数量。保持终端中的 `koder mail watch` 或已授权的后台监控运行。前台提醒显示后待提醒数应减少；重启后未显示的提醒应恢复。SMTP accepted 仅代表服务器接受，不代表对方已收到。真实 163 邮箱还需用户账户实测；不要发送授权码到聊天。

下载的技能用 `koder skills list --json` 找到 ID；`koder skills disable <id>` 关闭，`koder skills enable <id>` 恢复。Setup → 技能里也能看到同一项。选中方法后由原工具执行，脚本不会因为下载自动运行。

## 验证与保留项

本地实际 MCP 子进程完成 33 秒调用并把结果传回 Agent；TLS IMAP/POP/SMTP 使用合成账号核对发送及回执；Skill 读取后实际写出文件。另有重启、失败重试、1000 条提醒队列及长任务/费用/取消回归。原失败输出保留。

默认工具轮次不限，保留取消、费用预算、审批、多窗口隔离及 1800 课教材。Windows 10/11 原生冷启动和 MCP 图形操作交由 beta 专员；真实邮箱、付费模型与原生通知不以本地夹具冒充验收。macOS 锁屏原生组件仍是未签名候选。
