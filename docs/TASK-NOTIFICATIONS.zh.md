# 任务完成提醒

此功能随 Koder CLI 提供，无需模型密钥，也不要求先激活 agentd。它在任务结束后决定是否提醒你；主动提醒仍使用原来的 `agentd.proactive` 配置。

## 开始使用

```text
koder notifications status
koder notifications test task-done
koder notifications task-done off
koder notifications task-done on
```

手动测试直接诊断系统通道，不受自动提醒的安静时段或 CI 静默规则控制，也不计入自动任务提醒预算。第一次先发送测试通知，再到系统通知设置检查 Koder 或脚本宿主是否允许显示。测试命令只测试通知通道，不会执行原任务、发送邮件或修改电脑权限。`submitted` 表示系统通知程序接受了请求，不保证通知已经出现在屏幕上。

Setup 的通知设置可以关闭任务提醒、调整长任务阈值并发送测试通知。关闭任务完成提醒不停止 agentd、网关、邮件监控或正在运行的任务；关闭主动提醒也不会代替关闭任务完成提醒。

## 何时提醒

默认把两分钟及以上的任务视为长任务。交互输入的闲聊、模型流式片段、Todo 单项勾选、引导补充被接收，都不会各自触发一次“完成”。通知在整轮任务结束、最终输出处理完成后评估。

| 情形 | 默认行为 |
| --- | --- |
| 当前终端前台且有明确焦点，任务成功（含长任务） | 沉默，直接看终端结果；明确要求通知除外 |
| 失焦或焦点未知，长任务结束 | 提醒 |
| 已明确失焦，短任务成功 | 沉默；可通过配置开启 |
| 后台任务成功 | 提醒 |
| 任务失败 | 提醒；可关闭 |
| 等待审批、登录或用户输入 | 提醒；不会代替用户批准 |
| 用户取消 | 沉默；可开启 |
| 用户明确说“做完通知我” | 作为通知候选，仍服从开关、安静时段和日上限 |
| 没有桌面会话或处于 CI | 不发送，返回明确原因 |

焦点检测只使用终端进程/控制台元数据和当前输入活动。长任务连续一分钟没有键盘输入可以判为失焦。检测不到时记录 `unknown`，不索取辅助功能或屏幕录制权限，也不把“终端进程仍运行”当作用户一定在看。

## 安静时段、预算与去重

默认沿用主动提醒的安静时段：23:00–08:00。任务完成通道可单独设置。成功提醒在安静时段保留最近三条候选，结束安静后合并处理；后台 agentd 可在已有唤醒周期处理，未激活时可在下一次 CLI 通知处理或显式 flush 时处理。退出 CLI 不会偷偷创建新的常驻服务。

等待用户输入、以及耗时达到长任务阈值的失败可以打破安静时段，仍受每日上限限制。任务完成每天默认最多尝试 20 条，与主动提醒的每日预算分开。同一任务去重，提醒始终归属任务开始时的账号；中途切换账号不会把旧任务或续聊入口转给新账号。系统通知与允许的后备渠道每次发送前都会重新检查账号和当前设置；关闭提醒或撤掉渠道后停止后续发送。派发前先写入持久收据；结果不明时不自动重发，也不再向第二渠道发送。

## 查看结果并继续会话

系统通知隐藏原始任务、邮件正文、代码和完整差异。通知给出通用结果、耗时及继续处理的方法。

```text
koder status
koder notifications status
koder open <通知中的不透明令牌>
```

`open` 只查找当前账号所属的原工作区和已持久化会话，再打开聊天；不会重新提交已经执行的任务。令牌不是命令代码。切换账号、记录过期或工作区无法核实，会拒绝恢复而不会猜测另一个项目。临时回合或关闭历史存储的会话不能持久续聊，会明确报告这一限制，不会新建会话后冒充原对话。

Windows 可通过当前用户的协议注册接入通知按钮。未注册、被其它程序占用或不能核实处理程序时，使用文字命令继续；不要求管理员，也不覆盖其它软件的协议注册。Linux/macOS 的最低可用路径是上述文字命令，`clickSupported: false` 会明确表示不能依赖点击。三端点击是否实机通过见验收表。

网关对话使用独立的渠道历史。此候选会在网关回复发送结果确定后提醒；续聊目前提示返回原渠道，不会打开同名的终端会话冒充原对话。

## 配置示例

在原 Koder 配置中增加此字段即可，其他配置保留：

```json
{
  "notifications": {
    "taskDone": {
      "enabled": true,
      "longTaskMs": 120000,
      "unfocusedIdleMs": 60000,
      "notifyShortSuccessWhenUnfocused": false,
      "notifyOnCancel": false,
      "notifyOnFail": true,
      "notifyOnNeedsInput": true,
      "maxTaskDonePerDay": 20,
      "channels": ["os-notification"],
      "collapseQueuedAfterQuiet": 3
    }
  }
}
```

未写 `quietHours` 时继承 `agentd.proactive.quietHours`。显式写 `"quietHours": []` 表示本通道没有安静时段；写 `"quietHours": ["22:30-08:30"]` 表示覆盖继承值。

只有系统通道明确 `unavailable` 或 `denied` 时，才允许向配置中的后备渠道降级。`gateway-dm-self` 还需要原网关中已配对、明确指定的本人私聊；不猜联系人、不向群广播。默认只启用系统通知。

## 常见结果

| 收据或原因 | 含义与处理 |
| --- | --- |
| `submitted` | 调用被系统接收；检查系统通知中心，不能当作已读回执 |
| `denied` | 系统明确拒绝；在系统通知设置里调整，不反复重试 |
| `UNKNOWN` | 调用结果无法核实；避免自动重发造成重复提醒 |
| `NO_NOTIFICATION_SESSION` | Linux 没有桌面会话；SSH/纯终端不会伪造通知成功 |
| `NOTIFICATION_PROGRAM_MISSING` | 缺少通知程序；Linux 可安装发行版的 libnotify 工具包 |
| `TASK_DONE_DAILY_CAP` | 当天任务通知预算用完；不会占用主动提醒的预算 |
| `TASK_DONE_QUIET` | 已保留安静时段候选，不代表已经发送 |

Debian/Ubuntu 的工具包通常名为 `libnotify-bin`。Koder 不替你运行安装、不使用 root 通知、不绕过桌面会话或操作系统拒权。Windows 使用原生 PowerShell/WinRT Toast；WSL 中运行的 Linux 构建仍使用 Linux 适配器。

具体测试命令、平台状态与剩余手测见 [任务通知验收](TASK-NOTIFICATIONS-ACCEPTANCE.md)。常驻与主动提醒说明见 [ALWAYS-ON](ALWAYS-ON.zh.md)。
