# Koder CLI 0.6.1

本版将 0.5.21 之后的改进合入同一套 Windows、macOS、Linux 运行包。安装包与自动更新统一使用 [CLI 官网](https://kodermodule.com/cli-download.html)。保留原有配置、会话、权限、学习开关和第三方许可，不重复安装一套 Skills。

## 本版变化

1. **长任务接续**：保存目标、验收标准和计划；明确范围后继续未完成步骤，压缩后可以按需读取原会话历史。取消、费用预算及结果未核实保护继续有效。
2. **命令等待调整**：新审批默认等待 30,000 秒，可在 Setup 修改。模型给出的短时间提示不能静默压低该值；旧审批保留原值。长期运行的网站服务走受管预览。
3. **界面与任务模板组装**：用户可要求 Agent 调整 Koder 的主题、强调色、边框、密度、Todo 和状态栏，并提出、预览、应用或回退任务模板。该接口不能改写内核、权限或预算。
4. **网站交付**：加强需求与结构方案、设计工具分阶段发现、源码检查和实际文件验证；纯文档收尾不再误要求修改业务代码。结构图不能代替网站和可用预览。
5. **工具可靠性**：校验参数，保留具体错误与已完成文件结果，区分执行失败和副作用尚未核实，不自动重放未知操作。
6. **邮箱恢复**：收取已完成时，退出连接超时不再丢弃已获得结果；积压提醒可继续处理。认证、发件配置与后台监控分别诊断。
7. **设备、音频和安全**：授权范围内发现 USB/串口与驱动状态；提供原生 WAV 测量、可选 EARSHOT 连接和限定范围安全审查。发现设备不等于自动获得控制权限，也不静默安装驱动。
8. **官方更新入口**：新安装和更新走 CLI 官网；GitHub 保留至 0.5.21 的旧版本仅用于兼容，不能用旧清单判定最新版。

## 升级后怎么用

先执行 `koder --version`，应显示 `koder 0.6.1`；再执行 `koder` 进入聊天。`koder setup` 配置功能；`koder interface status` 查看界面组装，`koder context status` 查看上下文，`koder mail doctor --json` 检查邮箱。常驻服务仍可选，升级不需要删除用户数据目录。

## 实际验证与保留限制

随发行提供的 `ACCEPTANCE-RESULTS.json` 对应确切安装包。打包前界面/设计集成回归为 181 项通过；真实 MiniMax-M3 已完成界面设置应用；独立 Chromium 对生成的三页网站完成桌面与手机视口共 17 项检查。

该网站的模型自动收尾仍未通过：模型把 HTTP 请求次数与测试用例数量进行比较，自检闸门正确拦截。失败记录保留。本轮不是 MiniMax-M3.1-Flash 十题或 SELECTED-50 成绩，原质量目标尚未达到，不宣称“所有问题已修完”或网站自动达到完美设计。

Windows 实机、Ubuntu 原生 GUI、专用 163 邮箱真实收发/提醒、系统通知可见性仍由 beta 分别验收；macOS 锁屏功能仍为未签名候选。EARSHOT 模型运行及所有型号外设未获得全面实机验证。源码检查、通知提交、预览 HTTP 成功均不等于视觉、通知可见或公网部署验收。

遇到失败，在聊天输入 `/error copy`，或在终端运行 `koder logs report --json`，附版本与复现步骤；不要发送密码、授权码、API Key。默认本地遥测可在 Setup 关闭，本版没有新增云端日志上传。
