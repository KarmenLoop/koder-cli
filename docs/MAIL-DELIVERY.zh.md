# 绑定邮箱、新邮件发送与后台提醒

适用：0.4.4（发布版本）。本页描述已实现的行为，不代表 Windows 实机或真实 163 账号验收通过。

## 先绑定，再发送

在当前 Koder 对话输入 `/setup`，选择“邮箱与收信提醒 → 绑定邮箱”。163 预设使用 IMAP `imap.163.com:993` 和 SMTP `smtp.163.com:465`，均为 TLS。需在网易邮箱设置中开启 IMAP/SMTP，使用客户端授权码，不是网页登录密码。不要把授权码发给 Agent 或贴到命令里。可参考[网易帮助中心](https://help.mail.163.com/)和[华为客户端的 163 授权码说明](https://consumer.huawei.com/cn/support/content/zh-cn15872099/)。

绑定过程分别验证收信与 SMTP；选择“仅收信”的账号不能发送。发送新邮件无需另连 Apps/MCP，也不需要电脑浏览器授权。直接说：

> 用我绑定的邮箱，给 name@example.com 发一封邮件，主题“时间确认”，正文“我们明天下午三点见。”

Agent 应调用内置 `mail_send`。已有邮件的回复仍调用 `mail_reply`。不应反复查 Skill、Apps/MCP，更不应通过 shell 再启动一个 Koder 发送。

也可以在当前对话输入 `/mail send`，逐项填写；或在系统终端运行：

```text
koder mail send --to "name@example.com" --subject "时间确认" --text "我们明天下午三点见。"
```

本机显示最终发件人、收件人、主题和正文后，输入 `send` 确认；空回车取消。`--yes`、全面开放执行权限都不替代此确认。交互式 run/ask 也可显示邮箱确认；无交互进程不会自动批准。发送新邮件不要求授权模型读取收件箱。

只有 SMTP 返回接受结果才报告已提交。它不证明邮件已进入对方收件箱；垃圾邮件过滤、退信和远端投递仍需检查。相同收件人、主题及正文在当前绑定记录中已有成功收据时返回已有收据，不重复发送；结果未知时必须先核对，不改正文绕过防重。

## 关闭终端后继续查收

绑定完成后，交互界面会提供后台提醒授权；可以跳过，之后再开启：

```text
/mail monitor on
/mail monitor status
/mail monitor off
```

在系统终端使用 `koder mail monitor on`。授权页说明绑定账号、用户级常驻、检查周期、安静时段和每日提醒上限；输入 `watch-mail` 后使用原来的 agentd 服务。新绑定默认包含各类邮件提醒；旧账号若原来过滤广告，会另显示提醒设置确认。电脑访问、模型读取、自动回复和其他后台任务的权限不扩大。

状态必须显示 `enabled: true`、`activated: true`、`running: true` 才是后台运行。服务注册失败不会把已经成功的邮箱绑定报成失败。关闭后台邮箱检查不会终止其他后台任务；`koder deactivate` 关闭整个常驻服务。

当前采用每 **30 秒**轮询一次；配置项 `agentd.mailPollSeconds` 允许 15–300 秒。不是 IMAP IDLE 推送，不保证收到即刻弹窗；网络故障、休眠、退出系统登录或系统禁用通知会延迟提醒。前台 `koder mail watch` 也使用 30 秒周期。

收件箱新信包括个人、企业、广告、自动通知和验证码类别。默认首次读取未读收件箱，之后按 IMAP UID 追踪新信；即使另一客户端先标记为已读，也不会仅因已读漏掉。暂不监控垃圾箱和自定义文件夹。POP3 依赖稳定 UIDL，不删除服务器邮件。

同次查收的新邮件合并提醒。提醒遵守原常驻服务的安静时段和每日上限（默认 23:00–08:00、每天 8 次，包含其他主动提醒）；可在 Setup 的常驻设置调整。达到上限或安静时段会保留待提醒记录。通知渠道明确不可用时，至少间隔 60 秒再尝试；结果未知不重复推送。后台队列最多接收 1000 条未结通知，满后保留游标，等处理后继续查收。

锁屏通知只说“收到新邮件”，不展示正文、发件人或验证码。运行 `/mail status` 查看本机分类，`/mail code <id>` 只在本机终端显式查看验证码。

## 提醒与主动问询不同

只提醒有新信，不需要把邮件交给模型。若希望 Koder 根据内容询问“怎么回复”，再分别开启：

```text
/mail model on
/mail inquire on
```

模型读取与主动问询各有确认；广告和验证码不进入问询草稿。选择回复方案后仍需确认最终邮件。后台检查不自动回复。

## 排错

- `HARNESS_JIT_STOP`：任务编排停止，不等于 163 登录失败。查看失败工具及原始工具结果。已绑定邮箱任务应走 `mail_send`，无需先申请电脑 network 权限。
- `MAIL_SMTP_NOT_CONFIGURED`：账号只有收信配置，重新绑定并选择收发。
- `AUTH_FAILED`：检查完整邮箱地址、IMAP/SMTP 开关和客户端授权码。
- `MAIL_SEND_CANCELLED`：本机没有确认发送；未提交 SMTP。
- `DELIVERY_UNCERTAIN`：存在未核实的提交；先查实际邮箱和收件方，不自动重发。
- 后台无弹窗：先看 `/mail monitor status`，再看 `koder status` 的提醒收据、安静时段及上限。系统接受通知不等于用户已看到。

验收分层：本地脚本模型和合成 TLS 服务器已测试；真实 163 账号、Windows Toast 展示、原生 Windows 授权输入和登录后自启需另验。无真实账号密钥时不声称邮件已经真实送达。
