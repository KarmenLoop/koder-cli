# 把当前要求落实为交件

本说明适用于 0.4.10 保留的当前任务交付检查；该机制在 0.4.1 发行阶段加入原 CLI 执行链。原模型、权限、记忆和工具保持。

## 编程任务

例如：`koder run "修复 add.mjs 的加法错误，并运行测试"`。交付检查会核对本轮实际文件与回执；只讲计划、拿已有项目充数、改错指定文件，都不能当成完成。只补测试的任务允许只交测试文件；确实无需修改时，要读当前源码、实际验证并说明依据。明确要求测试时，改动前的旧结果不算最终验证；另一项测试通过也不能冲掉尚未解决的失败。

检查通过只说明这些可观察条件满足，不等于所有功能和测试覆盖都正确。复杂任务仍需要审阅实际改动。

明确只修改指定 JSON 或 YAML 配置的任务，可以通过这些文件交付，不要求额外改动运行代码。无关配置文件不能替代函数或应用实现。

## 撰写任务

例如：`koder run "写项目进展邮件，保存到 update.md，包含风险表格"`。未要求文件时可以直接交正文；指定保存时须有本轮实际稿件。旧稿加一句“已保存”、仅免责声明、仅写作计划，都不能替代完整交件。明确总字数和表格要求会检查主稿，不只看最后一句回复。

原有来源、版本增量、前稿哈希和价格检查继续生效。没材料就说明缺什么，不能为了过检查编事实。文采、事实完整性和每条细微要求仍需实际审阅，程序检查不冒充写作评分。

## 自动补齐与退出状态

发现缺项后，在原任务里最多追加两次补做，继续使用当前模型和原权限，可能增加模型 token 消耗。用户拒绝、结果未知、外部或插件操作、取消及模型续答恢复，不会被交付检查自动重试。`ask` 仍是只读；plan、report、enhance 不强迫落盘实现。

仍缺交件证据时返回退出码 3，显示 `TASK_DELIVERY_INCOMPLETE`，JSON 包含 `taskDeliveryEvidence`，本地历史也保留未完成结论。它不是 API 断网提示。根据输出查看缺项、真实文件与执行回执。

文件检查有数量、深度和体积上限，跳过隐藏目录、依赖、秘密路径及符号链接。扫描不全或多人同时改同一文件时，不能据目录差异断言独占完成。独立任务建议使用独立目录。

## 验收边界

本轮本地用合成模型驱动真实 CLI 和工具，不调用收费 API，不读取用户数据。它验证执行逻辑，不证明真实模型的编程或撰写均分提升。candidate.2 的 Windows 无 Node 安装及 Server 图形记录保留；candidate.3 的原生平台和客户端图形验收另计。当前正式版本和平台限制见 [0.4.10 更新说明](RELEASE-0.4.10.zh.md)。
