## 这是一套怎样的课堂

完整中文课堂共 1800 课、120 个单元：原 180 课讲基础，1620 个专题案例练迁移。每课已有输入、任务、讲解、基准与变式参考；这一跟做版把它们进一步落实到工作目录、产物和复做记录。原课号、正文和进度继续保留。课程修订号 2026.10.26.1 独立于 CLI 0.4.16，本次不要求重装 CLI。

## 没有编程基础怎样开始

先从第1课和原基础教练走起，再按主题链接做九个案例；不要按目录数量追求一天刷完。每课先写预测，再操作，再解释差异。术语看不懂时，在自己的笔记里记录“它指哪个文件、字段或动作”，回到具体输入理解。

## 没有 Key 或付费账号能不能学

能。网页阅读、下载工作簿、合成案例推演和教材的本地 Node 示例不调用模型。可选择把辅导提示词提交到自己配置的 Koder，届时才沿现有模型、费用预算和权限执行。真实邮件、GUI、仓库发布等另有环境要求；未执行的部分保留未验，不影响完成合成练习。

## 每课交什么才算有成果

至少保留六部分：事前预测、基准操作与结果、原因、变式与差异、失败排查、产物与复做方式。分析课交有依据的判断或图表；编程课交可运行文件与检查；写作课交正文和事实表；办公课交可编辑材料。不要只交“已学习”或复制参考答案。

## 老师与开发者怎样用

先检查学员是否理解原输入，再看基准和变式是否分别成立。使用五项 0–2 分量表逐项写依据，而不是只给总分。让学员解释一个失败和一个取舍；开发者加练要求把变式变成独立断言、接口契约或数据流检查。

## 第一次完整跟做：第721课

1. **选一课，先保留空白工作簿**：网页每课点击“下载本课工作簿”。将文件放进自己的 Koder Projects/lesson-课号 目录。也可下载离线教材并完整解压；不要只拖出单个脚本，docs/courses 与 docs/tutorial-labs 需要保持相对位置。

2. **确认本地环境，不自动安装**：需要运行本地示例时先运行 node --version；教材按 Node 22.21+ 编写。没有 Node 可先做文稿、图表和推演，或依照自己的环境要求安装。课堂不会替你安装软件、修改系统权限或要求真实 Key。

3. **创建一个具体练习**：在解压后的教材根目录打开终端，运行下方 create 命令。Windows PowerShell、CMD、macOS/Linux 均可使用这些 node 命令。../my-lesson-0721 的父目录已存在即可；若该目录已存在，换一个新名字，工具不会覆盖。

4. **打开输入和工作簿**：新目录应有 input.txt、workbook.md、coaching-prompt.txt、README.md、practice.json。第721课还带 case.mjs。先打开 workbook.md 填预测，保留 input.txt 不改；变式另存副本。创建结果 executed:false 表示没有执行程序。

5. **运行一次真实基准**：进入自己的练习目录，再运行 node case.mjs。第721课基准输出应为 750；这是两行 600 与 150 的合计。另存副本，把第二项 qty 从1改2，重新运行，应为900。记录这两次实际输出，而不是把参考数直接填成实测。

6. **检查漏填，再人工核对**：回教材根目录运行 check 命令。空白工作簿返回退出码3并列出漏填栏目；六栏填写后可返回0，但 contentVerified 和 executionVerified 仍为false。读回自己的文件，与讲义基准和变式逐项对照，再自行标记实操。

7. **把作品移交给下一位**：保留原输入、自己的代码或正文、变式结果与说明。用一个新目录按 README 重做。打开课程、下载文件或通过结构检查均不会自动勾选完成，也不会上传笔记。

在教材根目录运行：

```text
node docs/tutorial-labs/academy-practice.mjs create 721 "../my-lesson-0721"
node docs/tutorial-labs/academy-practice.mjs check "../my-lesson-0721"
```

工具和文件：[本地练习工具](../tutorial-labs/academy-practice.mjs) · [第721课](index.zh.html#lesson-721)。

## 如何检查与评分

评分逐项给出依据：0 分表示缺失、与输入矛盾或无法说明；1 分表示有结果但证据或复做说明不完整；2 分表示结果、推导依据和复做记录齐全。总分10分只是学习诊断。任何伪造结果、泄露私人凭据或无授权真实发送都不能靠其他项加分抵消。

## 如何安排学习

建议按“基础课 → 同主题案例 → 单元交件”循环。一次学习可分为：先理解10分钟、跟做20分钟、改一个条件再做15分钟、解释与复盘10分钟。复杂编程或真实设备任务可以跨天，建议时长不是执行上限。基础薄弱时先完成前30课，再选择编程、写作或办公路线；不必把1800课一次性学完才做项目。

## 专题 1 · 首次任务与操作基础

产物：操作记录与小作品。

### 具体文件

- environment.md：终端、Shell、工作目录与版本
- workbook.md：一次实际操作与变式
- output/：本课产物，保留可打开的原格式

### 跟做 1 · 定位操作入口

先分清屏幕上的系统终端和 Koder 提示符。系统命令在终端运行；以 / 开头的会话命令放在 Koder 对话中。把本课出现的目录逐个写入 environment.md，并标注“当前目录”“临时练习”“正式作品”。

应能核对：能指着一条命令说明由谁解释、在哪个目录发生；不同目录不被画成同一个对象。

### 跟做 2 · 先预测再操作

将本课输入逐项编号。执行前先写一句预期，再按本课任务操作一次。需要点击或审批时，记录选项名称与选择理由；无操作环境则只完成推演栏。

应能核对：实际输出与事前预期分开，拒绝或取消也有明确结果。

### 跟做 3 · 读回产物

不要只看最后一句回复。打开实际文件，或重新读取目标状态，记录与要求对应的行、字段或画面。临时目录退出后可能被清理，需要留存时按教练提示保留。

应能核对：作品路径可找到；模型陈述与文件内容能相互核对。

### 跟做 4 · 独立再做一遍

只替换题目指定条件，保留原结果。用自己的话解释哪些步骤保持、哪些步骤改变。请同学从记录中复做，不替对方补隐含步骤。

应能核对：变式有独立结果；接手者不用猜目录或输入。

### 示范解读

例如练习输入包含 Terminal、zsh、/lab 和 /tmp/cart-7，先画四个节点，再把 /lab 标为 Shell 当前位置、/tmp/cart-7 标为教练创建的临时工程。变成 Windows Terminal 与 PowerShell 后，应修改入口和语法说明，而不是声称目录会自动迁到 C 盘。

### 常见错误

- **找不到刚才的文件**：先核对当前目录与临时目录，再看退出时是否选择保留；不要重装模型解决路径问题。

- **界面提示与作品不一致**：以读回的文件或状态为准，保留两者差异，再定位第一次偏离。

### 本专题评分表

- 能区分终端、Shell、CLI 与文件对象：0 / 1 / 2；证据：____
- 操作前有明确预期，操作后有实际读回：0 / 1 / 2；证据：____
- 取消、拒绝或临时目录清理的后果解释正确：0 / 1 / 2；证据：____
- 变式保留原条件并指出变化：0 / 1 / 2；证据：____
- 小作品可打开，记录足以供另一人复做：0 / 1 / 2；证据：____

### 开发者教学

把入口、工作目录和产物路径显式传入测试。练习取消发生在修改前与修改后两种情况；断言未批准变更未落盘、已完成产物可读回。不要用“收到成功字符串”代替文件断言。

## 专题 2 · 安装、模型与个人工作台

产物：脱敏配置地图。

### 具体文件

- environment.md：系统、版本、命令入口
- configuration.md：非秘密字段及用途
- checks.md：保存、连通、能力、权限四层检查

### 跟做 1 · 列清配置层次

把本课给定字段放入“功能、配置位置、是否已保存、凭据引用名、授权范围”五列。未知字段写未知；密钥只写变量或凭据条目名称。

应能核对：能区分配置存在、接口可达、功能可用与授权允许。

### 跟做 2 · 选择最小检查

先运行本课的只读状态命令或分析给定状态，再选择一个无外部写入的检查。不要为了证明保存成功而发送邮件或公开仓库。

应能核对：每个判断对应一个状态字段或检查输出，不用一条文本回复证明全部工具能力。

### 跟做 3 · 沿失败层排查

按入口→配置→凭据→协议→权限→操作的顺序定位第一处失败。只改变有证据指向的字段，记录变更前后值；秘密值始终省略。

应能核对：修复与具体失败关联，没有同时重置一整套设置。

### 跟做 4 · 验证恢复与撤销

在自己的练习配置中恢复原字段或关闭可选功能。检查原项目和记录仍在；没有实际执行恢复时写出待验步骤。

应能核对：知道如何回退，功能开关不被误当作删除历史。

### 示范解读

一份合格记录可以写“配置已保存；文本请求 200；工具续答未测；desktop 未授权”。四个结论各对应一层，不能把它们合并成“全部接通”。

### 常见错误

- **同名模型仍不能调用**：核对区域、套餐、协议、地址与凭据归属；型号相同不代表账号权限相同。

- **更新后还是旧版**：核对实际命令入口和版本目录，不先删除数据目录。

### 本专题评分表

- 配置地图字段完整且脱敏：0 / 1 / 2；证据：____
- 保存与可调用证据分别列出：0 / 1 / 2；证据：____
- 错误定位到具体层而非泛称断网：0 / 1 / 2；证据：____
- 变式说明配置或权限如何变化：0 / 1 / 2；证据：____
- 有保留原数据的恢复方法：0 / 1 / 2；证据：____

### 开发者教学

用注入的配置和凭据引用测试路径，不读取学员真实 Key。给保存成功但调用失败、授权撤销、旧配置缺新字段各写一个用例。配置迁移应保留旧值，能力状态不能由 UI 默认值推断。

## 专题 3 · 终端、文件与项目管理

产物：可搬迁的练习工作区。

### 具体文件

- input/：原始合成输入，只保留副本
- output/：转换结果
- README.md：相对路径、运行方式与退出码

### 跟做 1 · 建立最小目录

在自有练习目录创建 input、output、notes 三个子目录。将本课给定文本写到 input 中，先列目录并读回文件，确认没有在安装目录里编辑。

应能核对：目录层级和文件内容与题目一致，路径包含空格时仍可定位。

### 跟做 2 · 拆开命令理解

将本课命令拆为程序、参数、输入、输出、重定向五部分。遇到管道，说明每段从哪里读取、向哪里写；先检查单段再组合。

应能核对：能解释 stdout、stderr 和退出码分别代表什么。

### 跟做 3 · 运行并记录差异

只在副本执行本课任务。保存关键输出和退出码；对文件转换，逐行比较输入与输出，明确编码、换行和相对路径。

应能核对：失败不会被空输出或最后一条 echo 掩盖。

### 跟做 4 · 搬迁后复做

复制练习到新的自有目录，优先用相对路径复做。Windows 的 PowerShell/CMD 与 macOS Shell 语法分别记录，不机械复制。

应能核对：新目录仍能读到相同输入并得到相同业务结果。

### 示范解读

输入文件在 input/report.txt 时，README 应写从项目根运行的相对路径。把工程复制到“academy work copy”后再读回，才能发现原来依赖 /Users/某人/Desktop 的命令。

### 常见错误

- **命令成功但文件为空**：检查重定向目标、当前目录和上游退出码；先验证产出内容再继续下游。

- **Windows 命令照抄后报错**：确认当前 Shell；单独核查引号、变量展开与管道语法。

### 本专题评分表

- 目录和输入可重建：0 / 1 / 2；证据：____
- 命令参数与重定向解释正确：0 / 1 / 2；证据：____
- 输出、错误与退出码均有记录：0 / 1 / 2；证据：____
- 空格、编码或缺文件边界有一项检查：0 / 1 / 2；证据：____
- 换路径后不依赖作者机器的绝对位置：0 / 1 / 2；证据：____

### 开发者教学

将 cwd、环境变量与临时目录作为测试参数。先构造输入边界再断言退出码和文件内容。对本课涉及的流处理，验证 EOF、无输入和坏参数，不用无限等待掩盖阻塞。

## 专题 4 · 任务表达、上下文与执行控制

产物：可执行任务卡与变更记录。

### 具体文件

- brief.md：目标、输入、产物、成功标准
- facts.md：已知、未知、假设及来源
- changes.md：引导、排队、取消与范围变化

### 跟做 1 · 把要求落到产物

从本课输入提取对象、读者或使用者、需要完成的动作。写出最终文件或可观察状态，再列出三条可以核对的成功标准。

应能核对：“好看”“专业”被补成可检查的结构、内容或交互要求。

### 跟做 2 · 分开事实与默认值

给每条事实标来源；未知事项判断是否会改变结果。低影响默认值可明确写出，高影响的发送对象、价格或权限不能靠猜。

应能核对：任务卡能告诉执行者哪些可以先做、哪些需确认。

### 跟做 3 · 安排依赖与补充

将目标拆成有输入和产物的小步骤。按本课情境记录补充是在当前任务引导、下一任务排队还是取消后改做；已完成操作不自动重放。

应能核对：补充要求能落到具体步骤，前后任务身份不混淆。

### 跟做 4 · 用结果倒查任务卡

完成本课操作后，逐条用产物对照成功标准。变式只改指定条件，并指出原任务哪些要求仍然有效。

应能核对：不会只因回复流畅就给完成；失败或缺条件有清楚的下一步。

### 示范解读

“做报名页”可以落为：本地 HTML、访客能填写姓名和邮箱、空值显示错误、演示不发送数据。日期未提供时写待确认，不编造活动时间，也不把静态页称为已接收报名。

### 常见错误

- **补充后原目标丢了**：把仍有效的目标写回任务卡，指出本次只替换哪一项要求。

- **不断问问题却不落盘**：先完成不依赖答案的资料整理与最小稿，再定位真正阻塞的决定。

### 本专题评分表

- 任务结果可观察：0 / 1 / 2；证据：____
- 事实与假设有明确区别：0 / 1 / 2；证据：____
- 步骤有输入输出和必要依赖：0 / 1 / 2；证据：____
- 引导、排队或取消语义对应情境：0 / 1 / 2；证据：____
- 结果能逐条追溯到任务要求：0 / 1 / 2；证据：____

### 开发者教学

为任务状态迁移写事件序列：根消息、steer、工具结果、取消、终态。检查引导不冒充新授权，排队文字不进入审批答案。模型与执行器职责分开，使用原预算和取消链。

## 专题 5 · 编程、调试与性能

产物：代码、检查与解释。

### 具体文件

- case.mjs：仅在本课有程序时提供的基准
- solution.mjs 或本课指定源文件：你的改动
- checks.md：预期、实际输出、边界及复杂度

### 跟做 1 · 逐项追踪输入

先列输入类型、单位、所有权和空值含义。按本课操作手算一遍或画数据流，再运行给定程序；保留原程序，修改放在副本。

应能核对：在看程序输出前已有独立预期，金额的分与元不混用。

### 跟做 2 · 定位最小改动

根据第一次不一致定位函数或分支。修复先写失败用例；重构固定行为；优化固定正确结果并记录数据规模。

应能核对：改动目标明确，不以全仓格式化或新增无关依赖代替修复。

### 跟做 3 · 逐步实现并核对

只改与题目有关的逻辑。运行原检查，再加入本课指定变式；保留标准输出、退出码及修改文件。无需真实服务时保持本地运行。

应能核对：新旧实现可在相同输入下比较，失败不被吞掉。

### 跟做 4 · 解释代价和边界

写出为什么成立，并至少指出一个不适用条件。性能题说明时间与额外空间；异步题说明顺序、失败和清理；重构题说明保留的行为。

应能核对：解释具体到数据、操作或状态，不能只有“更高效”。

### 示范解读

两行商品为 200 分×3 和 150 分×1，总额应先分别算出 600、150，再合为 750。把第二行数量改为 2 后应为 900；测试既要断言 900，也要确认原数组未被计算函数修改。

### 常见错误

- **只对给定样本正确**：改变数量、空输入或顺序，先写预期再运行，排除写死结果。

- **优化更快却结果变了**：先恢复同语义比较；正确性相等后才讨论耗时。

### 本专题评分表

- 输入输出契约明确：0 / 1 / 2；证据：____
- 有独立预期和有效检查：0 / 1 / 2；证据：____
- 改动范围与问题一致：0 / 1 / 2；证据：____

## 专题 6 · 网站、设计与前端交付

- index.html 或本课指定前端文件：页面

先创建一个可打开的页面或线框图。把标题、说明、输入、错误与结果状态放到明确位置，再实现本课要求的局部变化。

应能核对：主动作能被看见；空态、失败或未知状态有位置。

### 跟做 3 · 按真实路径跟做

从首次打开开始，用鼠标和键盘各走一遍。表单题输入空值、错误值和合成正确值；布局题缩窄窗口、放大文字。

应能核对：保留用户输入，焦点可见，结果文案与实际状态一致。

### 跟做 4 · 交付可复看的证据

### 示范解读

- **提交失败后表单被清空**：检查状态转换，把失败提示与输入值分离保存。

## 专题 7 · 后端、数据与接口

产物：业务契约、数据样本与边界检查。

### 具体文件

- contract.md：输入、身份、返回值与失败
- data.json 或 schema.sql：本课数据结构
- checks.md：合法、非法、越权或重复请求

### 跟做 1 · 写出数据与调用者

从题目列实体、字段、约束和调用身份。区分公开数据与用户私有数据；先用合成样本推演，再选择本课要求的内存、数据库或 HTTP 层。

应能核对：每次读写都能说明对象属于谁，以及由谁允许。

### 跟做 2 · 固定一次操作的契约

列前置状态、请求、成功返回、失败返回和持久化位置。对于缓存、事务或幂等，写出键包含的维度和有效期。

应能核对：同一 URL 不被默认当成同一用户数据；重复写不靠缓存冒充幂等。

### 跟做 3 · 跑正例再跑拒绝例

实现或分析本课操作，检查本人合法请求，再构造他人、坏输入、重复请求中的适用项。记录状态和数据是否变化。

应能核对：拒绝不仅有错误消息，还应没有越权写入或泄露。

### 跟做 4 · 验证变式与恢复

改变题目指定条件后重做。对未知写入先查询结果；对迁移说明前后结构及恢复约束。当前仅为内存例子时如实标注。

应能核对：能区分逻辑通过、HTTP 可用、持久化有效和生产可用。

### 示范解读

若缓存只以 /todos 为键，A 的列表可能被 B 命中。私有数据的键应至少表达调用身份和筛选维度，并保持返回时授权。若变式改为公开活动列表，必须先证明结果确实与用户身份无关，才能讨论共享。

### 常见错误

- **缓存命中却拿到别人的列表**：检查键是否包含身份、权限版本和筛选条件，并在返回前保留授权检查。

- **超时后重复创建了两条**：先查询原请求是否生效；幂等记录绑定调用者、操作和内容，不盲目重发。

### 本专题评分表

- 数据归属与约束清楚：0 / 1 / 2；证据：____
- 输入输出及失败语义一致：0 / 1 / 2；证据：____
- 合法请求和拒绝路径均检查：0 / 1 / 2；证据：____
- 变式覆盖身份、键或事务的关键维度：0 / 1 / 2；证据：____

### 开发者教学

设计失败用例检查外部数据未改变；事务测试覆盖中间失败和回滚。幂等冲突返回明确错误，缓存命中不能跳过对象授权。内存域、HTTP、数据库各自独立验收。

## 专题 8 · 测试、CI与验收工程

产物：能发现错误的验收包。

### 具体文件

- plan.md：被测对象、风险与层级
- tests/ 或 checks.md：检查入口
- evidence/：失败、修复和复测记录

### 跟做 1 · 从风险写预期

先列本课要防止的错误，再写应通过和应失败各一个输入。预期由业务规则推导，不能复制待测函数输出当答案。

应能核对：每条检查都有失败含义，空结果不会自动算通过。

### 跟做 2 · 证明检查能失败

在自有副本中故意破坏一处相关输入或实现，运行同一检查，保存失败输出后恢复。不要删断言来让基线变绿。

应能核对：能看到对应断言失败或非零退出，证明入口确实被调用。

### 跟做 3 · 固定条件再复测

保留版本、命令、cwd、数据和退出码。不同平台或账号层独立记录；复测仍使用原断言与合理时限。

应能核对：通过结果对应当前文件；历史失败也保留。

### 跟做 4 · 做接手者复现

复制验收包到新目录，只按 README 操作，补全隐含前提。变式后说明哪些检查失效、哪些需要新增。

应能核对：另一人能从说明找到输入、命令、预期和实际结果。

### 示范解读

一个解析审查结果的命令收到不可解析文本时，即使模型请求成功，也应产生明确非零退出及错误码。先测“有效空问题列表”，再测“并非 JSON”，才能避免把两者都当作无问题。

### 常见错误

- **CI 显示绿但没有测试**：核查发现的测试数、执行入口和退出码；空仓或解析失败不能默认为成功。

- **多跑几次总能过**：保留全部结果，固定变量验证假设；不能只留下最后一次绿。

### 本专题评分表

- 检查与实际风险对应：0 / 1 / 2；证据：____
- 有可观察的失败基线：0 / 1 / 2；证据：____
- 断言独立且退出码正确：0 / 1 / 2；证据：____
- 平台、账号和模拟层分清：0 / 1 / 2；证据：____
- 换目录可复做并保留原失败：0 / 1 / 2；证据：____

### 开发者教学

测试桩只替换外部边界，核心行为必须真的调用。增加坏参数、取消、UNKNOWN 和路径漂移用例。不要把模拟 Windows 平台值当成 PowerShell 或 GUI 真机结果。

## 专题 9 · 研究、事实与专业写作

用一句话写读者读完后应做什么，再安排论点、证据、限制和行动。介绍、更新邮件、对比与压缩稿使用不同结构。

应能核对：改稿前后事实集合可对照，解释内容取舍而不只说“润色”。

素材只说明产品支持导出，未提供 preview.22 变更清单时，可以写“以下是产品现有能力，未作为本版新增介绍”。压缩这封邮件时仍须保留这层限定，不能改成“本次新推出导出”。

- **没有 changelog 却要写更新邮件**：明确没有找到版本增量来源，改写为既有能力说明或征集反馈；不要虚构新增。

## 专题 12 · GitHub、发布与毕业交付

- **上传成功但官网仍是旧版**：读取公网清单与实际文件哈希，检查缓存和部署指向，不能只看本地目录。

- **毕业答辩只展示完成数**：用一个新输入现场重做，解释文件如何变化以及尚未验收的边界。
