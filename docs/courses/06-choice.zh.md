# 06. 做选择：Koder 也会问你

建议 25 分钟

**目标**：用可评价的选项推进任务，并能区分草稿选择、操作确认和真正交付。

**准备**：准备一份简短网站需求：受众、目标、内容、风格和限制。不提供密码或真实客户名单。

## 手把手操作

1. 输入：“做课程报名页，先给3个版式的可浏览草稿；暂不发布。受众是零基础学员，主动作是报名。”

   **应看到**：三案在信息层级或布局上有实质区别，不只是换颜色。

2. 查看每案的适用人群、优缺点和文件路径；需要时按第30课开启本地预览。

   **应看到**：能打开实际产物；一张概念图不能当可运行网页。

3. 选择一案并给具体反馈：“保留B的导航，报名区改为A，去掉自动播放。”

   **应看到**：反馈明确可执行；选择方案不表示同意部署、付款或发送。

4. 最后核查手机宽度、链接与表单行为，要求标出尚未接后端的按钮。

   **应看到**：演示与真实服务分开；没有后端不能写“报名成功已入库”。

## 常见问题与恢复

- **反复问同一问题**：补上目标与限制，要求沿已选方案继续；重要写操作仍要最终确认。
- **无头脚本一直等选择**：在任务中写明低风险默认取舍；必要授权缺失应退出或等待，不能伪造用户同意。

## 作业与自查

写一条少于150字的三案需求；给一案3条具体修改意见与2项验收标准。

**自查标准**：意见能直接对应页面区域；验收可观察，例如手机端无横向溢出、按钮打开指定表单。

## 开发者教学

1. 把选择题结果作为任务输入，不当作操作授权。

2. 给无头任务设置可接受默认值，并独立测试审批缺失分支。

3. 预览交件记录URL、文件、启动/停止方式和未连接服务；评价图示不能替代可运行文件。

交件要求：按本课步骤选择自有测试目标，保存前置、实际命令/退出码、产物、正反例、未验和恢复方式。使用 [验收模板](../tutorial-labs/acceptance-template.md)。
