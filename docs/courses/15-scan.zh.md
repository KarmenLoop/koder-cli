# 15. 扫描本机工程，决定下一步

建议 25 分钟

**目标**：找到正确工程再继续，控制跨工具任务资料进入模型的范围。

**准备**：准备两个测试工程，分别放不同README。扫描可能显示本机项目标题与路径，分享屏幕前先确认。

## 手把手操作

1. 运行 koder scan --limit 6，只看列表，不选择执行。

   **应看到**：能看到来源与路径；列举不请求模型，选择后续任务可能发送相关资料。

2. 选测试工程A，核对实际路径后再请求总结README。

   **应看到**：摘要只涉及A，不自动带上B的任务事实。

3. 需要多个任务时分别打开独立目录/会话；用 koder project list --json 核查。

   **应看到**：每项任务有明确归属，不能在安装目录直接散写项目。

4. 继续旧任务时说清项目、已完成部分和下一目标。

   **应看到**：先读已有产物再工作，不把聊天标题当完整项目状态。

## 常见问题与恢复

- **扫描到很多旧项目**：缩小数量或直接用-w指定路径；别批量删除历史来整理。
- **项目路径已移动**：用新路径明确打开并核查文件；不要假设旧路径映射还有效。

## 作业与自查

在A、B中写不同的测试标记，分别提问；结果不能串用另一工程标记。

**自查标准**：保留两个工作目录和结果；共享笔记是显式范围，和任务历史分开说明。

## 开发者教学

1. 规范工作路径是隔离键的一部分；路径别名、符号链接和并发会话需要一致处理。

2. 测试两工程、同工程不同命名会话、旧会话恢复；不删除旧记录以掩盖串话。

3. 交付前生成项目文件索引和运行入口，供下次恢复读回。

交件要求：按本课步骤选择自有测试目标，保存前置、实际命令/退出码、产物、正反例、未验和恢复方式。使用 [验收模板](../tutorial-labs/acceptance-template.md)。
