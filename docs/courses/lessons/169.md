# 169 · 上传文件：只提交明确选中的内容

单元 12 · 建议 30 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-169) · [总纲](../README.zh.md)

## 学习目标

完成「上传文件：只提交明确选中的内容」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

上传项目应先列出要提交的文件，检查秘密、大小和目标分支，再确认。Koder内置提交接口处理显式路径，不应把整个用户目录递归上传。远程分支在确认期间变化时，应读取新状态并重新审查，不能强推覆盖他人。

专题补充
远程提交是明确文件集合的写入，不是把当前目录全量同步。路径名、内容快照和目标分支都属于待审对象；预览后任何一项变化都可能让旧确认失效。并发检查保护别人新提交，读回验证保护本次写入是否落到预期位置。

先列本次允许提交的相对路径，读取内容并检查秘密、生成物与文件归属。固定本地候选内容和远程分支头，再审查差异；提交后核远程文件及提交身份。课堂只准备合成计划，不执行真实上传。

## 准备

先完成第168课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。账号、图形操作和外部写入须另有可用环境与授权；没有条件就记录NOT_RUN。

## 示例与解读

```text
koder github commit OWNER/demo README.md src/main.js --message "Add project files"

补充案例：文件清单：项目上传不是全目录
合成目录含README.md、src/main.js、.env、notes/private.txt与link.txt符号链接。任务只上传README，内容“青禾索引：本地标题检索”。远程main头a1，预览后同事推到b1。文档示例koder github commit OWNER/demo README.md --message "Clarify project setup"；真实确认语义以当前帮助为准。
本课条件：给定五个路径，授权只README
```

只包含列出的文件；真实运行前核对目标与本次确认词。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「上传文件：只提交明确选中的内容」，可与本课示例对照；无无关真实资料。

2. 检查本地文件

   应看到：没有.env或私人资料。

3. 确认远程分支

   应看到：记录当前状态。

4. 预览待提交内容

   应看到：用户能审查。

5. 提交后读回

   应看到：文件与SHA对应。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「只包含列出的文件；真实运行前核对目标与本次确认词。」逐项对照，不把未执行项填成通过。

7. 做纳入与排除表并写每项理由

   应看到：仅README纳入，其他文件保持本地

   为什么：任务授权按对象定义，工作目录包含不代表获准上传

8. 改变条件：用户追加src/main.js

   应看到：先读取审查该文件再扩大清单，不能顺便加整个src目录

   为什么：仅README进入候选，.env与private不上传。a1变b1后需读取新状态再决定；不能把原预览当仍覆盖当前远程。上传成功后还需核远程README内容。

## 故障恢复

- **结果与示例不一致**：文件名相同不代表内容相同；上传前快照与实际发送应一致。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

准备一个仅含README的私有测试提交计划，真实写入需获准。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不应，只提交明确选定并检查过的文件。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

路径越界、符号链接和秘密检测沿现有门；检测不能替代人工核对。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
记录selectedPaths、contentHashes、baseCommit与operationId。路径穿越、符号链接、大小和秘密检测在发送边界再核；自动检测不能代替内容审查。远程头变化需要重新对账与审查，不用强推覆盖。
