# 120 · 单元项目：制作一套可交给别人的验收包

## 学习目标

完成「单元项目：制作一套可交给别人的验收包」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

验收包包含检查脚本、合成数据、运行说明和结果模板。别人拿到后应知道前置条件、会产生什么副作用、怎样停止以及怎样收集证据。包本身也需要验证：解压、入口可读、路径可移植、失败能正确退出。

专题补充
验收包是一份别人拿到后能够理解并重做的最小工程。它包含检查入口、合成输入、独立预期、运行说明和结果模板。包的结构、可搬迁性与失败传播也需要验证，不能只把当前工作目录压缩后叫交付。

先从必要检查倒推文件清单，剔除缓存和个人资料，再在新的自有位置按README操作。保持测试与结果分离，实际执行后填结果，模板不能预填PASS。

## 准备

先完成第119课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「单元项目：制作一套可交给别人的验收包」，可与本课示例对照；无无关真实资料。

2. 选择3个关键契约

   应看到：成功、失败和恢复。

3. 准备合成夹具

   应看到：没有私人资料。

4. 在新目录运行

   应看到：验证可搬迁。

5. 整理结果与边界

   应看到：不把未验自动勾选。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「默认只运行无密钥本地检查；真实账号项明确单列。」逐项对照，不把未执行项填成通过。

7. 仅收源码、测试、合成夹具与运行说明 将上述完整程序保存为自有目录的 case.mjs，运行 node case.mjs；先独立预测输出，再与固定输出对照。

   应看到：每个文件对应必要检查
   Node 固定输出：{"missing":&#91;"test/cart.test.mjs"&#93;,"unneeded":&#91;"cache.tmp"&#93;}

   为什么：交付体积不代表质量

8. 改变条件：测试读取模板文件

   应看到：把模板纳入清单，不能误删运行资产

   为什么：检查入口存在、引用完整、路径可移植、失败非零以及清理范围。通过包内检查只能证明其覆盖的对象，真实设备、服务与生产结果单列。

## 故障恢复

- **结果与示例不一致**：测试包不是正式安装包，不应自动注册系统服务或改变用户权限。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

交验收ZIP及哈希，附真实执行命令与未验列表。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不应该，真实账号操作必须有明确范围与授权。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

验收脚本退出码可机器读取，清理范围限定为自有临时目录。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
清单与哈希识别交付内容，说明源码和产物对应关系。脚本应有可诊断退出状态与有界运行，依赖版本可追踪；自检与独立复验分别记录。
