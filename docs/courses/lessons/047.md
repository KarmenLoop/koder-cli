# 047 · 服务商、区域与套餐：选择正确入口

单元 4 · 建议 30 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-47) · [总纲](../README.zh.md)

## 学习目标

完成「服务商、区域与套餐：选择正确入口」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

同一厂商可能提供国内、国际、按量和订阅套餐入口，它们的模型ID、鉴权和配额可能不同。网页能登录并不能证明某条API可用。配置的最小单位是服务产品、区域、Base URL、协议和模型ID的组合，而不是只填一个品牌名。

专题补充
服务入口不是随意拼接的URL。官方产品资料、账号控制台和当前客户端支持共同决定可用组合。资料具有日期和适用范围，历史示例可能仍保留但不再可启用。明确自定义代理也要按其实际契约核对，不能悄悄把凭据转移到另一主机。

为每个字段记录来源与核对日期，先检查当前可用状态，再比较产品、地区与协议。用虚构主机做URL组成练习；真实账号请求由学员另行授权，课程不替用户选择付费路线。

## 准备

先完成第46课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 示例与解读

```text
配置核对表：服务产品 / 区域 / Base URL / 协议 / 模型ID / 凭据来源

补充案例：为配置字段标来源
model来自公共目录；region来自账号控制台；protocol来自客户端支持表
```

只记录变量名或已脱敏信息，不记录Key。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「服务商、区域与套餐：选择正确入口」，可与本课示例对照；无无关真实资料。

2. 从账号控制台确认购买的产品

   应看到：不是凭模型昵称猜套餐。

3. 对照Koder模型预设说明

   应看到：灰色或受限项按当前提示处理。

4. 核对协议与路径

   应看到：避免重复添加/v1。

5. 保存脱敏配置摘要

   应看到：能让别人定位产品边界。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「只记录变量名或已脱敏信息，不记录Key。」逐项对照，不把未执行项填成通过。

7. 建字段、值、来源、日期四列表

   应看到：每个决定都有可核查来源

   为什么：不同字段权威可能不同

8. 改变条件：公共目录无该账号私有模型

   应看到：允许按账号证据核手动型号，不假定不存在

   为什么：验收要求配置决定可追溯，未知字段不猜，灰色入口不绕过。主机相同不能证明路径正确，接口可见也不证明该账户能调用目标模型。

## 故障恢复

- **结果与示例不一致**：不要把另一地区Key反复试遍所有地址；服务商限制应以当前账号文档为准。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不一定，必须确认该产品的接口和授权范围。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

路由必须按产品显式选取；错误恢复不能静默切换区域并向新主机发送凭据。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
URL规范化与凭据目标绑定应一起考虑；公共目录更新不自动改变账号路线。错误或重定向不能无条件携带Authorization到新来源。
