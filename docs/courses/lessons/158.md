# 158 · 浏览器自动化：观察、定位、动作、再观察

## 学习目标

完成「浏览器自动化：观察、定位、动作、再观察」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

网页操作应以当前页面状态为依据。先看可见元素和目标，再定位、执行、核对结果；页面变化后旧定位可能失效。结构化API可用时优先，浏览器适合没有专用连接的网页流程。成功标准要是页面或业务状态，不是“点击调用返回了”。

专题补充
浏览器自动化是观察、定位、动作、再观察的循环。调用成功只说明请求被工具接受或执行，业务是否完成取决于页面或服务回执。语义定位通常比固定坐标更能表达意图，但重名、隐藏元素和页面变化仍需确认。恢复应针对当前状态，不盲目重复之前的点击。

先明确页面任务结果，读取当前可见状态，再使用实际可见名称或语义定位。每个会改变状态的动作后重新观察并核对业务结果；页面更新后放弃旧定位。课堂在自编页面与快照上演练，不操作真实账号。

```text
补充案例：成功定义：打开页面之后做什么
合成页面快照P1：标题青禾报名；活动选择绘画；人数输入1；按钮预览报名。P2点击后摘要显示绘画1人，按钮确认报名。P3服务返回演练编号demo-17。另有同名按钮出现在隐藏模板中，页面异步刷新会重建表单。课堂只用预览与本地模拟结果。
本课条件：请求为帮我检查报名表
```

每次关键动作后确认新状态，不凭预想继续点。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「浏览器自动化：观察、定位、动作、再观察」，可与本课示例对照；无无关真实资料。

2. 明确网页任务结果

   应看到：例如读标题而非只打开URL。

3. 检查授权与登录态

   应看到：缺失时提示现有入口。

4. 使用可见语义定位

   应看到：避免猜坐标。

5. 核对结果与来源

   应看到：保留页面证据。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「每次关键动作后确认新状态，不凭预想继续点。」逐项对照，不把未执行项填成通过。

7. 把任务限定为读取字段与预览摘要

   应看到：成功是字段和预览内容可核对，不包括真实提交

   为什么：URL打开只是前置，目标结果需具体

8. 改变条件：用户改为完成报名

   应看到：新增真实提交范围与确认要求，原只读检查不自动授权外部报名

   为什么：预览按钮只到P2，不等于报名完成；P3演练编号仍不是真实服务报名。隐藏同名元素不能当可见目标，刷新后需重新取得定位。

## 故障恢复

- **结果与示例不一致**：不要绕验证码或网站风控；需要用户登录时按原流程停在明确位置。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

定位器随页面重新获取；取消后不继续点击排队动作。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
记录pageIdentity、snapshotVersion、locatorIntent、action与observedState。避免缓存过期元素；对提交类动作明确幂等与未知处理。真实工具API以当前可用文档为准，本课的P1至P3是合成状态而非产品调用代码。
