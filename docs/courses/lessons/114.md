## 学习目标

完成「CI工作流：先让本地命令可重复」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

CI把已有检查自动执行，并不会自动修复不稳定的测试。先确认本地命令在干净目录可运行，再配置依赖、缓存和产物。失败日志要可下载，秘密只由CI秘密存储注入。没有真实运行的配置文件应标为准备完成，而非CI通过。

专题补充
CI自动执行已有检查，不会自动把不稳定测试变可靠。工作流需要清楚的入口、依赖、缓存、退出状态和产物；本地命令能在干净副本执行之后，才有可解释的远端结果。教学配置不触发真实仓库写入。

先写本地单一检查入口，再设计检出、依赖准备、检查、日志保存的顺序。确定失败如何传播以及哪些信息可公开；外部动作和秘密使用按实际仓库权限处理。

## 准备

先完成第113课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 示例与解读

```text
步骤：检出→安装锁定依赖→运行检查→保存报告
失败仍保存日志，不发布产物为正式版

补充案例：确定唯一检查入口
本地有node --test test/cart.test.mjs，CI写成npm run check但无该脚本
```

发布与测试是不同权限和触发条件。

### 跟做 1：从风险写预期

先列本课要防止的错误，再写应通过和应失败各一个输入。预期由业务规则推导，不能复制待测函数输出当答案。

检查点：每条检查都有失败含义，空结果不会自动算通过。

### 跟做 2：证明检查能失败

在自有副本中故意破坏一处相关输入或实现，运行同一检查，保存失败输出后恢复。不要删断言来让基线变绿。

检查点：能看到对应断言失败或非零退出，证明入口确实被调用。

### 跟做 3：固定条件再复测

保留版本、命令、cwd、数据和退出码。不同平台或账号层独立记录；复测仍使用原断言与合理时限。

检查点：通过结果对应当前文件；历史失败也保留。

### 跟做 4：做接手者复现

复制验收包到新目录，只按 README 操作，补全隐含前提。变式后说明哪些检查失效、哪些需要新增。

检查点：另一人能从说明找到输入、命令、预期和实际结果。

2. 列出本地检查命令

   应看到：每条退出码清楚。

3. 定义CI环境

   应看到：平台和运行时版本固定。

4. 保存报告与日志

   应看到：失败也能追查。

5. 检查触发范围

   应看到：不会每次文案修改都发布。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「发布与测试是不同权限和触发条件。」逐项对照，不把未执行项填成通过。

7. 核package清单并统一真实入口

   应看到：CI命令必须实际存在

   为什么：自动化不会补造缺失脚本

8. 改变条件：新增check脚本转发原命令

   应看到：测试该转发的退出码与工作目录

   为什么：检查失败时仍能取得日志、缓存键覆盖环境、矩阵每个平台独立报告。配置文件存在只是准备，只有真实运行回执才能证明CI执行。

## 故障恢复

- **结果与示例不一致**：缓存命中不应跳过必要验证；不要把Key写进YAML。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

并发任务避免共享临时路径；测试与发布凭据最小化分离。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
最小化工作流权限与秘密暴露范围。缓存是加速材料，不能取代锁定依赖和验证；产物发布与测试流程分开，检查通过不是发布授权。
