## 学习目标

完成「配置与秘密：让同一程序适应不同环境」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

开发、测试和生产可以共享代码，但配置不同。端口、数据库路径和公开地址属于配置，密码与令牌属于秘密。默认值应安全且可诊断，缺少必要秘密时应明确失败。把所有环境混在一个文件会增加误连生产的风险。

专题补充
同一程序在开发、测试和生产使用不同配置，但必须能解释每个值从哪里来。端口、路径和公开地址是配置；令牌与密码是秘密。配置缺失应在明确边界失败，不能猜一个可能连向真实服务的默认值。

列字段类型、默认值、来源优先级与是否可公开。先解析再验证，得到不可变配置对象后传给业务；测试用合成环境对象，不读真实秘密。

### 跟做 1：写出数据与调用者

从题目列实体、字段、约束和调用身份。区分公开数据与用户私有数据；先用合成样本推演，再选择本课要求的内存、数据库或 HTTP 层。

检查点：每次读写都能说明对象属于谁，以及由谁允许。

### 跟做 2：固定一次操作的契约

列前置状态、请求、成功返回、失败返回和持久化位置。对于缓存、事务或幂等，写出键包含的维度和有效期。

检查点：同一 URL 不被默认当成同一用户数据；重复写不靠缓存冒充幂等。

### 跟做 3：跑正例再跑拒绝例

检查点：拒绝不仅有错误消息，还应没有越权写入或泄露。

### 跟做 4：验证变式与恢复

改变题目指定条件后重做。对未知写入先查询结果；对迁移说明前后结构及恢复约束。当前仅为内存例子时如实标注。

检查点：能区分逻辑通过、HTTP 可用、持久化有效和生产可用。
