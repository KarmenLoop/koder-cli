# 099 · 配置与秘密：让同一程序适应不同环境

## 学习目标

完成「配置与秘密：让同一程序适应不同环境」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

开发、测试和生产可以共享代码，但配置不同。端口、数据库路径和公开地址属于配置，密码与令牌属于秘密。默认值应安全且可诊断，缺少必要秘密时应明确失败。把所有环境混在一个文件会增加误连生产的风险。

专题补充
同一程序在开发、测试和生产使用不同配置，但必须能解释每个值从哪里来。端口、路径和公开地址是配置；令牌与密码是秘密。配置缺失应在明确边界失败，不能猜一个可能连向真实服务的默认值。

列字段类型、默认值、来源优先级与是否可公开。先解析再验证，得到不可变配置对象后传给业务；测试用合成环境对象，不读真实秘密。

## 故障恢复

- **结果与示例不一致**：不要把.env.example复制后忘记替换生产地址；测试必须拒绝真实目标。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

配置解析一次并验证类型；来源优先级与覆盖规则应可解释。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
避免模块导入时捕获环境导致测试难以隔离。配置优先级应显式且可追溯；生产环境敏感默认值宁可明确缺失，也不意外连接开发或真实账户。
