# 138 · 表格清洗：类型、缺失与重复

## 学习目标

完成「表格清洗：类型、缺失与重复」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

表格清洗先理解每列含义，再处理格式。看起来一样的日期可能是文本或日期值，空白与0可能含义不同，重复行也可能是合法重复交易。先定义规则，再保留清洗前后数量和异常清单，避免把数据“清干净”却删掉重要信息。

专题补充
清洗不等于把数据变得整齐。类型转换可能破坏前导零，补值可能把未知改成真实零，去重可能删除合法交易。业务规则先决定转换，再由脚本或表格实施。对账应包含保留数、排除数、异常数和金额口径，才能发现无声损失。

先为每列定义类型、单位和业务含义，抽查原始值，再写转换规则。每次删行、改值或合并都记录原行号和原因。用行数、金额与异常清单做前后对账；保留原件，清洗结果另存。

## 示例与解读

```text
字段：日期、项目、金额分、状态
规则：金额为整数；缺失状态标待核对，不自动填成功

补充案例：类型画像：发现编号不是数量
合成CSV：id,date,amount_cents,status；001,2026-06-01,1200,paid；002,2026/06/01,0,free；003,2026-06-02,,pending；002,2026/06/01,0,free；004,2026-06-03,850,paid；005,2026-06-03,-200,refund。id是文本；重复002为导出重复；缺失金额未知；负值表示退款。
本课条件：001与002含前导零
```

每个转换可解释且可回溯。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「表格清洗：类型、缺失与重复」，可与本课示例对照；无无关真实资料。

2. 查看列类型与样本

   应看到：不只看表头。

3. 定义缺失和重复规则

   应看到：经业务语义确认。

4. 在副本清洗

   应看到：保留原件。

5. 对账行数与合计

   应看到：解释删改原因。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「每个转换可解释且可回溯。」逐项对照，不把未执行项填成通过。

7. 逐列列类型、合法值和转换风险，抽查每个状态

   应看到：数据字典将id列定为文本，amount_cents为可空整数

   为什么：外观像数字不代表可做算术，标识需保留原字形

8. 改变条件：新增编号0007

   应看到：仍保留四位文本，不能因长度不同自动补成统一数值

   为什么：原始6行，删除一个重复002后5行；已知金额合计1850分，003金额仍缺失。编号001不可变1，退款-200不可当脏数据删去。

## 故障恢复

- **结果与示例不一致**：账号、邮编等看似数字的标识可能有前导0，不能直接转数字。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

清洗脚本记录转换步骤与输入哈希，避免人工不可追溯修改。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
流水线记录inputHash、schemaVersion、rowId、ruleId和before/after。整数分避免浮点货币误差；解析日期需明确格式与时区。幂等性指相同输入重复清洗结果一致，不是允许覆盖原始文件。
