# 013 · 接入聊天软件：在手机上指挥 Koder

单元 1 · 建议 40 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-13) · [总纲](../README.zh.md)

## 学习目标

把已授权的聊天渠道接到本机任务，并验证配对、消息到达与权限。

## 原理讲解

Koder 能接入飞书、企业微信、微信、钉钉、Telegram、Slack、Discord 和 WhatsApp。各适配器需要相应平台账号与授权。按 setup 的实际提示连接并检查状态；微信流程由服务端决定。本预览版尚未完成真实账号验收，教程不会发起连接。

专题补充
聊天入口把远端消息送到本机任务，涉及账号身份、会话映射、配对、执行和回复。任何一个环节成功都不能代替整条链。默认配对与群聊范围保护用户资料。课堂只分析合成事件，不连接平台或发送消息；真实渠道需使用自己获授权的账号另验。

将一条消息拆成事件链，给每个事件写账号、会话、消息ID和状态。先验证只读任务，再讨论写入审批和取消。用重复、断线、未配对三类输入检验设计，保存未知结果而不是自动重发。

## 准备

先选一个已有账号与管理权限的平台。教程展示的配对码是示例，不能照抄；渠道上线可能对外发消息。

## 手把手操作

1. 运行 koder gateway status，确认是否已有运行实例。

   应看到：先复用现有宿主，不再启动另一个后台抢连接。

2. 运行 koder gateway setup &lt;平台ID&gt;，按当前界面完成自己的账号授权。

   应看到：成功仅表示配置/连接阶段完成，不能证明每种消息都可收发。

3. 用自己的测试私聊发送一句无敏感内容的话，核对本机生成的配对码再配对。

   应看到：未配对不执行任务；只批准自己识别的账号。

4. 完成一个只读任务，检查两端消息和会话归属；再测试取消。

   应看到：收取、执行、回复和取消各有证据；断线时不冒已回复。

5. 写五段状态图并指出未完成部分

   应看到：任务已执行但尚无回复成功证据

   为什么：业务完成与消息送达分属两层

6. 改变条件：回复取得平台receipt r1

   应看到：可以确认该回复已受理，收件端阅读另属状态

   为什么：输出包括消息关联表、拒绝路径和回复去重策略。客户端显示“在线”只说明连接层；执行与回复需要对应回执。两端状态不一致时先对账。

## 故障恢复

- **终端关了收不到消息**：检查常驻状态；可按第20课明确activate，不把后台子进程当重启后自动服务。

- **群聊与私聊资料混用**：先确认关联和共享范围，撤销不需要的关联，不清空全部个人历史。

## 开发者教学

Gateway复用原会话、权限、取消与操作账本；不要为渠道另建无边界执行器。
测试重复消息去重、重连、未配对拒绝和审批过期。
真实平台收据与本地桩分开；Webhook公网暴露须单独核查目标和访问控制。

开发者加餐
渠道应复用原会话与权限控制器，不能另建绕过审批的执行器。去重键需包含渠道和账号；群私聊映射必须显式，断线后的未知发送效果不能直接重试。
