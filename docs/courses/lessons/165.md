# 165 · 单元项目：交付一个可验证的工具Skill

## 学习目标

完成「单元项目：交付一个可验证的工具Skill」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

把一个小工具和Skill结合起来：Skill说明何时用，工具提供明确输入输出，测试验证成功、失败和权限边界。选择本地只读项目摘要工具即可，不需要云账号。最终交件要区分资源可读、工具能调用和业务结果正确。

专题补充
综合集成要让方法、工具和结果相互对应。Skill告诉调用者何时用及怎样核对，工具实现明确的转换，测试揭示边界。发现与读取可验证配置，真实工具调用验证执行，输出标题正确才验证业务效果。一个成功样例不能证明所有Markdown语法与平台兼容。

选择本地只读README摘要任务，先写输入输出和目录边界，再写Skill触发与资源说明。设计工具schema和实现方案，用正常、缺文件、越界与重复标题样本检验；最后交包结构、兼容矩阵和可复做样例。

## 准备

先完成第164课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。账号、图形操作和外部写入须另有可用环境与授权；没有条件就记录NOT_RUN。

### 跟做 1：画出能力链路

按本课情境列出 CLI、Skill、工具、MCP server 与真实目标。标明谁提供说明、谁执行、谁授权、谁保存回执。

检查点：能解释 Skill 被找到不等于工具已运行。

### 跟做 2：先查现有能力

检查本地目录和已连接工具，缺项再按既有权限查官方说明。记录来源、版本和适用平台，不直接执行教程里的任意脚本。

检查点：复用已有入口，网络、安装和桌面授权各自核对。

### 跟做 3：用最小目标验调用

先做一个有明确输入与输出的合成任务。MCP 分别检查握手、工具列表、调用和结果；子 Agent 分别检查任务归属、结果和取消。

检查点：工具声明、调用成功和真实外部效果不会混成一个状态。

### 跟做 4：变更后重验边界

按本课变式修改环境、权限或能力选择，检查拒绝与恢复路径。经验候选只记录实际证据，不把一次自评直接变成默认规则。

检查点：原 Core 的权限、预算与取消继续生效。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 工具链各层职责清楚
- 来源与适用条件可核对
- 最小调用有输入输出证据
- 缺权、缺驱动或取消有正确处理
- 能力改进保留原执行与权限边界

### 开发者复盘

为协议输入、工具结果、断开、取消和重连分别写断言。子任务共享父预算和授权，结果必须保留完整回执或可读取引用。JIT/经验层只调整受控配置，不修改凭据、权限或成功判据。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「单元项目：交付一个可验证的工具Skill」，可与本课示例对照；无无关真实资料。

2. 定义窄任务

   应看到：例如读取获准README并列标题。

3. 写Skill与工具接口

   应看到：能力不重复实现。

4. 运行正反例

   应看到：越界与缺文件明确拒绝。

5. 整理安装和停用说明

   应看到：可移除可回退。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「每个主张能对应实际检查。」逐项对照，不把未执行项填成通过。

7. 写标题提取范围、层级与输出格式

   应看到：工具返回三个标题，不生成不存在的内容摘要

   为什么：任务越窄越易独立验证，摘要推理需另一个契约

8. 改变条件：用户要评价章节质量

   应看到：保留标题提取作为输入，另定义评价依据，不把抽取器说成已能审稿

   为什么：正常样例3个标题、层级1/2/2；缺文件明确失败；代码块中的#不应误算为标题。若实现只支持窄Markdown子集，必须说明且用反例检验。

## 故障恢复

- **结果与示例不一致**：不要把“所有平台完全兼容”写进没有真实设备证据的交件。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。
