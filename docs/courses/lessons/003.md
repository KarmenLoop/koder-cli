## 学习目标

使用自己账号支持的服务、协议和型号建立连接，分别验证文本与工具续答。

专题补充
模型连接由服务产品、区域、协议、地址、型号和凭据共同决定。配置保存只表示这些字段写入成功，文本回复只证明一次文本请求；编码代理还需要工具调用、结果回传和续答。课堂使用虚构地址与凭据占位符进行配对，避免把某个套餐的历史参数当成账号当前权限。

先列配置六元组，再逐层验证字段是否属于同一产品。阅读当前文档的可用状态，灰色或 held 项不能靠改名启用。诊断从保存、发现、文本、工具循环分层；每一层都写明输入和可观察输出。这里的离线样例不发送任何网络请求。

## 准备

准备服务商控制台里的产品类型、模型ID和官方Base URL。密钥只在专用输入框或秘密管理器里提供，不贴到聊天。真实诊断可能收费。

## 手把手操作

1. 运行 koder setup，选择模型设置；先选国内/国际、按量API/套餐，再选型号。

   应看到：产品与密钥来源一致；灰色入口停用，不要把网页会员当API额度。

2. 输入密钥后保存；运行 koder model show，核对模型、协议和地址。

   应看到：配置值符合控制台；分享输出前确认敏感信息已遮盖。

3. 运行 koder model test；成功后再运行 koder model test --tools。

   应看到：分别保存两次结论；文本成功、工具失败时不能认定编程代理全通。

4. 运行 koder model presets；需要检查某入口的模型信息时用 koder model models &lt;预设ID&gt;，以本机帮助和控制台为准。

   应看到：发现结果与可用权限分别核查；自动更新型号信息不会给账号新增额度。

5. 把六字段写为配置说明，并指出哪些可分享、哪些只写引用名

   应看到：五项非秘密配置可用于定位；凭据只记录环境变量名不记录值

   为什么：同名模型可出现在不同产品，完整组合才确定请求路线

6. 改变条件：把凭据来源改为 EU_KEY

   应看到：指出区域与凭据可能不匹配，先核控制台产品归属

   为什么：输出应包含字段配对表、协议路径推导和分层能力矩阵。检查时用错区域、错协议、缺模型三个反例；用量不可得时保留未知。需要真实验证时由学员用自己的授权账号单独执行并记录，课程给定结果只能作为分析输入。

## 故障恢复

- **HTTP 401/403**：核对账号地区、产品、授权和密钥有效期，不循环重试。

- **422且含1026/1027**：这是MiniMax内容过滤信号；按第22课缩小输入、开新会话诊断，不当断网处理。

## 开发者教学

CI优先用 --key-env VARIABLE_NAME 引用秘密变量，不把Key值写入参数。
分别准备成功、401、429、5xx、内容过滤与工具协议错误的本地桩；断言错误分类和脱敏信息。
model test 是短诊断，不照搬长任务重试预算；真实请求和桩测试分别记账。

开发者加餐
适配器应将 endpoint 规范化和模型能力判断分开。缓存键包含账号凭据指纹与接口，不保存明文密钥；未知工具能力不能当作支持或不支持。测试需要覆盖工具调用 ID 与后续消息对应，防止一次文本成功掩盖协议问题。
