## 学习目标

完成“三分钟展示：先让评审看到作品”：安排打开页面、展示数据、解释一项结果的顺序；解释基准与变式的结果。

## 原理讲解

答辩的核心是能解释并交付，而不是背诵术语或展示完成数。证据要指向当前文件与实际检查，取舍要说明为何选择某方案及放弃什么。新输入能暴露只会照抄模板的缺口。自评分用于定位学习计划，不自动成为职业资格或真实平台能力认证。

本案例的关键推理：产物先出现能让后续解释有具体对象

操作方法：先实际打开最终产物，再用问题、实现、证据、取舍和恢复五条线讲解。给每个评分附可定位依据，并用一个新输入检验迁移能力；阅读进度、测验与实操成果分别记录，后续学习按真实薄弱项安排。

## 准备

先读原第 180 课。使用自有练习目录。本课提供合成数据与状态，可先离线完成分析或文稿。涉及真实模型、GUI或账号时，只在条件与授权齐备后另做实测。

### 跟做 2：在副本完成变更

按本课操作修改文档、代码或发布资料，查看完整差异。GitHub 令牌只用既有凭据入口；课程练习不默认推送真实仓库。

检查点：改动范围具体，可审查；草稿与已公开状态分开。

### 跟做 3：核对交付链

逐层检查源码、测试、打包文件、安装启动与公开下载。本课只做文档或推演的层保持相应标记，不把一个环节成功扩成全链通过。

检查点：版本与哈希能对应实际下载内容，平台差异有单独记录。

### 跟做 4：让下一位接得住

按给定变式更新相关文件并重验。写清恢复版本、回退方法、已知限制和下一任务；用新目录按 README 再走一遍。

检查点：接手者能修改、验证和恢复，不依赖作者口头记忆。

### 开发者复盘
