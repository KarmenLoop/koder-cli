# 034 · 复制命令之前先分清命令与输出

## 学习目标

完成「复制命令之前先分清命令与输出」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

教程通常同时展示要输入的命令、工具输出和解释文字。把提示符、行号或“应该看到”一起粘进去会产生莫名其妙的错误。先运行只读短命令，观察返回，再逐步增加参数，比一次粘贴十行更容易知道错误发生在哪一步。

专题补充
终端记录通常混合提示符、输入、stdout、stderr和退出状态。复制一整段屏幕可能把提示符、注释或旧结果当命令执行。好的教程把可输入内容与解释分开；复制命令前还要核对占位符、Shell类型和当前目录。

从给定转录中标注每一行的来源，提取最短可复制命令。对可疑运算符和占位符先解释含义，再用打印参数的小程序验证。保留原始转录与提取版，避免改写错误文本。

## 准备

先完成第33课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 示例与解读

```text
输入：koder --version
示例输出：0.4.11
不要输入：koder › koder --version

补充案例：从转录提取唯一命令
三行：$ node --version；v22.0.0；$
```

版本由程序返回；示例版本是内容基线，不保证你的电脑正好相同。

### 跟做 1：建立最小目录

在自有练习目录创建 input、output、notes 三个子目录。将本课给定文本写到 input 中，先列目录并读回文件，确认没有在安装目录里编辑。

检查点：目录层级和文件内容与题目一致，路径包含空格时仍可定位。

### 跟做 2：拆开命令理解

将本课命令拆为程序、参数、输入、输出、重定向五部分。遇到管道，说明每段从哪里读取、向哪里写；先检查单段再组合。

检查点：能解释 stdout、stderr 和退出码分别代表什么。

### 跟做 3：运行并记录差异

只在副本执行本课任务。保存关键输出和退出码；对文件转换，逐行比较输入与输出，明确编码、换行和相对路径。

检查点：失败不会被空输出或最后一条 echo 掩盖。

### 跟做 4：搬迁后复做

复制练习到新的自有目录，优先用相对路径复做。Windows 的 PowerShell/CMD 与 macOS Shell 语法分别记录，不机械复制。

检查点：新目录仍能读到相同输入并得到相同业务结果。

## 故障恢复

- **结果与示例不一致**：出现“无法识别命令”先看是否多粘了$、&gt;或中文解释；别立即修改系统执行策略。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。
