# 036 · 标准输入：交互终端与管道的区别

## 学习目标

完成「标准输入：交互终端与管道的区别」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

交互输入用于对话，标准输入也可能来自另一个程序。管道的生产者即使暂时没发文字，仍可能保持连接。脚本已有明确任务参数时，不应无限等待输入结束。本课用有界合成生产者观察这件事，不启动长时间睡眠，也不把真实资料交给模型。

专题补充
标准输入是字节流，不保证每次数据事件对应一行、一个JSON或一个汉字。TTY交互和管道读取的结束方式不同。正确消费者先保留完整字节顺序，再解码和解析；流超时、超量或中断必须明确失败，不能把前半段当完整资料。

创建只读stdin的Node练习程序，收集Buffer块，结束后合并并解析。用手工分块数组模拟任意边界，观察UTF8与行分隔。将本地流练习与Koder --stdin入口对应，但不在课程中发起模型请求。

5. 在笔记画出生产者到消费者再到EOF

   应看到：区分无数据与输入结束。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

7. 按顺序拼接后再split换行

   应看到：得到ab和cd两行

   为什么：传输边界与文本边界独立

8. 改变条件：最后没有换行

   应看到：仍保留最后cd，不能只处理带分隔符行

   为什么：验证应覆盖空输入、分块、EOF、大小上限和解析失败。结果必须与原字节一致；界面没有新文字并不能证明生产者已经结束。

## 开发者教学

读取stdin需要有界首块等待、取消和资源释放；答案已输出仍不退出也是缺陷。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
使用增量解码器或在有界输入完成后统一解码，避免拆坏多字节字符。背压和截止时间保护资源，取消只关闭本次拥有的流。
