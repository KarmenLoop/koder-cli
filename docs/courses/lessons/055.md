# 055 · 会话上下文：保留事实，丢掉噪声

## 学习目标

完成「会话上下文：保留事实，丢掉噪声」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

上下文不是越长越好。安装包二进制、长日志和重复讨论会占据窗口，让关键约束变得不明显。好的压缩保留目标、已完成工作、事实证据、剩余问题和权限边界。摘要只能帮助继续任务，不能替代原始回执或把猜测变成事实。

专题补充
上下文应保存目标、约束、已完成事实、未决状态和证据入口。重复讨论、完整二进制和无关日志会挤占有效窗口。摘要是导航材料，原始回执仍是事实依据；压缩不能把推断改成确定，也不能把历史引用提升为新授权。

将合成任务历史标成目标、决定、观察、猜测和噪声五类，再按当前下一步选择必需内容。给每条已完成事实加文件或回执来源，保留旧失败和禁止重放事项。用摘要完成一个新小步骤来检查遗漏。

### 跟做 1：把要求落到产物

从本课输入提取对象、读者或使用者、需要完成的动作。写出最终文件或可观察状态，再列出三条可以核对的成功标准。

检查点：“好看”“专业”被补成可检查的结构、内容或交互要求。

### 跟做 2：分开事实与默认值

给每条事实标来源；未知事项判断是否会改变结果。低影响默认值可明确写出，高影响的发送对象、价格或权限不能靠猜。

检查点：任务卡能告诉执行者哪些可以先做、哪些需确认。

### 跟做 3：安排依赖与补充

将目标拆成有输入和产物的小步骤。按本课情境记录补充是在当前任务引导、下一任务排队还是取消后改做；已完成操作不自动重放。

检查点：补充要求能落到具体步骤，前后任务身份不混淆。

### 跟做 4：用结果倒查任务卡

完成本课操作后，逐条用产物对照成功标准。变式只改指定条件，并指出原任务哪些要求仍然有效。

检查点：不会只因回复流畅就给完成；失败或缺条件有清楚的下一步。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 任务结果可观察

- 引导、排队或取消语义对应情境

### 开发者复盘

为任务状态迁移写事件序列：根消息、steer、工具结果、取消、终态。检查引导不冒充新授权，排队文字不进入审批答案。模型与执行器职责分开，使用原预算和取消链。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「会话上下文：保留事实，丢掉噪声」，可与本课示例对照；无无关真实资料。

2. 选一段合成任务历史

   应看到：不放私人聊天。

3. 提取有效约束

   应看到：去掉重复礼貌语与无关日志。

4. 给事实加来源

   应看到：文件、命令或工具回执。

5. 用摘要继续一个小步骤

   应看到：核对没有遗漏边界。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「每个已完成项可回到文件或回执，未知项仍写未知。」逐项对照，不把未执行项填成通过。

7. 逐项贴标签并选续接必需项

   应看到：保留目标失败与文件事实，猜测明确标注

   为什么：内容类型决定压缩优先级

8. 改变条件：礼貌句中夹“不要发布”

   应看到：提取关键约束，不能按整句风格删除

   为什么：验收要求摘要足够短但能安全继续，未知项仍未知，原始证据可找回。字符缩短率不等于语义保真；应通过问题清单反向检查保留信息。

## 故障恢复

- **结果与示例不一致**：大块Hex不直接贴入模型；先用受控工具提取相关信息并保留原始文件。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

上下文压缩要保留工具调用关联、未决状态和取消点；压缩后仍能追溯。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
