# 045 · 单元项目：做一份可搬走的练习工作区

单元 3 · 建议 90 分钟（含自行练习） · 0.4.16 配套教材

## 学习目标

完成「单元项目：做一份可搬走的练习工作区」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

这一课把终端、路径、文件、差异和日志连成一份可交接的工作区。目标不是堆很多文件，而是另一位学习者能够打开README、运行本地检查、看到同一结果。目录可以压缩搬走，但不应携带密码、无关缓存或机器专属绝对路径。

专题补充
可搬迁意味着作品不依赖原电脑的绝对路径、未声明工具或隐藏账号状态。复制文件只是第一步，目标位置还要能打开、运行和理解。归档应保留必要源码、资产、说明与证据，同时排除秘密、无关缓存和机器专属状态。

用一个无依赖Node统计小项目制作完整交付目录。先列文件清单与相对关系，再复制到新路径从README启动；建立哈希清单以核文件完整性。移动测试只作用于自己的练习副本。

## 准备

先完成第44课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 从文件开始跟做

本课工作目录：`Koder Projects/lesson-0045`。交件：可搬迁的练习工作区，保存到 workbook.md 或本课指定文件。

1. 下载本课工作簿，或用离线教材的 academy-practice.mjs 创建自有目录；把本课合成输入保留在 input.txt。
2. 在 workbook.md 的“操作前的预测”写出预期，然后完成：完成「单元项目：做一份可搬走的练习工作区」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。。
3. 按下面的方法保存实际步骤与结果，先不复制参考答案。
4. 只改变这项条件：提交压缩包与验收表，至少记录路径、编码、退出码和目录隔离四项。。保留基准，再独立完成变式。
5. 用自评表和课堂参考核对，说明证据缺口；有实际作品时保留可编辑文件。

### 跟做 1：建立最小目录

在自有练习目录创建 input、output、notes 三个子目录。将本课给定文本写到 input 中，先列目录并读回文件，确认没有在安装目录里编辑。

检查点：目录层级和文件内容与题目一致，路径包含空格时仍可定位。

### 跟做 2：拆开命令理解

将本课命令拆为程序、参数、输入、输出、重定向五部分。遇到管道，说明每段从哪里读取、向哪里写；先检查单段再组合。

检查点：能解释 stdout、stderr 和退出码分别代表什么。

### 跟做 3：运行并记录差异

只在副本执行本课任务。保存关键输出和退出码；对文件转换，逐行比较输入与输出，明确编码、换行和相对路径。

检查点：失败不会被空输出或最后一条 echo 掩盖。

### 跟做 4：搬迁后复做

复制练习到新的自有目录，优先用相对路径复做。Windows 的 PowerShell/CMD 与 macOS Shell 语法分别记录，不机械复制。

检查点：新目录仍能读到相同输入并得到相同业务结果。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 目录和输入可重建
- 命令参数与重定向解释正确
- 输出、错误与退出码均有记录
- 空格、编码或缺文件边界有一项检查
- 换路径后不依赖作者机器的绝对位置

### 开发者复盘

将 cwd、环境变量与临时目录作为测试参数。先构造输入边界再断言退出码和文件内容。对本课涉及的流处理，验证 EOF、无输入和坏参数，不用无限等待掩盖阻塞。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「单元项目：做一份可搬走的练习工作区」，可与本课示例对照；无无关真实资料。

2. 建立干净练习目录

   应看到：没有秘密或真实资料。

3. 完成路径与编码两个检查

   应看到：结果可从文件核对。

4. 保存一次参数错误再修正

   应看到：证明失败有清楚诊断。

5. 在新位置复制后重跑只读检查

   应看到：相对路径依然有效。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「README说明Shell和步骤，日志保留成功与失败两类结果。」逐项对照，不把未执行项填成通过。

7. 列三文件及相互依赖

   应看到：三件足以理解和运行，无隐藏外部服务

   为什么：小项目先建立完整依赖闭包

8. 改变条件：脚本还读取桌面config.json

   应看到：将必要非秘密配置纳入或显式参数化，不能漏报

   为什么：验收包含复制完整、入口有效、依赖声明、路径可移植和结果一致。当前操作系统通过不能替代另一系统实机验收，归档成功也不等于程序可运行。

## 故障恢复

- **结果与示例不一致**：搬迁失败先查硬编码绝对路径；不要靠把整台电脑配置一起打包来解决。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

设计交件清单与哈希；压缩包验收要实际解压后检查入口，而不只检查压缩命令退出0。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
清单应使用稳定相对路径与内容摘要，排除运行时秘密。生成物和源码版本要对应，恢复时不自动继承执行权限或重放旧任务。
