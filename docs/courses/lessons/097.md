# 097 · 事务：多步操作要么一起成立

单元 7 · 建议 30 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-97) · [总纲](../README.zh.md)

## 学习目标

完成「事务：多步操作要么一起成立」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

事务用于保持一组数据库变更的一致性。比如创建任务并写审计记录，两者应按设计一起提交或一起回滚。事务不能覆盖任意外部邮件或HTTP调用，所以不要把数据库回滚误认为外部效果也撤销。对跨系统流程需要单独的状态与对账。

专题补充
事务把一组数据库变更视为同一提交单位。创建待办与写审计应按设计一起成功；外部邮件和HTTP调用通常不在同一数据库事务中，回滚数据库不能撤回已经发出的消息。

列出参与同一事务的SQL及外部动作，设计每一步失败时的结果。先用合成状态推演，再在可用的隔离数据库中验证提交与回滚，保留原始失败。

## 示例与解读

```text
BEGIN
插入todo
插入audit
COMMIT
任一步失败：ROLLBACK

补充案例：让待办与审计共同提交
步骤insert todo t1，再insert audit a1

可复制的离线 Node 样例（仅计算合成数据或内存时序）：
(async()=>{const db={todos:[],audit:[]};const draft=JSON.parse(JSON.stringify(db));let committed=false;try{draft.todos.push("t1");throw Error("AUDIT_FAILURE");}catch{}return {db,committed,draftTodoCount:draft.todos.length};})().then(value=>console.log(JSON.stringify(value)));
```

测试失败后两张表都不留下半成品。

   Node 固定输出：{"db":{"todos":&#91;&#93;,"audit":&#91;&#93;},"committed":false,"draftTodoCount":1}

   为什么：同一业务不变量可由事务保护

8. 改变条件：第二插入失败

   应看到：回滚后两条均不存在，不留下无审计待办

## 故障恢复

- **结果与示例不一致**：长时间网络请求放在数据库事务里会占锁；先设计流程再实现。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

事务提交后再发送事件时要考虑可靠投递；不得把未确认写入记为完成。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
事务范围不宜包含长网络等待。跨系统可用outbox等明确状态设计，但必须处理重试与幂等；教学模型不自动提供生产消息可靠性。
