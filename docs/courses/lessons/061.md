## 学习目标

完成「读代码的第一步：输入、输出与副作用」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

阅读函数先问它接收什么、返回什么、还改变了什么。返回值之外的文件写入、网络请求和全局变量修改都属于副作用。用几个小输入手算一遍，通常比逐字解释语法更快发现业务规则。本课以原有购物车为例，不需要先学完一门语言。

专题补充
社区书店用整数分记录价格，数量表示同一商品的件数。维护者准备在购物车和订单摘要两处复用计算函数；两处都需要明确输入所有权、返回单位和失败方式。先读数据流，再读每个运算符，可以避免把恰好成功的小样本当成通用规则。 计算层只接收显式参数；金额使用整数分，计算不修改调用方数组。输入与输出都应能独立列成表，任何额外读取和写入必须单独说明。

把函数拆成输入域、转换、返回值、可观察副作用四部分。值相等不意味着引用相等；局部变量重新赋值和修改共享对象也不是同一行为。用拷贝前后的结构比较保护数据所有权。

## 示例与解读

```text
export function total(items) {
  return items.reduce((sum, item) => sum + item.price, 0);
}

补充案例：追踪数量怎样进入总额
合成 Node 程序：
(async()=>{const items=[{price:200,qty:3},{price:150,qty:1}];return items.map(x=>x.price*x.qty).reduce((a,b)=>a+b,0);})().then(value=>console.log(JSON.stringify(value)));
```

这个实现忽略qty；200分三件仍只加200分，说明输入契约未落实。

### 跟做 1：逐项追踪输入

先列输入类型、单位、所有权和空值含义。按本课操作手算一遍或画数据流，再运行给定程序；保留原程序，修改放在副本。

检查点：在看程序输出前已有独立预期，金额的分与元不混用。

### 跟做 2：定位最小改动

根据第一次不一致定位函数或分支。修复先写失败用例；重构固定行为；优化固定正确结果并记录数据规模。

检查点：改动目标明确，不以全仓格式化或新增无关依赖代替修复。

### 跟做 3：逐步实现并核对

只改与题目有关的逻辑。运行原检查，再加入本课指定变式；保留标准输出、退出码及修改文件。无需真实服务时保持本地运行。

检查点：新旧实现可在相同输入下比较，失败不被吞掉。

### 跟做 4：解释代价和边界

写出为什么成立，并至少指出一个不适用条件。性能题说明时间与额外空间；异步题说明顺序、失败和清理；重构题说明保留的行为。

检查点：解释具体到数据、操作或状态，不能只有“更高效”。

   为什么：总额正确但调用者列表顺序改变时，检查 sort 是否作用在原数组；只有数字正确而没测输入快照，会漏掉这种副作用。
