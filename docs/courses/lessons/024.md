## 学习目标

理解工具调用是完整往返：提出调用、执行、回传、模型续答。

## 原理讲解

小米 Token Plan 暂时检修，请别拿密钥反复试。下面说明只适用于当前可用的接口；灰色入口会直接提示暂时无法使用。
MiMo 的按量付费与 Token Plan 也不能混用密钥。已经配置好模型后，先检查文字，再明确选择工具续答测试。下面命令会真实请求你的 API，可能产生费用；教程只展示，不替你执行。

专题补充
模型说“我要读取文件”只是调用提议。完整往返包括结构化调用、获准执行、带关联ID的结果和模型基于结果续答。工具可以成功而续答失败，也可以文本聊天正常但工具参数不兼容。当前MiMo Token Plan文档标暂不可用，课堂不启用该路线，只用协议事件练习。

先将消息按角色排序，检查调用ID、工具名和参数，再把执行结果回填到对应位置。最后核对最终回答是否来自实际结果，而不是模型猜测。用缺ID、错参数和续答失败三个反例测试理解。

## 准备

本版MiMo Token Plan入口停用时只做离线理解；真实测试选择当前可用且已授权的服务。

### 跟做 1：列清配置层次

把本课给定字段放入“功能、配置位置、是否已保存、凭据引用名、授权范围”五列。未知字段写未知；密钥只写变量或凭据条目名称。

检查点：能区分配置存在、接口可达、功能可用与授权允许。

### 跟做 2：选择最小检查

先运行本课的只读状态命令或分析给定状态，再选择一个无外部写入的检查。不要为了证明保存成功而发送邮件或公开仓库。

检查点：每个判断对应一个状态字段或检查输出，不用一条文本回复证明全部工具能力。

### 跟做 3：沿失败层排查

按入口→配置→凭据→协议→权限→操作的顺序定位第一处失败。只改变有证据指向的字段，记录变更前后值；秘密值始终省略。

检查点：修复与具体失败关联，没有同时重置一整套设置。

### 跟做 4：验证恢复与撤销

在自己的练习配置中恢复原字段或关闭可选功能。检查原项目和记录仍在；没有实际执行恢复时写出待验步骤。

检查点：知道如何回退，功能开关不被误当作删除历史。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 配置地图字段完整且脱敏
- 保存与可调用证据分别列出
- 错误定位到具体层而非泛称断网
- 变式说明配置或权限如何变化
- 有保留原数据的恢复方法

### 开发者复盘

用注入的配置和凭据引用测试路径，不读取学员真实 Key。给保存成功但调用失败、授权撤销、旧配置缺新字段各写一个用例。配置迁移应保留旧值，能力状态不能由 UI 默认值推断。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 先运行 koder model show，确认实际模型与协议。

   应看到：文字测试与工具测试必须是同一配置，否则无法对照。

2. 在可用入口运行一次model test，再明确运行model test --tools。

   应看到：记录两次结果与时间，工具测试使用无业务副作用的检查。

3. 读错误细节：是工具格式、缺少结果、空回复，还是HTTP拒绝。

   应看到：MODEL_PROTOCOL不是自动等于网络断开。

4. 新会话做简短对照，保留旧会话；继续旧任务时明确指出未完成项。

   应看到：不把问候当重放旧任务的指令。

5. 按时间和角色排序

   应看到：user→调用c1→结果c1→final

   为什么：模型续答应在结果之后

6. 改变条件：final出现在工具执行之前

   应看到：不能证明答案使用实际工具结果

   为什么：输出需逐段标已发生和未发生。一次read_file返回成功只能证明这一调用，不能自动证明写入、取消或跨平台能力。

## 故障恢复

- **能聊天但不能执行**：把工具诊断结果交给反馈，不反复修改系统权限来解决协议错误。

- **旧历史太大**：新会话隔离复现，使用相关摘要与产物引用；不删除所有记忆。
