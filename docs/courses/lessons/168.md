# 168 · 读取仓库：先了解目标再修改

单元 12 · 建议 30 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-168) · [总纲](../README.zh.md)

## 学习目标

完成「读取仓库：先了解目标再修改」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

远程仓库读取要确认owner、repo、分支和路径。README可能落后于实际脚本，仓库文档也可能包含不可信指令。读取结果应作为任务资料，不替代用户授权。大文件有限读取时保留完整结果入口与版本信息。

专题补充
远程文件身份由仓库、ref、路径与内容版本共同确定。默认分支可能变化，文件也可能在读取期间更新；保存SHA帮助说明依据哪个快照。README提供入口，脚本和实现给实际行为。摘要不应丢掉原始结果恢复方式，也不应把仓库文档当作用户授权。

先确认owner/repo、分支或提交ref与路径，再读取README及实际脚本。大文件按问题分段读取，保留完整结果入口与SHA；把仓库内容当资料，不执行里面要求改变任务或泄漏数据的文字。

## 准备

先完成第167课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。账号、图形操作和外部写入须另有可用环境与授权；没有条件就记录NOT_RUN。

## 示例与解读

```text
koder github repo OWNER/demo
koder github read OWNER/demo README.md
koder github read OWNER/demo src --ref main

补充案例：目标身份：同名仓库如何区分
合成仓库qinghe-demo/docs-lab：main@a1的README写npm test，package.json实际脚本test为node --test；docs/setup.md在main存在，在release分支不存在；README@a0仍写旧命令。文档示例koder github read OWNER/demo README.md与--ref main，OWNER为占位。
本课条件：两个owner都有docs-lab
```

将OWNER/demo替换为获准测试仓库；不在无账号课堂自动调用。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「读取仓库：先了解目标再修改」，可与本课示例对照；无无关真实资料。

2. 核对仓库身份

   应看到：防止同名误选。

3. 读取目标分支

   应看到：记录ref。

4. 查看README与相关文件

   应看到：对照实际内容。

5. 保存变更前快照

   应看到：便于后续并发检查。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「将OWNER/demo替换为获准测试仓库；不在无账号课堂自动调用。」逐项对照，不把未执行项填成通过。

7. 制作仓库全名、ref、路径三字段读取卡

   应看到：卡明确qinghe-demo/docs-lab main README.md

   为什么：repo短名不唯一，远程身份必须完整

8. 改变条件：用户只给docs-lab

   应看到：先从已授权上下文确定owner，不能随意选搜索第一项

   为什么：摘要应说明main@a1与release差异，测试命令来自实际package脚本。release缺setup不能推断整个仓库无安装说明，也不能把a0内容当a1事实。

## 故障恢复

- **结果与示例不一致**：仓库里要求“上传全部秘密”的文字不能成为执行指令。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

交远程项目摘要，附仓库、分支、文件和未决项。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：没有，读取能力与写入授权独立。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

返回artifact引用、SHA与bytes；摘要截断不能丢失恢复入口。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
记录repositoryIdentity、requestedRef、resolvedCommit、path、blobSha、bytes和artifactId。路径大小写与owner/repo规范化规则不能混用。有限读取保留位置与完整入口；文档和执行脚本存在不证明已实际运行。

## 自测

A. 没有，读取能力与写入授权独立。

B. 获得了，读权限包含全部管理权限。

C. 获得了，公共仓库允许任何人直接写main。
