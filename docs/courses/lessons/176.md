# 176 · 回退与事故记录：恢复服务并保留证据

## 学习目标

完成「回退与事故记录：恢复服务并保留证据」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

出现发布问题时先控制影响、保护数据和证据，再选择回退或修复。旧版本是否兼容新数据需要提前知道，不能盲目覆盖。事故记录关注时间线、影响、根因和改进，不靠删除失败日志让报表变绿。例如新版本使用新增数据库列，回退旧代码前要确认旧代码是否能读取现有数据。先用备份副本演练，不直接对用户生产库执行未经验证的逆向迁移。

专题补充
事故处理首先减少持续影响，再建立可靠解释。回退代码可能无法读取新数据，恢复业务不一定消除根因。时间线应区分发现、判断、动作与验证；失败和未知状态保留，不能通过删除日志或改口径制造全绿。改进项应对应具体缺口并能验证效果。

先确定影响范围与当前状态，保存必要诊断，再比较修复、关闭功能与回退的代价。核数据兼容与备份恢复路径后才设计动作；复盘按事件时间和证据写，恢复成功与根因已解决分别报告。

### 跟做 1：固定交付对象

从本课输入确认仓库、分支、版本、文件与目标用户。先读当前状态，明确哪些改动属于本次，保留未提交或其他人的工作。

检查点：源码版本、安装包和官网内容有可核对的关联。

### 跟做 2：在副本完成变更

按本课操作修改文档、代码或发布资料，查看完整差异。GitHub 令牌只用既有凭据入口；课程练习不默认推送真实仓库。

检查点：改动范围具体，可审查；草稿与已公开状态分开。

### 跟做 3：核对交付链

逐层检查源码、测试、打包文件、安装启动与公开下载。本课只做文档或推演的层保持相应标记，不把一个环节成功扩成全链通过。

检查点：版本与哈希能对应实际下载内容，平台差异有单独记录。

### 跟做 4：让下一位接得住

按给定变式更新相关文件并重验。写清恢复版本、回退方法、已知限制和下一任务；用新目录按 README 再走一遍。

检查点：接手者能修改、验证和恢复，不依赖作者口头记忆。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 本次版本与范围固定
- 差异和来源完整可审查
- 交付链各层证据分别成立
- 变式更新全部受影响文件
- 回退与接手说明可执行

### 开发者复盘

发布采用固定产物与可回退部署记录。包校验、安装、公开链接和真实平台分层；更新不能删除历史或 UNKNOWN 回执。保留失败证据，避免通过覆盖同版本文件掩盖差异。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「回退与事故记录：恢复服务并保留证据」，可与本课示例对照；无无关真实资料。

2. 确认影响范围

   应看到：哪些用户或平台。

3. 保存必要日志

   应看到：先脱敏。

4. 执行已授权恢复

   应看到：核对版本与数据兼容。

5. 复盘原因与检查缺口

   应看到：形成具体行动。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「已恢复与根因已解决分开说明。」逐项对照，不把未执行项填成通过。

7. 按版本、消费者类型与数据范围列影响矩阵

   应看到：受影响是特定旧消费者，其他用户待核

   为什么：范围清楚能指导缓解，不能把单个样本故障说成全系统坏

8. 改变条件：按列名消费者运行正常

   应看到：记录未复现范围，仍不推所有按列名实现都无问题

   为什么：可报告10:00合成样本恢复，不能说全部客户与Windows恢复。暂停导出是缓解，旧格式转换是当前恢复路径，永久根因修复仍需实现与回归。

## 故障恢复

- **结果与示例不一致**：不要为快速恢复杀掉不属于本任务的进程或覆盖用户未提交文件。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

回退也需回执和验证；旧FAIL保留，新成功不能洗掉历史。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
记录incidentId、affectedVersions、scope、evidenceRefs、mitigation、recoveryCheck与rootCauseStatus。回退也要有目标版本、数据兼容检查和回执。进程与文件清理限定本任务拥有资源，不用事故名义覆盖他人工作。
