# 156 · 工具schema：让模型知道怎样正确调用

[课堂](../index.zh.html#lesson-156) · [总纲](../README.zh.md)

## 学习目标

完成「工具schema：让模型知道怎样正确调用」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

工具schema描述输入类型、必需字段和结果形状。名字准确、说明具体能减少模型猜参数。错误结果也应有稳定结构，告诉调用者是否可重试和有没有外部效果。工具描述不是越长越好，关键是选择和调用时所需信息。

专题补充
工具schema同时帮助选择和验证。类型正确不代表业务合法，路径还需约束根，数值还需范围。空字符串、缺字段、null与合法零值必须按契约区分。稳定错误码使调用者选择修参数、补前置或停止；把所有失败包成空文本会让模型生成错误结论。

先确定工具唯一职责，再定义输入类型、必需字段、长度范围和结果结构。用合法、缺失、越界、类型错误和空结果五类输入检查；对每种失败写是否产生效果与是否可重试，模型输出仍需工具边界验证。

## 示例与解读

```text
工具例：read_note({path:string})
结果：{ok:true,text,artifactId} 或 {ok:false,code}

补充案例：职责命名：读笔记还是管理文件
教学接口read_note接收path字符串与可选maxChars正整数，默认1000、上限5000；允许根为/lab/notes。样本a.md内容“青禾周报
报名40人”；missing.md不存在；../secret.md越界。成功返回ok、text、truncated、artifactId，失败返回ok:false、code、effect:"none"。这是合成接口设计，不是新增Koder命令。
本课条件：候选名do_everything含读写删
```

路径受工作区范围限制，返回大内容时保留artifact入口。

   应看到：目标聚焦「工具schema：让模型知道怎样正确调用」，可与本课示例对照；无无关真实资料。

2. 写工具用途

   应看到：说明何时用。

3. 定义输入约束

   应看到：范围、长度和必需项。

4. 设计成功与失败返回

   应看到：能区分状态。

5. 用错误参数调用测试

   应看到：得到可理解诊断。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「路径受工作区范围限制，返回大内容时保留artifact入口。」逐项对照，不把未执行项填成通过。

7. 将工具缩为read_note并写何时使用与不做什么

   应看到：描述明确只读获准笔记，调用者可预期结果

   为什么：单一职责降低选择歧义，名字不能替代权限校验

8. 改变条件：新增搜索需求

   应看到：设计独立搜索输入或独立工具，不把任意Shell塞进path字段

   为什么：a.md可返回正文，missing明确NOT_FOUND，越界明确OUTSIDE_ROOT，maxChars=0或5001拒绝。失败不读取其他文件；成功截断时保留artifact入口。

## 故障恢复

- **结果与示例不一致**：不要把工具返回的任意文本当成系统指令。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

schema与实际执行器一致；参数验证在工具边界再次执行。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
JSON schema与执行器校验保持一致；拒绝未知或不支持字段时给明确错误。大文本返回截断标志与原文入口，不能只裁掉尾部。参数验证发生在执行边界，不能信任模型已遵守schema。
