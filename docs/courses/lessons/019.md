# 019 · 记忆目录、群私聊与多设备

单元 2 · 建议 35 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-19) · [总纲](../README.zh.md)

## 学习目标

理解工作区、会话与共享记忆边界，安全地多窗口运行和恢复。

## 原理讲解

记忆并不等于把所有聊天塞进一次模型请求。当前任务使用相关记忆与压缩历史，完整记录按已配置范围持久化。新 Windows 用户优先使用可写 D 盘，否则使用可写 C 盘的用户专属目录；已有位置和显式配置保留。安装目录、密钥目录与记忆目录可能不同。
跨设备记忆服务：你们部署并确认可用的 Core 地址
登录后，此账号默认共享空间可在已关联的终端、渠道和设备间同步对话与记忆。已关联群的所有成员可使用关联私聊记忆，回复到群的内容会被群成员看到。请只关联允许共享的会话。模型API密钥、电脑执行授权不作为记忆同步。退出本机账号：koder account logout；删除共享空间记忆：koder memory forget。退出不等于删除服务器副本；离线设备需再次同步才应用删除。

专题补充
会话历史、项目事实和显式共享笔记有不同范围。多窗口的独立会话防止聊天与审批混淆，但文件仍可能共用。恢复要匹配工作区和会话身份，遇到占用应保护现有owner，不能因为记录旧就强行接管。

用两个合成工作区和三个命名会话画映射。给事实贴来源和范围标签，再模拟查询、恢复和并发修改。只使用A_ONLY_SYNTHETIC等标记，避免用真实秘密测试隔离。

## 准备

准备两个测试目录和不同的合成暗号；不使用真实个人秘密测试隔离。

### 跟做 1：列清配置层次

把本课给定字段放入“功能、配置位置、是否已保存、凭据引用名、授权范围”五列。未知字段写未知；密钥只写变量或凭据条目名称。

检查点：能区分配置存在、接口可达、功能可用与授权允许。

### 跟做 2：选择最小检查

先运行本课的只读状态命令或分析给定状态，再选择一个无外部写入的检查。不要为了证明保存成功而发送邮件或公开仓库。

检查点：每个判断对应一个状态字段或检查输出，不用一条文本回复证明全部工具能力。

### 跟做 3：沿失败层排查

按入口→配置→凭据→协议→权限→操作的顺序定位第一处失败。只改变有证据指向的字段，记录变更前后值；秘密值始终省略。

检查点：修复与具体失败关联，没有同时重置一整套设置。

### 跟做 4：验证恢复与撤销

在自己的练习配置中恢复原字段或关闭可选功能。检查原项目和记录仍在；没有实际执行恢复时写出待验步骤。

检查点：知道如何回退，功能开关不被误当作删除历史。

## 手把手操作

1. 在项目A运行 koder memory status，记录范围与存储位置。

   应看到：知道记录归属，而不是假设所有内容都在项目目录。

2. 在A告诉Koder合成标记；切到B询问A的标记，不提供答案。

   应看到：B不应自动读到A的任务事实。

3. 回到A继续；同项目另开命名会话用于独立排障。

   应看到：原任务可续，新会话单独归属；显式共享笔记另按范围说明。

4. 查看要删除的具体记录，先确认范围再执行forget类命令。

   应看到：退出账号、关闭学习和删除记忆不同；同步需要实际Core和读回证据。

5. 制作workspace与session二维表

   应看到：三个任务身份不同

   为什么：模型相同或窗口相邻不合并历史

6. 改变条件：再开/lab/a显式tests

   应看到：已占用时应MEMORY_BUSY，不能接管

   为什么：验收应覆盖跨项目不可见、显式共享可见、独立取消和文件冲突四项。自动task facts不能因摘要方便而变成全局记忆。

## 故障恢复

- **不同窗口仍相互串话**：记录目录、版本、session与共享笔记配置；先隔离复现，不清库掩盖。

- **登录显示成功但未同步**：检查账号、设备和同步状态，真实多设备需两端读回。

## 开发者教学

身份、存储键、检索过滤和缓存都要带相同工作区/会话范围。
并发测试覆盖同工程不同任务与不同工程；旧占用锁恢复需判断实际拥有者，不用盲删锁。
Headroom压缩仅影响模型视图，原始证据仍须可检索；压缩不是删除授权。

开发者加餐
会话键应包含工作区及会话标识；活动所有权保持到窗口正常关闭。进程实例比PID更可靠，未知owner不能抢占。共享文件需独立协调，不能从会话隔离推出磁盘隔离。
