# 116 · 安装与更新：下载、校验、切换、恢复

## 学习目标

完成「安装与更新：下载、校验、切换、恢复」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

更新流程应先获得完整可信包，再校验、准备新版本、切换入口并验证启动。下载成功不代表安装成功，切换成功也不代表旧进程已重启。失败时保留可用版本和清楚日志；不能让一次中断留下半个安装目录。

专题补充
更新包含发现、下载、校验、解包、准备、入口切换和启动检查。每一步成功都不能替代下一步。更新失败应保留可用版本；中断后的状态要能识别，而不是留下半个目录让用户猜测。

用合成版本A/B和包清单画流程，给各阶段注入失败。区分磁盘上的候选、当前入口和正在运行的进程，保留回退身份与完整错误。

## 准备

先完成第115课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

```text
更新阶段：发现→下载→哈希校验→解包→准备→切换→启动检查→清理

补充案例：识别下载未完成
清单预期1000字节，实际800字节

可复制的离线 Node 样例（仅计算合成数据或内存时序）：
(async()=>{const expected={bytes:1000,sha:"abc"};const received=[{bytes:800,sha:"abc"},{bytes:1000,sha:"bad"},{bytes:1000,sha:"abc"}];return received.map(x=>({complete:x.bytes===expected.bytes,hashMatches:x.sha===expected.sha,eligible:x.bytes===expected.bytes&&x.sha===expected.sha}));})().then(value=>console.log(JSON.stringify(value)));
```

每阶段可记录状态，旧可用版本保留到验证后。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「安装与更新：下载、校验、切换、恢复」，可与本课示例对照；无无关真实资料。

2. 确认当前版本与入口路径

   应看到：发现多安装位置冲突。

3. 检查包与校验值

   应看到：失败不继续切换。

4. 在隔离目录模拟更新

   应看到：不改正在运行安装。

5. 验证失败恢复

   应看到：仍能启动旧版本。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「每阶段可记录状态，旧可用版本保留到验证后。」逐项对照，不把未执行项填成通过。

7. 比较长度与完整性标记，停止解包 将上述完整程序保存为自有目录的 case.mjs，运行 node case.mjs；先独立预测输出，再与固定输出对照。

   应看到：不能激活部分包
   Node 固定输出：&#91;{"complete":false,"hashMatches":true,"eligible":false},{"complete":true,"hashMatches":false,"eligible":false},{"complete":true,"hashMatches":true,"eligible":true}&#93;

   为什么：网络命令退出不一定代表取得期望对象

8. 改变条件：长度1000但哈希不同

   应看到：仍拒绝，长度一致不能证明内容正确

   为什么：检查字节数、哈希、解包路径、文件完整性、切换结果与真实启动版本。包校验通过不证明程序行为；哈希也需要来自可信清单。

## 故障恢复

- **结果与示例不一致**：不要把新版文件覆盖到正在运行目录再补校验。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

原子切换与Windows文件锁需分别处理；日志应区分待重启与已生效。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
候选准备与激活尽量分离，使用明确原子边界和自有临时目录。回退不能覆盖用户后来数据，旧运行进程也不因入口更新自动换版本。
