# 154 · Skill资源与脚本：阅读后再执行

[课堂](../index.zh.html#lesson-154) · [总纲](../README.zh.md)

## 学习目标

完成「Skill资源与脚本：阅读后再执行」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

Skill可以引用脚本和示例，但这些文件仍需检查来源、输入输出和副作用。相对路径应从Skill目录解析，不从任意工作区猜测。脚本运行需要原权限批准，并在任务专属目录操作。文档中的代码块不应被加载器自动当作命令执行。

专题补充
脚本资源是代码材料，读取它不等于同意执行。契约必须说明什么算非空、路径从哪解析、编码如何处理和失败时输出什么。退出0只是程序报告成功，业务结果还需独立对照。便于复用的小脚本通常限制输入域并保持副作用简单。

先列包内文件和引用关系，阅读脚本入口、参数解析与读写范围，再决定是否有必要执行。课堂设计只读合成文本转换；执行前写独立预期，结果核内容、退出码和额外副作用。

## 准备

先完成第153课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。账号、图形操作和外部写入须另有可用环境与授权；没有条件就记录NOT_RUN。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「Skill资源与脚本：阅读后再执行」，可与本课示例对照；无无关真实资料。

2. 列出所有引用资源

   应看到：确认可读且未越界。

3. 阅读脚本入口

   应看到：找副作用。

4. 用合成输入运行获准部分

   应看到：不碰真实资料。

5. 核对产物与退出码

   应看到：不只看启动成功。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「执行范围可预览，依赖缺失有明确说明。」逐项对照，不把未执行项填成通过。

7. 阅读入口并列读取、写入、网络、子进程操作

   应看到：盘点明确统计脚本只读，安装脚本不属于统计必要步骤

   为什么：文件扩展名不能证明行为，必须看实际入口和调用

8. 改变条件：outline内部调用curl

   应看到：标网络副作用与来源，不能继续称完全本地只读

   为什么：样本非空行3，空白行按trim后为空处理。错误路径应有明确失败，不输出伪造count=0；脚本不得修改原文本或下载依赖。

## 故障恢复

- **结果与示例不一致**：不要自动下载并执行任意远程脚本来补依赖。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

写一个仅处理合成文本的脚本示例，附输入与输出契约。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不可以，阅读与执行需要分开并沿原审批。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

脚本路径和哈希可记录；执行不使用模型生成代码作为权限权威。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
参数验证与文件读取分离；规范化路径后仍须检查允许根及符号链接策略。JSON结果字段保持稳定，诊断不混入stdout。时间和大小上限属于执行边界，不能通过脚本内部重启绕过。
