# 006 · 做选择：Koder 也会问你

单元 1 · 建议 25 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-6) · [总纲](../README.zh.md)

## 学习目标

用可评价的选项推进任务，并能区分草稿选择、操作确认和真正交付。

## 原理讲解

遇到必须由你拍板的事，Koder 会停下来出一道选择题。输入选项前面的数字，回车确认；直接回车就是取消这一轮。

专题补充
一个好选项需要明确改变什么、保留什么、付出什么。视觉偏好、需求决策与执行授权虽然都可能用按钮呈现，含义不同。比较方案时固定目标和输入，避免把漂亮的描述当作已实现功能。没有答案时可继续整理资料，但涉及账号、费用和发送的决定不能由沉默补齐。

先把问题改写成一句决策，再列两到三个互斥方案。给每个方案写同一组评价维度与一个反例。用纸面原型或本地文档进行评选，选中后将理由写回需求；检查后续交付是否真的体现了选择。

## 准备

准备一份简短网站需求：受众、目标、内容、风格和限制。不提供密码或真实客户名单。

## 从文件开始跟做

本课工作目录：`Koder Projects/lesson-0006`。交件：操作记录与小作品，保存到 workbook.md 或本课指定文件。

1. 下载本课工作簿，或用离线教材的 academy-practice.mjs 创建自有目录；把本课合成输入保留在 input.txt。
2. 在 workbook.md 的“操作前的预测”写出预期，然后完成：用可评价的选项推进任务，并能区分草稿选择、操作确认和真正交付。。
3. 按下面的方法保存实际步骤与结果，先不复制参考答案。
4. 只改变这项条件：写一条少于150字的三案需求；给一案3条具体修改意见与2项验收标准。。保留基准，再独立完成变式。
5. 用自评表和课堂参考核对，说明证据缺口；有实际作品时保留可编辑文件。

### 跟做 1：定位操作入口

先分清屏幕上的系统终端和 Koder 提示符。系统命令在终端运行；以 / 开头的会话命令放在 Koder 对话中。把本课出现的目录逐个写入 environment.md，并标注“当前目录”“临时练习”“正式作品”。

检查点：能指着一条命令说明由谁解释、在哪个目录发生；不同目录不被画成同一个对象。

### 跟做 2：先预测再操作

将本课输入逐项编号。执行前先写一句预期，再按本课任务操作一次。需要点击或审批时，记录选项名称与选择理由；无操作环境则只完成推演栏。

检查点：实际输出与事前预期分开，拒绝或取消也有明确结果。

### 跟做 3：读回产物

不要只看最后一句回复。打开实际文件，或重新读取目标状态，记录与要求对应的行、字段或画面。临时目录退出后可能被清理，需要留存时按教练提示保留。

检查点：作品路径可找到；模型陈述与文件内容能相互核对。

### 跟做 4：独立再做一遍

只替换题目指定条件，保留原结果。用自己的话解释哪些步骤保持、哪些步骤改变。请同学从记录中复做，不替对方补隐含步骤。

检查点：变式有独立结果；接手者不用猜目录或输入。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 能区分终端、Shell、CLI 与文件对象
- 操作前有明确预期，操作后有实际读回
- 取消、拒绝或临时目录清理的后果解释正确
- 变式保留原条件并指出变化
- 小作品可打开，记录足以供另一人复做

### 开发者复盘

把入口、工作目录和产物路径显式传入测试。练习取消发生在修改前与修改后两种情况；断言未批准变更未落盘、已完成产物可读回。不要用“收到成功字符串”代替文件断言。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 输入：“做课程报名页，先给3个版式的可浏览草稿；暂不发布。受众是零基础学员，主动作是报名。”

   应看到：三案在信息层级或布局上有实质区别，不只是换颜色。

2. 查看每案的适用人群、优缺点和文件路径；需要时按第30课开启本地预览。

   应看到：能打开实际产物；一张概念图不能当可运行网页。

3. 选择一案并给具体反馈：“保留B的导航，报名区改为A，去掉自动播放。”

   应看到：反馈明确可执行；选择方案不表示同意部署、付款或发送。

4. 最后核查手机宽度、链接与表单行为，要求标出尚未接后端的按钮。

   应看到：演示与真实服务分开；没有后端不能写“报名成功已入库”。

5. 为三案分别写首屏内容和报名入口位置

   应看到：三案可按信息到达速度比较，不能仅说“高级”

   为什么：共同目标让视觉差异有评价尺度

6. 改变条件：目标改为招募演讲者

   应看到：人物经历与征集条件权重上升，需要重新评选

   为什么：有效结果包括选项、取舍、选择依据与受影响的验收项。不能只留下一个字母。若信息不足，写出能改变决定的那项信息，而不是连续追问与结果无关的偏好。

## 故障恢复

- **反复问同一问题**：补上目标与限制，要求沿已选方案继续；重要写操作仍要最终确认。

- **无头脚本一直等选择**：在任务中写明低风险默认取舍；必要授权缺失应退出或等待，不能伪造用户同意。

## 开发者教学

把选择题结果作为任务输入，不当作操作授权。
给无头任务设置可接受默认值，并独立测试审批缺失分支。
预览交件记录URL、文件、启动/停止方式和未连接服务；评价图示不能替代可运行文件。

开发者加餐
问题的 id、选项值和展示文案应分离。无交互终端返回 unanswered，而非默认选第一项。选择事件应保留所属任务；已排队文字不能替当前审批作答。
