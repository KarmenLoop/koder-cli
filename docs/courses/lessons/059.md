# 059 · 让回复落实：从建议到文件、测试与交付

## 学习目标

完成「让回复落实：从建议到文件、测试与交付」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

用户要一个网站或文稿时，只有方法建议常常不够。完成需要可打开的产物、验证方式和限制说明。编程应给具体文件与运行命令，撰写应给正文文件和事实来源。最终汇报要短而具体，不能用“已全面优化”掩盖未完成事项。

专题补充
交付需要主文件、可打开入口和与要求相符的内容。文件存在、格式有效、业务正确、真实上线是逐层递进的证据。最终回复应帮助用户立即使用产物，同时准确标明未验证部分；“已生成”不能代替实际读回。

先指定一个主产物，再安排阶段性保存。完成后用独立读取检查路径、内容和关键要求；代码跑对应检查，文稿核正文与来源，页面实际打开。最后写短说明指向真实文件与验证结果。

## 准备

先完成第58课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

```text
最终交件：产物路径 / 做了什么 / 实际检查与退出码 / 尚未验证 / 下一步

补充案例：区分聊天承诺与实际产物
回答说已生成report.md；文件清单无该文件
```

每项都能被使用者独立核对，不把计划列成完成。

### 跟做 1：把要求落到产物

从本课输入提取对象、读者或使用者、需要完成的动作。写出最终文件或可观察状态，再列出三条可以核对的成功标准。

检查点：“好看”“专业”被补成可检查的结构、内容或交互要求。

### 跟做 2：分开事实与默认值

给每条事实标来源；未知事项判断是否会改变结果。低影响默认值可明确写出，高影响的发送对象、价格或权限不能靠猜。

检查点：任务卡能告诉执行者哪些可以先做、哪些需确认。

### 跟做 3：安排依赖与补充

将目标拆成有输入和产物的小步骤。按本课情境记录补充是在当前任务引导、下一任务排队还是取消后改做；已完成操作不自动重放。

检查点：补充要求能落到具体步骤，前后任务身份不混淆。

### 跟做 4：用结果倒查任务卡

完成本课操作后，逐条用产物对照成功标准。变式只改指定条件，并指出原任务哪些要求仍然有效。

检查点：不会只因回复流畅就给完成；失败或缺条件有清楚的下一步。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 任务结果可观察
- 事实与假设有明确区别
- 步骤有输入输出和必要依赖
- 引导、排队或取消语义对应情境
- 结果能逐条追溯到任务要求

### 开发者复盘

为任务状态迁移写事件序列：根消息、steer、工具结果、取消、终态。检查引导不冒充新授权，排队文字不进入审批答案。模型与执行器职责分开，使用原预算和取消链。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「让回复落实：从建议到文件、测试与交付」，可与本课示例对照；无无关真实资料。

2. 明确主交付文件

   应看到：避免产物散落。

3. 要求阶段性保存

   应看到：即使中断也有可恢复内容。

4. 实际打开或运行

   应看到：区分存在、可读和可用。

5. 整理短交付说明

   应看到：给读者直接入口。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「每项都能被使用者独立核对，不把计划列成完成。」逐项对照，不把未执行项填成通过。

7. 写交付检查与缺口说明

   应看到：交付未成立，需要实际保存正文

   为什么：文字承诺没有文件系统效果

8. 改变条件：有同名旧文件

   应看到：核内容和本轮写入记录，不能借旧文件冒充

   为什么：验收需要本轮文件对应当前要求，不能拿旧文件或截图充数。检查失败保留原输出，尚未运行的范围明确列出，不用模糊“全面优化”覆盖。

## 故障恢复

- **结果与示例不一致**：文稿字数应量正文文件而非聊天结尾；代码测试不能只说“应该通过”。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

为同一个任务写一份空泛汇报和一份证据化汇报，逐项比较。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不等于，需要读取文件或检查实际产物。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

交付门应识别本轮实际写入主文件并保存证据字段；失败门不能误报API故障。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
交付闸门可捕捉缺文件和显式格式缺失，但不能证明语义完全正确。产物绑定本轮写入与读回证据，失败状态保留已有工作和恢复入口。
