# 015 · 扫描本机工程，决定下一步

单元 1 · 建议 25 分钟（含自行练习） · 0.4.15 配套教材

## 学习目标

找到正确工程再继续，控制跨工具任务资料进入模型的范围。

## 原理讲解

koder scan 会把你在 Koder、Codex、Claude Code、Cursor 里最近做过的项目和任务汇总起来。它只读工作目录、时间和标题，这一步不请求模型；选择后续模型任务时，相关项目和任务材料会进入你配置的模型请求。
列表出来以后，这样选：

专题补充
工程发现解决“在哪里工作”，不是授权扫描整个用户目录。相同项目可能有源码、发行包和旧副本；选择目标需同时核路径、文件结构和版本。导入旧任务资料时应保留来源与时间，不能把历史讨论当作现在的执行许可。

先用有限根目录列候选，再读取每个候选的README与包信息。对照任务需要的源文件和当前差异选择工作区，建立项目卡。跨工具资料只抽取与当前目标有关的部分，秘密和无关私人文本不进入模型。

## 准备

准备两个测试工程，分别放不同README。扫描可能显示本机项目标题与路径，分享屏幕前先确认。

## 手把手操作

1. 运行 koder scan --limit 6，只看列表，不选择执行。

   应看到：能看到来源与路径；列举不请求模型，选择后续任务可能发送相关资料。

2. 选测试工程A，核对实际路径后再请求总结README。

   应看到：摘要只涉及A，不自动带上B的任务事实。

3. 需要多个任务时分别打开独立目录/会话；用 koder project list --json 核查。

   应看到：每项任务有明确归属，不能在安装目录直接散写项目。

4. 继续旧任务时说清项目、已完成部分和下一目标。

   应看到：先读已有产物再工作，不把聊天标题当完整项目状态。

5. 为“修计算bug”选择目录并写理由

   应看到：选择cart-src且再核当前需求与状态

   为什么：目录名不足以判断，结构和版本提供证据

6. 改变条件：cart-src有未提交用户修改

   应看到：保留并先读差异，不能重置为整洁状态

   为什么：定位结论至少包含实际路径、项目身份、当前状态与选择理由。搜索无结果只说明本次范围没有命中；不要推断全机不存在。

## 故障恢复

- **扫描到很多旧项目**：缩小数量或直接用-w指定路径；别批量删除历史来整理。

- **项目路径已移动**：用新路径明确打开并核查文件；不要假设旧路径映射还有效。

## 开发者教学

规范工作路径是隔离键的一部分；路径别名、符号链接和并发会话需要一致处理。
测试两工程、同工程不同命名会话、旧会话恢复；不删除旧记录以掩盖串话。
交付前生成项目文件索引和运行入口，供下次恢复读回。

开发者加餐
扫描应有目录深度、文件数和内容大小边界，跳过依赖与秘密。工作区路由返回真实路径，不能在找不到工程时静默退到安装目录。
