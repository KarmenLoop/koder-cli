## 学习目标

完成「JIT Harness：按任务选配置」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

Harness Profile把记忆、规划、动作和能力编排绑定到任务。它帮助研究任务偏向证据、办公任务偏向依赖图，但不能改写身份、预算和权限。轻量选配从已审种子中选择，不让模型即时生成任意可执行代码当运行时。

专题补充
任务profile调节记忆投影、规划、能力集合和验证节奏。它帮助把注意力放在适合任务的过程上，但权限仍由原执行边界决定。显式选择、保存配置和自动匹配有不同优先级；中途切换不能重置已消耗预算。方法偏好与真实能力是否连接也必须分开。

先按任务结果选择研究、办公或默认配置，再读当前profile的工具和步骤约束。用同一合成任务检查选择原因、实际能力范围和恢复行为；明确配置只编排原执行器，不创造权限、预算或新账号。

### 跟做 1：画出能力链路

按本课情境列出 CLI、Skill、工具、MCP server 与真实目标。标明谁提供说明、谁执行、谁授权、谁保存回执。

检查点：能解释 Skill 被找到不等于工具已运行。

### 跟做 2：先查现有能力

检查本地目录和已连接工具，缺项再按既有权限查官方说明。记录来源、版本和适用平台，不直接执行教程里的任意脚本。

检查点：复用已有入口，网络、安装和桌面授权各自核对。

### 跟做 3：用最小目标验调用

先做一个有明确输入与输出的合成任务。MCP 分别检查握手、工具列表、调用和结果；子 Agent 分别检查任务归属、结果和取消。

检查点：工具声明、调用成功和真实外部效果不会混成一个状态。

### 跟做 4：变更后重验边界

按本课变式修改环境、权限或能力选择，检查拒绝与恢复路径。经验候选只记录实际证据，不把一次自评直接变成默认规则。

检查点：原 Core 的权限、预算与取消继续生效。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「JIT Harness：按任务选配置」，可与本课示例对照；无无关真实资料。

2. 读当前profile说明

   应看到：知道配置影响什么。

3. 选择研究与办公两种任务

   应看到：比较工具需求。

4. 查看实际选配诊断

   应看到：不是只看声明。

5. 检查失败恢复次数

   应看到：有界且不伪造成功。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「profile可序列化与比较，默认关闭时保留原执行行为。」逐项对照，不把未执行项填成通过。

7. 列每项所需产物与工具，再配候选profile

   应看到：R研究、O办公、C按编程任务用默认或已支持配置

   为什么：按实际动作匹配比按关键词匹配更可靠

8. 改变条件：R新增保存总结文件

   应看到：研究配置写入限制需核，不能仍假设只读配置满足全部任务

   为什么：R适合研究，O需办公能力；研究profile不能因邮件请求自行放开发送。切换后stepsUsed与repairsUsed应保留，具体生效点以当前文档定义的工具批次边界核对。

## 故障恢复

- **结果与示例不一致**：缩窄工具列表不等于撤销权限；权限仍由Core最终检查。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。
