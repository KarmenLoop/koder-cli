# 021 · Gamma、应用连接与 MCP

单元 2 · 建议 60 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-21) · [总纲](../README.zh.md)

## 学习目标

把工具接入真正用于交付：MCP能调用，邮箱能经确认发送，GitHub能受控上传与编辑。

## 原理讲解

应用与 MCP：连接会使用所选服务的 API Key 或浏览器授权；第三方能接收你通过该连接提交的数据，费用和服务条款由该服务决定。同一连接配置可由当前配置范围内的对话与 Agent 复用，外部写入仍走工具批准。stdio MCP 会在本机启动配置的程序；导入默认关闭，启用或 test 会启动连接。可用 koder apps disconnect &lt;id&gt;、koder mcp disable &lt;id&gt; 停用；在服务方撤销授权后才能终止其持有的令牌。
断线先看连接诊断，区分令牌失效、服务限流、网络和模型工具调用失败。连接可被同一配置下的对话和 Agent 复用；这不表示凭据已跨设备同步。超长工具结果会有限读取或截取，不能把连接成功当成外部任务已经完成。

专题补充
连接应用通常经过发现工具、建立账号身份、确认操作范围和调用结果四层。MCP提供工具接口，但工具名字不保证参数、权限或业务效果。生成演示、保存草稿和发送邮件属于不同动作。本课使用合成工具schema与回执，不连接真实账号或修改远端资料。

先读工具名称、描述、输入字段与输出结构，再把任务映射到最小动作序列。对于外部写入先形成可审阅内容，明确目标和版本；用离线回执练习失败与未知结果的处理。

## 准备

只选自己已授权的测试账号、测试收件人和私有测试仓库。密钥放专用输入框。无需为读教程绑定任何账号；外部步骤全部由你选择执行。

### 跟做 1：列清配置层次

把本课给定字段放入“功能、配置位置、是否已保存、凭据引用名、授权范围”五列。未知字段写未知；密钥只写变量或凭据条目名称。

检查点：能区分配置存在、接口可达、功能可用与授权允许。

### 跟做 2：选择最小检查

先运行本课的只读状态命令或分析给定状态，再选择一个无外部写入的检查。不要为了证明保存成功而发送邮件或公开仓库。

检查点：每个判断对应一个状态字段或检查输出，不用一条文本回复证明全部工具能力。

### 跟做 3：沿失败层排查

按入口→配置→凭据→协议→权限→操作的顺序定位第一处失败。只改变有证据指向的字段，记录变更前后值；秘密值始终省略。

检查点：修复与具体失败关联，没有同时重置一整套设置。

### 跟做 4：验证恢复与撤销

在自己的练习配置中恢复原字段或关闭可选功能。检查原项目和记录仍在；没有实际执行恢复时写出待验步骤。

检查点：知道如何回退，功能开关不被误当作删除历史。

## 手把手操作

1. 运行 koder apps status、koder mcp list，核对服务名和enabled状态；查看 koder help mcp。

   应看到：列出工具只是发现，未配置或未启用时不得声称可以调用。

2. 检查MCP配置里的程序路径、参数、服务器地址和环境变量名；再对一个已授权服务运行 koder mcp test &lt;服务ID&gt;。

   应看到：测试建立真实连接；保留服务端报错与返回工具，不把测试当业务完成。

3. 163邮箱在 /setup 绑定：输入完整邮箱地址与客户端授权码，选择收发模式；之后查看 /mail status。

   应看到：收信与SMTP各有配置。授权码只在专用隐藏输入中使用；仅收信账号不能发送。

4. 用自己的测试收件地址替换占位符，运行 koder mail send --to "YOUR_TEST_ADDRESS" --subject "Koder test" --text "This is my authorized test."；核对后输入send。

   应看到：只发送自己确认的内容。保留SMTP提交回执，再去测试收件箱核对；结果未知先查账，不连发。

5. 运行 koder github connect，在隐藏输入里绑定令牌；运行status、repos和read查看自己的测试仓库README。

   应看到：确认账号与仓库范围；读取成功不表示拥有写权限。令牌不进入项目文件。

6. 在测试项目准备README.md，用 koder github commit OWNER/REPO README.md --message "Improve learning notes"；再用read读回，另用edit修改仓库描述。

   应看到：每次写入核对目标并输入对应确认词；回执含提交SHA或操作状态。只提交列出文件，不上传整目录。

7. 选择搜索与读取，列出不需要的动作

   应看到：无需send_mail，最终可以本地总结

   为什么：可用工具不等于每个都应调用

8. 改变条件：用户明确要求发送总结给自己

   应看到：先准备总结与准确收件目标，再按授权执行

   为什么：交付应包含能力矩阵、参数实例、结果解释和可打开的产物入口。连接成功不能替代任务结果；页面标题不能替代实际文件内容。

## 故障恢复

- **发信却一直查skill_catalog或shell**：指定使用已绑定邮箱的原生mail_send或/mail send；不要在shell里套第二个Koder。

- **GITHUB_PENDING_REVIEW_REQUIRED**：运行 koder github reconcile OWNER/REPO；未能证明结果时保留待核对，不强推、不重复提交。

## 开发者教学

所有外部写入沿原授权、幂等与UNKNOWN对账规则；--yes不代替最终邮件/GitHub确认。
大结果保留artifactId、SHA、bytes与读取方式，不能截断后丢失证据入口。
GitHub验收覆盖仓库大小写身份、分支变动、拒绝、超时和重试；文件/分支大小写不可随意归一化。
凭据存储不可用要明确失败；不要静默写明文或把令牌插进模型请求。

开发者加餐
工具schema是接口契约而非用户授权。连接器应保护身份与目标映射，写操作需稳定请求标识和收据；未知结果先查询状态，不自动重复创建文档或发送。
