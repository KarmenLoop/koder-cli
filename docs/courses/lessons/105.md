# 105 · 单元项目：可验证的待办服务

单元 7 · 建议 90 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-105) · [总纲](../README.zh.md)

## 学习目标

完成「单元项目：可验证的待办服务」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

完成一个小而完整的待办服务：接口契约、输入验证、身份边界、数据存储、测试和启动说明。允许先用本地合成身份演练，但必须明确与生产鉴权的差别。最终交付应能让别人启动并验证A不能访问B的数据，不只展示成功请求。

专题补充
综合待办服务要把接口、输入、身份、存储与错误处理装配成可验证的系统。允许使用合成身份和内存存储学习业务，但必须清楚说明与真实鉴权、持久化和部署的差距。

按创建、读取、更新、删除建立最小契约，再加入对象权限、失败与分页。为每条业务规则安排测试与文档位置，让交接者可以从入口重做。

## 准备

先完成第104课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

### 跟做 1：写出数据与调用者

从题目列实体、字段、约束和调用身份。区分公开数据与用户私有数据；先用合成样本推演，再选择本课要求的内存、数据库或 HTTP 层。

检查点：每次读写都能说明对象属于谁，以及由谁允许。

### 跟做 2：固定一次操作的契约

列前置状态、请求、成功返回、失败返回和持久化位置。对于缓存、事务或幂等，写出键包含的维度和有效期。

检查点：同一 URL 不被默认当成同一用户数据；重复写不靠缓存冒充幂等。

### 跟做 3：跑正例再跑拒绝例

实现或分析本课操作，检查本人合法请求，再构造他人、坏输入、重复请求中的适用项。记录状态和数据是否变化。

检查点：拒绝不仅有错误消息，还应没有越权写入或泄露。

### 跟做 4：验证变式与恢复

改变题目指定条件后重做。对未知写入先查询结果；对迁移说明前后结构及恢复约束。当前仅为内存例子时如实标注。

检查点：能区分逻辑通过、HTTP 可用、持久化有效和生产可用。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 数据归属与约束清楚
- 输入输出及失败语义一致
- 合法请求和拒绝路径均检查
- 变式覆盖身份、键或事务的关键维度
- 持久化与恢复声明符合实际层次

### 开发者复盘

设计失败用例检查外部数据未改变；事务测试覆盖中间失败和回滚。幂等冲突返回明确错误，缓存命中不能跳过对象授权。内存域、HTTP、数据库各自独立验收。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「单元项目：可验证的待办服务」，可与本课示例对照；无无关真实资料。

2. 按契约实现最小功能

   应看到：先创建和读取。

3. 补授权与数据约束

   应看到：拒绝跨用户访问。

4. 跑失败与恢复测试

   应看到：保存真实结果。

5. 整理启动和回退说明

   应看到：环境缺失有明确提示。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「正常路径、非法输入和越权反例都可运行。」逐项对照，不把未执行项填成通过。

7. 写请求响应样例及错误码

   应看到：每动作输入输出可独立核查

   为什么：先定契约减少前后端互猜

8. 改变条件：新增截止日期

   应看到：补类型、时区和缺失规则，不能只加数据库列

   为什么：检查正常路径、越权、非法输入、重复操作与重启数据。仅显示成功JSON不够，拒绝后必须确认没有副作用，所有报告都绑定相同版本。

## 故障恢复

- **结果与示例不一致**：不要为了“一键起”跳过鉴权或把测试秘密当生产配置。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

编程能力评价绑定同题、模型和环境；没有真实盲测不宣称评分提升。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
