# 005 · 命令确认：跑测试，也拦下可疑命令

单元 1 · 建议 25 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-5) · [总纲](../README.zh.md)

## 学习目标

区分普通检查、敏感操作和系统权限；会拒绝危险命令，也会处理长任务。

## 原理讲解

改完代码当然要跑测试。运行项目代码属于敏感操作，默认先询问；node --version 这类低风险检查会自动执行。
命令的输出会原样交回给模型，它看得到测试结果，再决定下一步。

专题补充
命令文本包含程序、参数和 Shell 运算符。程序名看似熟悉不表示所有参数都安全；检查、生成文件、安装依赖和对外发布的影响不同。判断一条命令需要看执行目录、输入来源、写入位置、网络范围以及失败时能留下什么。允许某次命令也不等于永久改变系统权限。

先把命令拆成参数列表与 Shell 结构，再预测读、写、网络和进程四类作用。用课程给定的合成命令做桌面推演；需要实际执行时仅采用独立练习目录中的 Node 小程序。记录退出码和输出，不把命令回显当作执行结果。

## 准备

只使用一次性练习目录。阅读命令时同时看工作路径、目标地址、输入输出文件，不能只看命令开头。

## 手把手操作

1. 让Koder运行项目测试，阅读“准备运行命令”下的完整命令。

   应看到：知道要执行什么、在哪里执行、是否会写入或访问网络。

2. 批准本次测试；遇到下载后直接执行的陌生脚本时拒绝。

   应看到：拒绝不是任务失败；原文件与授权范围保持不变。

3. 在 Setup 查看审批策略；运行 koder permissions status 看电脑授权。

   应看到：full审批和系统权限是两层；--yes不会代开电脑、发信或GitHub写入确认。

4. 长任务先确认合理等待时限；超时后核对进程、日志和产物，再决定继续或取消。

   应看到：超时不是已回滚；后台 started 也不等于安装完成。

5. 标出可执行文件、两个参数和工作目录，再写预期读写范围

   应看到：程序node，参数--test和测试路径；测试是否写文件取决于测试内容

   为什么：命令名称不能证明只读，需要读被执行脚本才能判断副作用

6. 改变条件：脚本加入writeFileSync('out.json')

   应看到：影响表增加对/lab/cart/out.json的写入

   为什么：验收使用两个问题：它是否完成本次检查；它是否做了不属于本次检查的事。成功输出必须有对应退出码，长任务还要有终端状态和产物。不要为了得到绿色结果而扩大删除范围、安装范围或忽略错误。

## 故障恢复

- **EXECUTION_PERMISSIONS_INVALID**：先看Koder权限与工作区状态；不是见到PowerShell就全局放开执行策略。

- **确认窗口无法输入**：保留版本和终端类型；取消本次操作，使用交互终端重试，不通过聊天文本绕过批准。

## 开发者教学

用本地合成文件验证 allow/deny/cancel 三条路径。拒绝和取消不得执行未批准的写入。
区分工具超时、任务预算和服务商诊断超时；不能统一无限延长。
结果未知按UNKNOWN保留，重试前对账；shell输出文字不能自行升级为外部成功回执。

开发者加餐
命令审批应显示实际 Shell、cwd、完整参数与敏感目标。复用现有取消和进程所有权；持续时间配置应明确单位与上限。stdout、stderr 和退出状态需要分别保存，未知状态保留未知而非转换成成功。
