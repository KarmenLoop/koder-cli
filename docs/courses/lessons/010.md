# 010 · 修到测试通过：fix --check

单元 1 · 建议 40 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-10) · [总纲](../README.zh.md)

## 学习目标

用可重复失败的检查驱动修复，保留失败证据，避免只改测试让它变绿。

## 原理讲解

fix 是一个循环：先跑检查命令，失败就把输出交给 Koder 修，修完再跑，直到通过或者次数用完（默认 3 次）。

专题补充
修复的起点是可重复失败，终点是同一要求下的独立复测。先区分环境、测试和业务错误，再只改能解释失败的最小实现。循环次数增加不会自动提高质量；检查命令、输入和预期都应稳定，避免修改期望值或减少覆盖制造成功。

准备一份小购物车代码与独立断言，记录改前结果。手算正确答案后修改实现，再运行原例与边界例。每次循环都写一个可被检查推翻的假设，失败时保留输出；本课本地Node练习不必调用模型。

## 准备

将cart-lab复制到独立项目；需要可用Node运行示例。没有Node时先学内置教练，不必为了读教程装依赖。

### 跟做 1：定位操作入口

先分清屏幕上的系统终端和 Koder 提示符。系统命令在终端运行；以 / 开头的会话命令放在 Koder 对话中。把本课出现的目录逐个写入 environment.md，并标注“当前目录”“临时练习”“正式作品”。

检查点：能指着一条命令说明由谁解释、在哪个目录发生；不同目录不被画成同一个对象。

### 跟做 2：先预测再操作

将本课输入逐项编号。执行前先写一句预期，再按本课任务操作一次。需要点击或审批时，记录选项名称与选择理由；无操作环境则只完成推演栏。

检查点：实际输出与事前预期分开，拒绝或取消也有明确结果。

### 跟做 3：读回产物

不要只看最后一句回复。打开实际文件，或重新读取目标状态，记录与要求对应的行、字段或画面。临时目录退出后可能被清理，需要留存时按教练提示保留。

检查点：作品路径可找到；模型陈述与文件内容能相互核对。

### 跟做 4：独立再做一遍

只替换题目指定条件，保留原结果。用自己的话解释哪些步骤保持、哪些步骤改变。请同学从记录中复做，不替对方补隐含步骤。

检查点：变式有独立结果；接手者不用猜目录或输入。

## 手把手操作

1. 先运行 node --test，记录失败用例和实际/期望值。

   应看到：这是基线，不删除失败日志；测试应确实触发总价bug。

2. 运行 koder fix "修复总价计算，不删除现有测试" --check "node --test"。

   应看到：先看到检查与修复循环；每次修改范围可审阅。

3. 检查实现是否按单价×数量计算；补空数组、0数量与多商品案例。

   应看到：测试覆盖需求，不是硬编码某个750结果。

4. 独立再跑一次检查，打开README确认使用说明可执行。

   应看到：结束条件是实际检查通过；达到预算仍失败应列出卡点和已有产物。

5. 写node:assert断言总额36，记录改前实际12

   应看到：断言失败且退出非零

   为什么：先观察失败才能证明测试有区分力

6. 改变条件：输入改qty1

   应看到：测试通过但无法暴露本题bug，需恢复qty3

   为什么：修复包包含复现输入、根因、最小差异、原失败变绿及相关回归。实际未运行的检查不能写通过。预算用完时保留当前文件和下一项最有信息量的检查，不继续盲改。

## 故障恢复

- **fix没有说明缺什么**：补明确任务和--check命令；先单独运行检查确认工具存在。

- **依赖安装失败却一直改代码**：区分环境故障与业务失败；不改测试掩盖缺依赖。

## 开发者教学

性能题先固定输入与测量条件；重构题先固定行为，不能用更换测试输入刷结果。
对长任务阶段性保存可运行文件、测试与下一步，避免超时只剩聊天。
修复次数与耗时记录真实值；没有全量回归不能称全工程全绿。

开发者加餐
fix --check需要明确任务和检查命令；使用前先独立确认检查可运行。测试程序应在断言失败时返回非零。把测试的业务oracle与实现分开，避免两者共享同一错误公式。
