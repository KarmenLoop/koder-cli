# 010 · 修到测试通过：fix --check

单元1 · 建议40分钟（含自行练习） · 0.4.13版课堂

[课堂](../index.zh.html#lesson-10) · [总纲](../README.zh.md)

## 学习目标

用可重复失败的检查驱动修复，保留失败证据，避免只改测试让它变绿。

## 原理讲解

fix 是一个循环：先跑检查命令，失败就把输出交给 Koder 修，修完再跑，直到通过或者次数用完（默认 3 次）。

## 准备

将cart-lab复制到独立项目；需要可用Node运行示例。没有Node时先学内置教练，不必为了读教程装依赖。

## 手把手操作

1. 先运行 node --test，记录失败用例和实际/期望值。

   应看到：这是基线，不删除失败日志；测试应确实触发总价bug。

2. 运行 koder fix "修复总价计算，不删除现有测试" --check "node --test"。

   应看到：先看到检查与修复循环；每次修改范围可审阅。

3. 检查实现是否按单价×数量计算；补空数组、0数量与多商品案例。

   应看到：测试覆盖需求，不是硬编码某个750结果。

4. 独立再跑一次检查，打开README确认使用说明可执行。

   应看到：结束条件是实际检查通过；达到预算仍失败应列出卡点和已有产物。

## 故障恢复

- **fix没有说明缺什么**：补明确任务和--check命令；先单独运行检查确认工具存在。
- **依赖安装失败却一直改代码**：区分环境故障与业务失败；不改测试掩盖缺依赖。

## 开发者教学

性能题先固定输入与测量条件；重构题先固定行为，不能用更换测试输入刷结果。
对长任务阶段性保存可运行文件、测试与下一步，避免超时只剩聊天。
修复次数与耗时记录真实值；没有全量回归不能称全工程全绿。
