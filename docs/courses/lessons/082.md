# 082 · 表单：输入、校验与错误提示

单元 6 · 建议 30 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-82) · [总纲](../README.zh.md)

## 学习目标

完成「表单：输入、校验与错误提示」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

表单应告诉用户填什么、为什么失败、怎样修正。必填标识和格式提示尽量提前给出，提交失败后保留已填内容。前端校验提升体验，后端校验保护数据，两者都需要。没有接后端的演示页必须标明只演示，不能显示真的报名成功。

专题补充
表单把用户意图转成结构化输入。好的校验告诉用户哪一项错、如何修，并保留其他已填内容。前端校验帮助体验，服务端仍需独立验证。课堂报名表只有合成数据，不发出真实报名请求。

先定义字段、必填条件、规范化和错误结构，再实现输入与提交状态。校验时避免每按一个键就责备用户；提交失败应定位问题并保留输入。

## 准备

先完成第81课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 示例与解读

```text
字段：姓名、邮箱
错误：邮箱格式不完整，请补齐@example.com部分
演示状态：仅本地校验，尚未提交服务器

补充案例：定义称呼规范化
输入"  小林  "，要求去首尾空白后1–30字符

可复制的离线 Node 样例（仅计算合成数据或内存时序）：
(async()=>{const normalize=s=>s.trim();const input=["  小林  ","   "];return input.map(s=>{const value=normalize(s);return value?{ok:true,value}:{ok:false,code:"NAME_REQUIRED"};});})().then(value=>console.log(JSON.stringify(value)));
```

错误贴近字段，状态明确，不伪造远程提交。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「表单：输入、校验与错误提示」，可与本课示例对照；无无关真实资料。

2. 为字段加label

   应看到：点击标签可聚焦输入。

3. 定义必填与格式规则

   应看到：规则可解释。

4. 提交空表与错误邮箱

   应看到：显示具体错误。

5. 修正后再提交

   应看到：保留其他输入并更新状态。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「错误贴近字段，状态明确，不伪造远程提交。」逐项对照，不把未执行项填成通过。

7. 先trim再计算长度并保存规范值 将上述完整程序保存为自有目录的 case.mjs，运行 node case.mjs；先独立预测输出，再与固定输出对照。

   应看到：值为"小林"
   Node 固定输出：&#91;{"ok":true,"value":"小林"},{"ok":false,"code":"NAME_REQUIRED"}&#93;

   为什么：展示空格不应绕过必填判断

8. 改变条件：输入全空格

   应看到：返回NAME_REQUIRED，不能存空字符串

   为什么：检查空白、格式、重复提交、服务器拒绝和回执丢失。成功提示必须匹配实际结果；仅本地验证通过应明确写为演示通过。

## 故障恢复

- **结果与示例不一致**：不要把正则当完整邮箱有效性证明；格式可接受也不代表邮箱存在。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

交表单正常、空值、错误格式和网络失败四种状态。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不是，还需要真实提交结果。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

服务端再次验证；避免把用户输入直接拼进HTML或查询。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
客户端与服务端共享规则定义时也要保留各自信任边界。字段错误以稳定键映射控件，服务端错误不应直接当HTML插入；提交身份与幂等处理分开。
