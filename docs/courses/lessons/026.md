# 026 · 找得到人：反馈不是把密钥打包寄来

单元 2 · 建议 25 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-26) · [总纲](../README.zh.md)

## 学习目标

提交可复现、无秘密的反馈，并把撰写任务变成有来源的实际文稿。

## 原理讲解

对话里明确说“我要反馈”或“怎么联系官方”，Koder 会给你邮箱和空白模板。它不会自动发送，也不会把聊天历史、API Key 或私人路径塞进附件。

专题补充
反馈的目标是让他人理解并重现问题，而不是把所有日志打包。清楚的报告提供环境、最小步骤、预期、实际和影响；没有证据的猜测单独标注。写作也需要实际正文和来源，不能只给一个写作计划。反馈命令提供联系信息和模板，阅读模板不会发送邮件。

从一份混乱描述中抽取可观察事实，缩减到最短复现输入。使用合成数据重现关键特征，删除秘密与无关历史。将结论写成可直接审阅的文稿，最后逐项验证读者是否能按步骤得到同一结果。

## 准备

准备实际错误输出与最短复现；写作练习只提供已核实事实，不暗示不存在的更新。

### 跟做 1：列清配置层次

把本课给定字段放入“功能、配置位置、是否已保存、凭据引用名、授权范围”五列。未知字段写未知；密钥只写变量或凭据条目名称。

检查点：能区分配置存在、接口可达、功能可用与授权允许。

### 跟做 2：选择最小检查

先运行本课的只读状态命令或分析给定状态，再选择一个无外部写入的检查。不要为了证明保存成功而发送邮件或公开仓库。

检查点：每个判断对应一个状态字段或检查输出，不用一条文本回复证明全部工具能力。

### 跟做 3：沿失败层排查

按入口→配置→凭据→协议→权限→操作的顺序定位第一处失败。只改变有证据指向的字段，记录变更前后值；秘密值始终省略。

检查点：修复与具体失败关联，没有同时重置一整套设置。

### 跟做 4：验证恢复与撤销

在自己的练习配置中恢复原字段或关闭可选功能。检查原项目和记录仍在；没有实际执行恢复时写出待验步骤。

检查点：知道如何回退，功能开关不被误当作删除历史。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 配置地图字段完整且脱敏
- 保存与可调用证据分别列出
- 错误定位到具体层而非泛称断网
- 变式说明配置或权限如何变化
- 有保留原数据的恢复方法

### 开发者复盘

用注入的配置和凭据引用测试路径，不读取学员真实 Key。给保存成功但调用失败、授权撤销、旧配置缺新字段各写一个用例。配置迁移应保留旧值，能力状态不能由 UI 默认值推断。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 运行 koder feedback，阅读邮箱与空白模板。

   应看到：只显示联系方式和模板，不自动发送聊天或附件。

2. 填写版本、系统/终端、操作步骤、预期、实际和最后几行脱敏错误。

   应看到：别人能按步骤复现；不要只写“不能用”。

3. 需要Koder写反馈邮件时，明确受众、已核实事实、文件名和字数，要求保存为feedback.md。

   应看到：实际文件可读；未知原因写待排查，不编根因。

4. 若要发送，按第21课检查最终内容与收件人后独立确认。

   应看到：撰写交付与发送是两步；可只保留草稿。

5. 写环境、步骤、预期、实际四段

   应看到：问题定位到启动入口未被找到

   为什么：“打不开”可能覆盖多个层，具体文本缩小范围

6. 改变条件：提示改为401

   应看到：转为已启动后的鉴权失败，复现步骤相应改变

   为什么：验收要求问题可定位、信息不泄密、正文可阅读。联系地址应从随包入口核实；草稿与已发送分别记状态，不因反馈模板存在就声称已联系维护者。

## 故障恢复

- **文稿只有空泛口号**：补受众、具体事实、风险和下一步；要求主文件落盘读回。

- **更新邮件乱说本版新增**：先读对应release/CHANGELOG/验收材料；无材料明确非本版增量。
