## 原理讲解

机器消费的结果需要明确schema、状态和错误语义。空数组可能表示没有问题，也可能是解析失败后的默认值，这两种不能混在一起。消费者应检查解析标志与退出码，生产者则在无法解析时明确失败，不把不完整结果当正常成功。

专题补充
结构化JSON要同时通过语法、schema和业务状态检查。空findings可能表示没有发现，也可能是解析失败后的默认容器。消费者必须看parsed、错误码与进程退出状态，不能从空数组直接推出通过。

先定义成功与失败形状，按语法解析、字段验证、语义校验和最终判定顺序处理。用完整、截断、类型错和状态矛盾样本验证消费者。

## 示例与解读

```text
{"parsed":false,"code":"REVIEW_UNPARSED","findings":[]}

补充案例：拒绝空数组假绿
{parsed:false,code:"REVIEW_UNPARSED",findings:[]}，exit3

可复制的离线 Node 样例（仅计算合成数据或内存时序）：
(async()=>{const samples=[{parsed:false,code:"REVIEW_UNPARSED",findings:[],exit:3},{parsed:true,findings:[],exit:0}];return samples.map(x=>x.parsed===true&&x.exit===0&&Array.isArray(x.findings)&&x.code!=="REVIEW_UNPARSED");})().then(value=>console.log(JSON.stringify(value)));
```

findings为空不能覆盖parsed=false。
