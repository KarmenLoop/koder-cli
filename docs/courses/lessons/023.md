## 学习目标

辨认套餐与按量API，避免选错地区、地址和计费产品。

## 原理讲解

先看门口的牌子：小米 Token Plan、Kimi、DeepSeek、阿里云 Token Plan 和火山接口目前存在已知 Bug，暂时无法使用，菜单已标灰。配置可以留着，但不会发出请求，也不会切到备用引擎。
套餐密钥不是万能门卡。阿里云 Token Plan、Coding Plan 和按量付费是独立通道；火山 Coding Plan 也有单独的地址。Koder 把它们分开列出，不会偷偷换到另一条计费路线。

专题补充
套餐、按量API、国内与国际地区可能使用不同凭据和地址。相似服务商名称不能证明这些路线互通。当前文档中的held或暂不可用状态必须优先于旧配置示例；课程不以历史命令重新激活禁用入口。这里用虚构域名练习配对与计费边界。

建立产品、地区、凭据类别、协议四列表，再逐项匹配。核对文档日期与当前可用状态，保留历史条目但标用途。任何路线变化都要说明会否改变账号或计费产品，不自动备用切换。

## 准备

只准备不含密钥的控制台产品信息。当前停用入口不做真实连接练习。

### 跟做 1：列清配置层次

把本课给定字段放入“功能、配置位置、是否已保存、凭据引用名、授权范围”五列。未知字段写未知；密钥只写变量或凭据条目名称。

检查点：能区分配置存在、接口可达、功能可用与授权允许。

### 跟做 2：选择最小检查

先运行本课的只读状态命令或分析给定状态，再选择一个无外部写入的检查。不要为了证明保存成功而发送邮件或公开仓库。

检查点：每个判断对应一个状态字段或检查输出，不用一条文本回复证明全部工具能力。

### 跟做 3：沿失败层排查

按入口→配置→凭据→协议→权限→操作的顺序定位第一处失败。只改变有证据指向的字段，记录变更前后值；秘密值始终省略。

检查点：修复与具体失败关联，没有同时重置一整套设置。

### 跟做 4：验证恢复与撤销

在自己的练习配置中恢复原字段或关闭可选功能。检查原项目和记录仍在；没有实际执行恢复时写出待验步骤。

检查点：知道如何回退，功能开关不被误当作删除历史。

## 手把手操作

1. 运行 koder model presets，找出标灰条目及说明。

   应看到：以当前安装版可用性为准，不按宣传数量推断都可连。

2. 对照自己购买的是Token Plan、Coding Plan还是按量API，并写下国内/国际地区。

   应看到：套餐名称相近也不能混用密钥。

3. 用本课原有models命令查看对应入口；到服务商控制台核对模型ID与Base URL。

   应看到：缓存或发现列表只提供候选；权限取决于账号。

4. 入口可用且产品一致时才按第3课诊断；不可用就保留配置并选已授权替代。

   应看到：不静默改变计费路线、不绕过停用标记。

5. 填四格匹配矩阵

   应看到：只P/P与M/M为已知匹配，交叉项需拒绝或核实

   为什么：服务商相同不代表凭据通用

6. 改变条件：两者模型名都叫demo-coder

   应看到：模型同名不改变产品配对规则

   为什么：验收是路线一致性与状态解释，不是真实套餐可用性。未知额度、价格与模型权限保持未知；不能从Key前缀推导全部权利。

## 故障恢复

- **控制台有余额却401**：余额与权限是不同条件，查密钥所属产品与地区。

- **models列表为空**：先区分发现接口失败、未授权与产品无可用型号，别随机猜模型名。
