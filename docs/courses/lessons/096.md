完成「SQLite建模：表、键与约束」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

数据模型应表达业务不变量。主键标识记录，外键连接归属，非空和唯一约束帮助防止坏数据。应用层检查不能完全代替数据库约束，因为并发请求可能同时通过检查。设计前先写查询场景，再决定字段与索引。

专题补充
待办模型用主键标识记录，用owner_id关联用户，并以约束表达不变量。应用层先检查有助于提示，数据库约束帮助抵御并发与绕过入口。SQL示例用于自有合成数据库；不安装数据库工具，也不接触用户真实数据。

从查询场景写表结构，再标非空、唯一、外键和检查约束。用两三条合成记录验证约束；SQLite外键检查需要在连接层明确启用并核实。

## 示例与解读

```text
todos(id, owner_id, title, done, created_at)
约束示例：title非空；done只允许0或1；owner_id关联用户

补充案例：定义待办主键
todos(id TEXT PRIMARY KEY,owner_id TEXT,title TEXT,done INTEGER)
```

这是教学模型；迁移前应在独立测试库验证。
