# 030 · 基础训练结课与项目初稿

单元 2 · 建议 90 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-30) · [总纲](../README.zh.md)

## 学习目标

完成可运行、可预览、可核对的项目交付，并交一份有来源的产品文稿。

## 原理讲解

基础训练完成！先收好速查表，后面还有150课专题课堂与毕业项目：
下一步：先用 koder setup 配好模型，然后在你自己的项目里输入 koder。

专题补充
结课作品需要可打开的文件、可复做检查和明确使用说明。页面、文稿与交付记录可以组成一个小项目，但每项都应有独立验收。先完成本地最小主路径，再考虑发布；教程临时练习场和正式作品目录不能混用。

用社区读书会报名介绍页作贯穿案例，先固定日期、地点、容量和报名方式。创建独立目录，保存页面与事实表，再按内容、链接、布局和文件可搬迁性检查。所有账号与上线动作放在本地内容验收之后。

## 准备

从网站、应用或PPT中选一个真实小需求，放在独立Koder Projects目录。使用合成数据，外部部署和GitHub上传单独确认。

## 手把手操作

1. 写任务卡：受众、目标、必需内容、不做的范围、产物路径、验证方式。网站先做3个可浏览版式。

   应看到：要求能对应实际文件与行为；选定方案后再细化。

2. 要求实现并补检查；静态站点在当前聊天用 /preview start --directory site，确认目录正确。

   应看到：浏览器能看到本地产物；框架工程先按项目README启动开发服务器，再用已有preview URL入口。

3. 改一处标题，查看预览是否更新；检查手机宽度、键盘操作、链接与空数据。

   应看到：刷新或重载反映实际改动；不能只交一张截图。

4. 要求生成项目结构图H5：目录、入口、模块、数据流、运行/测试方式和未接通服务；确认图中节点来自项目。

   应看到：结构图可在浏览器打开，路径可追溯，不把示例支付/邮件当已上线服务。

5. 写一篇面向技术决策者的介绍，保存intro.md；另写无变更清单的更新邮件，明确非本版增量。

   应看到：文稿主文件符合字数与受众；来源、限制和下一步具体，不编定价或新增功能。

6. 交付README、测试结果、预览说明、结构图、文稿与未验清单；用 /preview stop 收尾。

   应看到：别人可按README重现；只有明确同意时才按第21课上传或走Netlify授权部署。

7. 写受众、内容、交付文件和三项验收

   应看到：一页静态介绍包含日期地点容量与报名入口

   为什么：小范围能在本地闭环，避免先造完整后台

8. 改变条件：容量需要实时剩余人数

   应看到：这是新增动态需求，单独规划数据来源

   为什么：结课包含README、源文件、事实来源、检查结果与未验范围。页面截图是辅助材料，不能代替HTML或实际预览；文稿也要量正文而不是聊天承诺。

## 故障恢复

- **预览状态显示not-running**：预览归属于创建它的进程；在同一聊天操作，独立终端start用Ctrl+C停止，不指望另进程status看到它。

- **完成报告有了却没有项目文件**：回到任务卡逐项核路径与内容；缺文件就标未完成并继续交付。

## 作业

提交毕业包：README、可运行产物、测试日志、project-map.html、intro.md、release-email.md和未验清单。不要提交密钥、账号缓存或node_modules。

## 开发者教学

开发者结课：从干净测试目录按README复现；核验失败基线、最小diff、测试和打包文件。
网页静态预览只绑定本机；不要暴露整个主目录或把公开部署当预览。Netlify登录、站点选择与发布均按已有授权流程。
交件记录版本、SHA、命令/退出码与平台；真实Windows、真实模型、真实账户、签名分别标PASS/FAIL/NOT_RUN。
对照30课完成表找缺口，旧行为回归与新能力验证都保留。

开发者加餐
项目结构保持简单，资源使用相对路径，秘密不打包。验收矩阵将本地文件、浏览器预览、真实发布分层；恢复说明指向实际文件和版本。
