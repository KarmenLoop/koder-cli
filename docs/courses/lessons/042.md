# 042 · 差异检查：看见每一个修改

[课堂](../index.zh.html#lesson-42) · [总纲](../README.zh.md)

## 学习目标

完成「差异检查：看见每一个修改」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

差异展示旧内容如何变成新内容，不能只凭最终文件看出是否丢掉重要逻辑。先看文件列表，再看每一处增删，最后核对测试和需求。大块格式化会掩盖真正修改，所以一个小修复尽量保持小差异；不相关文件应说明原因或移出本次任务。

专题补充
差异有工作区、暂存区和提交间等不同视角。同样的文件名在这些视角中可能包含不同内容；stat只给数量，完整hunk才展示语义。重命名、换行、二进制与未跟踪文件都需要额外观察，避免把没出现在某个diff里的文件误认为不存在变化。

在自有练习仓库中先画HEAD、index和working tree三层，再用小文本修改观察差异。逐项检查路径、上下文和删除内容；对于二进制用来源、尺寸和实际预览补充。

## 准备

先完成第41课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 示例与解读

```text
git diff --stat
git diff --check
git diff
前提：练习目录已是你拥有的Git仓库

补充案例：区分暂存与未暂存差异

```

统计告诉你范围，check抓空白问题，完整diff展示实际修改；三者不是同一种验证。

### 跟做 1：建立最小目录

在自有练习目录创建 input、output、notes 三个子目录。将本课给定文本写到 input 中，先列目录并读回文件，确认没有在安装目录里编辑。

检查点：目录层级和文件内容与题目一致，路径包含空格时仍可定位。

### 跟做 2：拆开命令理解

将本课命令拆为程序、参数、输入、输出、重定向五部分。遇到管道，说明每段从哪里读取、向哪里写；先检查单段再组合。

检查点：能解释 stdout、stderr 和退出码分别代表什么。

### 跟做 3：运行并记录差异

只在副本执行本课任务。保存关键输出和退出码；对文件转换，逐行比较输入与输出，明确编码、换行和相对路径。

检查点：失败不会被空输出或最后一条 echo 掩盖。

### 跟做 4：搬迁后复做

复制练习到新的自有目录，优先用相对路径复做。Windows 的 PowerShell/CMD 与 macOS Shell 语法分别记录，不机械复制。

检查点：新目录仍能读到相同输入并得到相同业务结果。

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 目录和输入可重建
- 命令参数与重定向解释正确

- 空格、编码或缺文件边界有一项检查

### 开发者复盘

将 cwd、环境变量与临时目录作为测试参数。先构造输入边界再断言退出码和文件内容。对本课涉及的流处理，验证 EOF、无输入和坏参数，不用无限等待掩盖阻塞。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「差异检查：看见每一个修改」，可与本课示例对照；无无关真实资料。

2. 记录修改前的状态

   应看到：知道原有未提交内容。

3. 让Koder只修一个小问题

   应看到：范围明确到文件和行为。

4. 逐段看diff

   应看到：确认没有删除测试或混入密钥。

5. 按验收清单核对

   应看到：每项需求能对应差异和检查。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「统计告诉你范围，check抓空白问题，完整diff展示实际修改；三者不是同一种验证。」逐项对照，不把未执行项填成通过。

7. 画两次比较并写各自结果

   应看到：暂存B对A，未暂存C对B

   为什么：Git有中间暂存层，不止旧与新

8. 改变条件：working改回B

   应看到：未暂存为空，但暂存仍有变化

   为什么：验收要能解释每处变化及其归属，保留用户已有修改。没有看到diff只是选定比较范围为空；不能据此宣布工作区完全干净。

## 故障恢复

- **结果与示例不一致**：git diff默认不显示未跟踪文件内容；还要看git status，不能漏交新增文件。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

自动验收同时查tracked diff与new files；不要用全仓格式化让文件计数看起来像很多工作。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
审查工具应准确标左右版本和行号。自动过滤空白只能辅助阅读，不能默认丢弃有意义空格；未跟踪、权限位和文件类型变化要独立呈现。
