# 134 · 写作审校：事实、逻辑与读者三遍检查

[课堂](../index.zh.html#lesson-134) · [总纲](../README.zh.md)

## 学习目标

完成「写作审校：事实、逻辑与读者三遍检查」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

审校先问有没有错，再问推理是否成立，最后问读者是否看得懂。语法顺畅可能掩盖无来源的事实或偷换比较条件。把每个强主张回到证据，把每个行动回到实际入口。未解决的问题应保留注释或说明，不能靠漂亮措辞遮住。

专题补充
事实审校问句子是否与材料一致；逻辑审校问证据是否足以支持结论；读者审校问表述是否会导致错误行动。三类问题常在一句话里同时出现，修复时应先处理对决定影响最大的错误。高风险不是词语本身，而是无证据的确定性、范围扩大与实际后果。

事实、推理、行动各审一遍，问题记录包含位置、证据和建议。按误导后果排序修复，区分证据不足和明确冲突；修改后重读邻段，确认结论真正改变而非只换词。

## 示例与解读

```text
三遍：事实核对→逻辑与归因→读者与行动
结果：修改项、保留项、未决项

补充案例：事实第一遍：找出可直接核对的错误
待审稿：“本次96名居民参加，80%居民满意，因此自习室让全社区学习效率翻倍。我们已决定永久免费开放，下周人人都可直接到访。”依据包：96人次；16名现场受访者中11人希望延长；未测学习效率；六周预算；容量与日期待定；未提供费用政策。
本课条件：原稿把人次写成人
```

每项问题有理由和位置。

### 跟做 1：先建事实表

逐条读取本课材料，建立“编号、原文或数据、出处、可支持的结论、不能推出什么”五列。区分历史功能、版本增量、判断和待核实信息。

检查点：每项重要陈述都有依据，缺材料不会被写成新增功能。

### 跟做 2：围绕读者排结构

用一句话写读者读完后应做什么，再安排论点、证据、限制和行动。介绍、更新邮件、对比与压缩稿使用不同结构。

检查点：段落承担不同功能，不靠同义反复凑字数。

### 跟做 3：成稿后反向核对

将正文的数字、产品名、定价、版本和比较结论逐一连回事实表。按本课要求计算正文长度，文件正文与聊天收尾分开。

检查点：删掉无据归因；保留不确定性，但仍交出读者能用的稿件。

### 跟做 4：做受控改稿

只引入给定变式，检查受影响句子和来源。压缩时先删重复，再缩例子，不能新增前稿没有的事实来补流畅度。

检查点：改稿前后事实集合可对照，解释内容取舍而不只说“润色”。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 事实可追溯且不编造
- 结构符合读者及使用场景
- 论点有材料和具体含义
- 长度、语气与任务要求匹配
- 变式或压缩未引入无据新事实

### 开发者复盘

把主交付文件作为长度与事实检查对象。保存来源与前稿的路径或摘要哈希；检测明确增量句与来源范围是否匹配。语法顺畅不能替代事实准确，不用模型自评分作为唯一质量证明。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「写作审校：事实、逻辑与读者三遍检查」，可与本课示例对照；无无关真实资料。

2. 逐条核对事实

   应看到：价格、版本和范围重点查。

3. 检查因果与比较

   应看到：同条件才可比较。

4. 模拟目标读者

   应看到：找理解障碍。

5. 整理修订说明

   应看到：不重复无关细节。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「每项问题有理由和位置。」逐项对照，不把未执行项填成通过。

7. 逐个核对人数、比例、日期与费用

   应看到：交四条事实问题及修订句

   为什么：凭印象把96也删掉→保留数字但修单位

8. 改变条件：11除16应怎样表述

   应看到：可写约68.8%受访者希望延长，通常原始人数更直观且不等于满意率

   为什么：把所有数字都列为错误→逐项核对来源，正确数字保留，只修口径、范围或推理不成立的部分。

## 故障恢复

- **结果与示例不一致**：自动评分只是参考，不能代替来源核查。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

审校自己的更新邮件，至少找出一个可能误导的句子并修正。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不代表，事实需要证据。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

门禁应降低假红同时保留真实拦截；有披露不等于任意主张都可过。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
问题记录使用location、claim、evidence、category、severity、suggestedFix与status。规则检查可以提示数字变化和绝对词，但误报需回材料解释。保留原稿与修订稿，未解决项不因文字变顺而自动关闭。
