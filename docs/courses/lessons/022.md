# 022 · API、上下文与更新排障

单元 2 · 建议 40 分钟（含自行练习） · 0.4.15 配套教材

[课堂](../index.zh.html#lesson-22) · [总纲](../README.zh.md)

## 学习目标

先区分失败层，再收集最少证据；恢复任务时不重放已经完成的操作。

## 原理讲解

开发任务先检索公开 GitHub 候选、核对固定版本许可，再分轮提问并写需求、架构、任务和工具方案。已有项目优先复用，安装工具仍走本轮授权。对话中说“帮我更新 Koder CLI”或输入 /update 可触发版本比较、校验安装和新版入口核验；Ask/计划模式只检查。
API 无法连接：核对地址、协议、型号、环境变量和网络；401/403通常需要核对凭据或权限，429检查额度与限流，5xx或超时查看服务方状态。保留具体错误码，分享日志前遮盖密钥与聊天内容。不要反复更换随机接口。
上下文设置在 setup → 上下文与输出。填写当前型号与接口真实支持的窗口；输出上限也占用窗口。客户端会压缩历史、限制工具结果并保留相关记忆，但改一个更大的数字不会扩大服务方的硬上限。单个超大文件应分段读取或检索相关部分；支持更大窗口的模型也要按其实际规格配置。
update --check 只检查 GitHub 官方更新；update 下载、校验并安装当前更新通道的新版本，同版不重装、旧版不回退。配置、记忆和渠道绑定保留。preview.6 起启动的会话会在任务保存后自动重启，恢复原会话与待处理输入；运行中的网关先完成任务和回复再重连。旧版进程首次迁移需启动一次新版。更新不代替等待中的批准，也不重放已完成操作。若新版本使用许可变化，先查看并明确接受新许可。升级后用 version 核对；旧版教程毕业后会从新增第17课续学。

专题补充
错误需要按发生层定位：输入、配置、网络、服务商、工具执行或交付验证。相同HTTP数字可能包含不同业务原因；最后一行错误不一定是最早原因。恢复既要解决故障，也要保护已经完成的文件和未知外部效果，避免把重试变成重复执行。

从合成日志提取时间、阶段、状态码和脱敏原因，建立最短因果链。每次只改变一个相关条件，写出预期观察。保留原始日志入口和可公开摘要，不复制密钥或无关二进制。

## 准备

保存当前工作，不清空历史。准备版本、系统、失败命令、错误码和最后几行已脱敏输出。

## 手把手操作

1. 先运行 koder version、koder doctor；记录出错的是安装、模型、工具、权限还是外部提交。

   应看到：层次明确后才处理；MAIL_CHECK_FAILED与当前编程任务超时可能是独立事件。

2. 模型问题先看 koder model show，再做一次model test；401/403查授权，429查配额，5xx/网络查服务状态。

   应看到：诊断不无限重试；记录状态码和服务商原因，分享前脱敏。

3. MiniMax422且含1026/1027时，新会话用简短无敏感任务对照；避免再把安装包二进制或超长Hex送入上下文。

   应看到：过滤原因不写成断网；保留旧记录，不尝试绕过服务商审核。

4. 工具超时或HARNESS_JIT_STOP时，查看最后一次工具、产物与回执，列出完成/未知/未执行。

   应看到：started、退出码0或编排停止均不足以证明业务已完成；续做只接未完成部分。

5. 写已完成产物与失败阶段

   应看到：report保留，后续请求鉴权失败

   为什么：失败发生较晚不抹掉已完成写入

6. 改变条件：report之后被用户编辑

   应看到：恢复不得用旧内容覆盖最新用户改动

   为什么：输出应明确已知、推断和待核实；恢复步骤从最早可定位错误开始。单次成功是该条件下的结果，不是全部模型或所有平台稳定性证明。

## 故障恢复

- **把上下文窗口随意调大**：按真实模型限制配置，保留输出预算；大文件按需检索而不是一次塞满。

- **升级后还跑旧版**：检查命令路径和新终端版本；按第16课处理多入口。

为“发信超时”和“网页搜索返回空结果”分别写恢复方案；第一步都先取证，不能直接重发或重复安装。

## 开发者教学

错误分类保存HTTP状态、服务商码与脱敏原因；用户标题不能与原因矛盾。
网络失败不得污染成功历史；未知使用量不能记成0。
恢复依赖任务输入、基线、模型设置与经验版本；取消或撤权后重新确认范围。

开发者加餐
错误分类保留providerCode和安全原因，读取响应体需要大小界限。重试策略按错误类型与副作用状态决策；未知效果不能自动重放。
