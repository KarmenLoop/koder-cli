# 066 · 异步任务：等待完成而不是等待一会儿

## 学习目标

完成「异步任务：等待完成而不是等待一会儿」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

异步代码的关键是等待实际完成信号。固定sleep可能在快机器浪费时间，在慢机器仍然太短。Promise表达结果或失败，await把后续步骤放到完成之后。测试要检查等待关系，而不是靠偶然时序通过。

专题补充
异步任务的正确性取决于结果与依赖关系。调用返回Promise通常意味着工作尚未完成；回调被触发、数据写完、资源关闭也可能是不同节点。本组使用可控Promise与事件数组推导顺序，避免靠机器速度碰运气。

先标明启动点、完成信号和消费点，再决定串行或并行。把依赖作为参数传入，测试用deferred控制何时完成；完成前检查中间状态，释放后再检查结果。

## 示例与解读

```text
async function load(loadText) {
  const text = await loadText();
  return text.trim();
}

补充案例：观察await前后的事件
程序：const log=[];const p=Promise.resolve("x").then(v=>log.push(v));log.push("start");await p

可复制的离线 Node 样例（仅计算合成数据或内存时序）：
(async()=>{const log=[];const p=Promise.resolve("x").then(v=>log.push(v));log.push("start");await p;return log;})().then(value=>console.log(JSON.stringify(value)));
```

trim发生在文本加载后；加载失败应传播或按契约处理。

## 故障恢复

- **结果与示例不一致**：async函数内部启动任务却不返回或await，会让调用者误判结束。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

测试用可控deferred而非任意sleep；取消和清理也应等待实际完成。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
异步函数总返回Promise；同步抛错与异步拒绝对调用者有区别。并行组合要说明失败后其他任务是否仍在执行，Promise.all的拒绝本身不会取消已启动工作。
