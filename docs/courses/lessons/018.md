# 018 · 电脑与文件：查看、授权、撤销

单元 2 · 建议 45 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-18) · [总纲](../README.zh.md)

## 学习目标

在明确授权范围内操作浏览器或桌面，并核对每一步真实状态。

## 原理讲解

先检查能力，再选需要的目录和能力。主目录模式用于个人文件；完整工作模式选择本机可见磁盘根。授权时逐项核对执行程序、目录和远端成员，输入 GRANT 后才保存。系统隐私授权、管理员权限和缺失的驱动仍需按系统流程处理。
文件操作请提供完整路径，带空格的路径用双引号。Windows 的 D: 是盘符相关路径；明确使用 D:\folder\file.txt。遇到“路径离开目录”，先检查工作目录、授权根、网络盘与链接目标，再查看 permissions status，不要关闭目录边界检查。文件发给渠道前，还要确认接收人、群和附件范围。

专题补充
桌面操作依赖当前窗口、可访问对象和真实系统权限。工具配置存在不表示目标应用已经可控。点击前核对对象，点击后读取新状态；不能用预期画面代替观察。文件读取也需要实际路径与允许范围，符号链接和同名窗口会使表面判断失效。

先用合成截图文字练习状态识别，再设计观察→动作→读回的最小闭环。每一步只改变一个对象，记录目标窗口与预期变化。课堂不操控真实应用；学员获准手测时先选自己的无敏感练习文件。

## 准备

只用自己创建的测试窗口和公开网页；不操作正在使用的私人窗口。GUI需要受支持的系统、驱动和交互桌面。

## 手把手操作

1. 运行 koder permissions status，查看network/browser/desktop/files等范围。

   应看到：缺失项明确；不能因--yes就当作已有电脑授权。

2. 通过Setup或 koder permissions request 的提示申请本次目标所需范围。

   应看到：只开放目标所需权限；系统弹窗需用户自己核对。

3. Windows运行 koder mcp doctor windows-mcp --json；检查后再在Setup测试/启用内置驱动。

   应看到：缺驱动、架构或权限如实显示；不要额外winget安装一套抢配置。

4. 给任务：“在我新建的测试文本窗口输入 HELLO-KODER，然后读回；不要保存到私人目录。”

   应看到：操作前识别目标，操作后重新观察；输入成功需实际窗口内容。

5. 选择修改a的目标并写定位依据

   应看到：使用路径或明确窗口身份，不能只匹配标题

   为什么：同名可见文本不保证同一资源

6. 改变条件：窗口不显示路径

   应看到：先读取额外可观察身份，无法区分则不猜

   为什么：验收要求动作前状态、具体动作、动作后状态三者一致。读取成功不证明写入可用；点击完成不证明业务保存。账号、OS权限与工具可达性分别确认。

## 故障恢复

- **驱动不存在或无显示服务器**：只执行可用的文件/API任务，记录GUI未验；不虚报点击成功。

- **锁屏后无法操作**：本机后台任务与锁屏GUI是两种能力；原生锁屏组件仍需签名与专机验收。

## 作业

在自有窗口完成一次输入和读回；撤销对应权限后验证后续操作被阻止。

## 开发者教学

窗口身份用平台返回的实际句柄/PID等证据固定；标题相同不等于同一个目标。
清理仅限本轮拥有的资源，取消不终止其他用户进程。
分别记录tools/list、tools/call、图形效果和真实用户任务；发现工具不等于已完成操作。

开发者加餐
使用公开工具能力而非猜测私有接口。定位器需要可验证身份，窗口切换后重读状态。取消和未知结果应沿原控制器传播，不能盲点或杀无关进程。
