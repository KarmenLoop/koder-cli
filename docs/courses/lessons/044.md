# 044 · 可复现问题报告：别人照着也能看到

单元 3 · 建议 30 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-44) · [总纲](../README.zh.md)

## 学习目标

完成「可复现问题报告：别人照着也能看到」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

好的问题报告让维护者从相同前置条件到达相同结果。版本、平台、Shell、任务输入、最小文件和实际输出缺一项都可能变成猜谜。报告要同时写预期和实际，不能只有“坏了”。减少样本大小时仍要保留触发条件，尤其是中文路径、并发或管道这样的关键因素。

专题补充
可复现问题需要稳定输入、明确环境、确定步骤和独立预期。最小化不是删得越少越好，而是去除无关因素后仍保留故障。无法稳定复现时，记录成功与失败的差异条件，比随意贴更多日志更有价值。

从一个失败样本开始，固定随机数、时间和依赖版本等变量。每次只删除或改变一个条件，再检查故障是否仍存在。把最小样本与完整原样本关联，保留不复现的反例。

## 准备

先完成第43课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 示例与解读

```text
标题：Windows PowerShell中带空格路径读取失败
前置：版本、Shell、工作区
步骤：1/2/3
预期：...
实际：错误码与退出码

补充案例：把步骤压到最短链
原步骤12个；故障只需新建空购物车并计算
```

别人无需你的私人账号或完整磁盘即可理解并尝试复现。

## 从文件开始跟做

本课工作目录：`Koder Projects/lesson-0044`。交件：可搬迁的练习工作区，保存到 workbook.md 或本课指定文件。

1. 下载本课工作簿，或用离线教材的 academy-practice.mjs 创建自有目录；把本课合成输入保留在 input.txt。
2. 在 workbook.md 的“操作前的预测”写出预期，然后完成：完成「可复现问题报告：别人照着也能看到」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。。
3. 按下面的方法保存实际步骤与结果，先不复制参考答案。
4. 只改变这项条件：完成bug-report.md和最小样本，另列尚未验证的平台。。保留基准，再独立完成变式。
5. 用自评表和课堂参考核对，说明证据缺口；有实际作品时保留可编辑文件。

### 跟做 1：建立最小目录

在自有练习目录创建 input、output、notes 三个子目录。将本课给定文本写到 input 中，先列目录并读回文件，确认没有在安装目录里编辑。

检查点：目录层级和文件内容与题目一致，路径包含空格时仍可定位。

### 跟做 2：拆开命令理解

将本课命令拆为程序、参数、输入、输出、重定向五部分。遇到管道，说明每段从哪里读取、向哪里写；先检查单段再组合。

检查点：能解释 stdout、stderr 和退出码分别代表什么。

### 跟做 3：运行并记录差异

只在副本执行本课任务。保存关键输出和退出码；对文件转换，逐行比较输入与输出，明确编码、换行和相对路径。

检查点：失败不会被空输出或最后一条 echo 掩盖。

### 跟做 4：搬迁后复做

复制练习到新的自有目录，优先用相对路径复做。Windows 的 PowerShell/CMD 与 macOS Shell 语法分别记录，不机械复制。

检查点：新目录仍能读到相同输入并得到相同业务结果。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 目录和输入可重建
- 命令参数与重定向解释正确
- 输出、错误与退出码均有记录
- 空格、编码或缺文件边界有一项检查
- 换路径后不依赖作者机器的绝对位置

### 开发者复盘

将 cwd、环境变量与临时目录作为测试参数。先构造输入边界再断言退出码和文件内容。对本课涉及的流处理，验证 EOF、无输入和坏参数，不用无限等待掩盖阻塞。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「可复现问题报告：别人照着也能看到」，可与本课示例对照；无无关真实资料。

2. 选一个合成可重复问题

   应看到：不使用真实客户数据。

3. 缩减到最少步骤

   应看到：每一步都影响复现。

4. 记录实际输出而非转述

   应看到：保留错误码和时间。

5. 按同样步骤再验证一次

   应看到：区分稳定复现与偶发现象。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「别人无需你的私人账号或完整磁盘即可理解并尝试复现。」逐项对照，不把未执行项填成通过。

7. 逐步去除登录和装饰设置，再确认错误

   应看到：保留两步仍触发同一异常

   为什么：删除无关前置能减少复现成本

8. 改变条件：去掉登录后错误变401

   应看到：不是同一复现，需恢复必要身份条件

   为什么：验收是第三人能够按说明触发同一类失败，或者清楚知道哪些条件尚不确定。不能用不同错误冒充原问题复现；截图不足时补原始文本和输入文件。

## 故障恢复

- **结果与示例不一致**：如果故障未重现，报告NOT_REPRODUCED而不是改写旧证据；不要向支持邮箱发送Key。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

完成bug-report.md和最小样本，另列尚未验证的平台。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不能；应保留原失败和本轮未复现的边界。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

缺少复现不等于用户没有问题；分类配置、平台、服务、产品逻辑和证据不足。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
测试夹具应包含真正触发路径，避免绕开关键API。固定时钟与随机源只在测试中使用；环境故障与业务断言分开报告。
