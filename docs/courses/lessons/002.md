# 002 · 认识开屏和提示符

单元 1 · 建议 20 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-2) · [总纲](../README.zh.md)

## 学习目标

认清当前目录、模型与模式，并能在同一窗口找到帮助，不把提示符当任务结果。

## 原理讲解

左边这位是 KARMEN 折光体，我们官网上的吉祥物，形状和官网用的是同一条曲面；右边是 KODER 和 KARMEN LOOP，下面列着当前用的模型、引擎、目录和常用命令。它不是装饰——好吧，主要是装饰，但它确实很好看。
开屏下面是提示符，它会告诉你现在的状态：

专题补充
提示符反映当前交互上下文：目录、模型、模式和会话。它不是执行回执。输入行还可能保存未发送草稿、菜单选中项或排队消息；这些状态的外观相似，后果不同。读界面时应先判断当前谁接收输入，再解释状态文字，避免把选择、接收和执行混为一谈。

把界面分成任务区、输入区、状态区。逐项提取可见文字，写出该文字允许推出的最小结论；涉及草稿时记录是否再次按了发送键。用合成屏幕日志练习，再在自己的界面复现一个只读操作；不把练习用日志冒充本机实际状态。

## 准备

先完成第1课；把窗口放宽到至少80列。准备一条无敏感内容的任务。

### 跟做 1：定位操作入口

先分清屏幕上的系统终端和 Koder 提示符。系统命令在终端运行；以 / 开头的会话命令放在 Koder 对话中。把本课出现的目录逐个写入 environment.md，并标注“当前目录”“临时练习”“正式作品”。

检查点：能指着一条命令说明由谁解释、在哪个目录发生；不同目录不被画成同一个对象。

### 跟做 2：先预测再操作

将本课输入逐项编号。执行前先写一句预期，再按本课任务操作一次。需要点击或审批时，记录选项名称与选择理由；无操作环境则只完成推演栏。

检查点：实际输出与事前预期分开，拒绝或取消也有明确结果。

### 跟做 3：读回产物

不要只看最后一句回复。打开实际文件，或重新读取目标状态，记录与要求对应的行、字段或画面。临时目录退出后可能被清理，需要留存时按教练提示保留。

检查点：作品路径可找到；模型陈述与文件内容能相互核对。

### 跟做 4：独立再做一遍

只替换题目指定条件，保留原结果。用自己的话解释哪些步骤保持、哪些步骤改变。请同学从记录中复做，不替对方补隐含步骤。

检查点：变式有独立结果；接手者不用猜目录或输入。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 能区分终端、Shell、CLI 与文件对象
- 操作前有明确预期，操作后有实际读回
- 取消、拒绝或临时目录清理的后果解释正确
- 变式保留原条件并指出变化
- 小作品可打开，记录足以供另一人复做

### 开发者复盘

把入口、工作目录和产物路径显式传入测试。练习取消发生在修改前与修改后两种情况；断言未批准变更未落盘、已完成产物可读回。不要用“收到成功字符串”代替文件断言。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 运行 koder；先看开屏的版本、模型、目录，不急着输入任务。

   应看到：目录应是你想工作的项目；模型名字是配置，不证明接口已连通。

2. 输入 /help；再输入 /setup 查看设置，退出设置返回原对话。

   应看到：帮助与设置在当前命令窗口打开，不需要再开一个 Koder。

3. 空输入时按 /，方向键选择，按 Tab 填入；先编辑草稿，再回车提交。

   应看到：选择只填草稿；Esc 可关闭。不能弹出时按提示改用 /help 或补全。

4. 在另一个窗口进入不同项目，分别运行 koder，再查看各自目录。

   应看到：两个窗口应各做各的任务；明确共享同一会话时的占用提示要保留原文排查。

5. 制作四张字段卡，分别说明位置、模型、模式、会话身份

   应看到：plan 表示计划状态；没有任何字段证明文件已经修改

   为什么：状态文字说明环境，执行结论必须来自后续动作与产物

6. 改变条件：把 plan 改为 run，但没有工具日志

   应看到：仍不能声称修改完成，只能说明执行模式改变

   为什么：界面判断使用成对反例：同一段文本分别处于草稿、排队、工具完成时应得出不同结论。目录和会话名要在任务开始前核实；菜单选择后检查输入框，审批出现时检查提示对象。简短提示仍应能追踪到具体任务。

## 故障恢复

- **框线错位、菜单折行**：先扩大窗口或在 Setup 改纯字符开屏；不要因界面错位重置模型配置。

- **只有一个窗口却显示会话占用**：记录版本和会话名，核查是否还有常驻或另一终端；不要直接删除整份历史。

## 作业

截取不含密钥的开屏，标出版本、工作目录、模型与模式；用菜单填一条草稿后取消，不发送。

## 自查与参考答案

能指出配置与真实执行的区别；草稿取消后没有新增模型任务，也没有文件改动。

## 开发者教学

把输入行为看作事件：选择、填草稿、提交、取消必须分开。
在80×24与窄终端各检查一次菜单；窄终端降级可读，不应输出半截控制序列。
对非TTY/JSON调用，检查输出没有开屏动画和交互菜单；用两个独立项目验证会话边界。

开发者加餐
渲染层不应成为任务状态权威。草稿、发送、接收、消费和工具回执应有各自状态；窄终端需要纯文本退路。模型或会话身份改变后，旧建议不能作为新任务的授权来源。
