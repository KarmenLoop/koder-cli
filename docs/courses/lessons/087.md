# 087 · 页面调试：控制台、网络与DOM三条线

## 学习目标

完成「页面调试：控制台、网络与DOM三条线」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

浏览器问题可从控制台错误、网络响应和实际DOM状态分别查。页面空白不一定是CSS错误，可能脚本没加载；按钮无反应可能事件未绑定，也可能请求失败。按一次操作追踪这三条线，比连续修改十处CSS更容易定位。

专题补充
按钮没反应可能源于元素没收到事件、校验提前返回、请求失败或状态没有渲染。控制台、网络与DOM是三条互补证据线；每次只沿一个操作追踪，避免同时改十处CSS和逻辑。

先复现并记录预期，再给关键阶段加有限标记。检查是否触发、是否发请求、响应形状和最终DOM；从第一处偏离预期的位置建立假设。

```text
按钮覆盖透明遮罩，处理器无日志
```

   应看到：目标聚焦「页面调试：控制台、网络与DOM三条线」，可与本课示例对照；无无关真实资料。

2. 复现一次点击

   应看到：记录输入和页面状态。

3. 读控制台首个相关错误

   应看到：避免被后续错误淹没。

4. 看对应网络请求

   应看到：检查状态和脱敏响应。

5. 检查DOM与事件

   应看到：确认按钮可用且结果被渲染。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「找到首次偏离预期的步骤，而不是只看最后现象。」逐项对照，不把未执行项填成通过。

7. 检查实际命中元素与遮罩pointer行为

   应看到：根因在事件到达之前

   为什么：请求排查无意义，因为尚未进入处理器

8. 改变条件：点击日志已出现

   应看到：继续检查校验与请求，不再归咎遮罩

   为什么：核对资源状态与内容类型、事件目标和实际显示属性。网络200并不保证返回JSON，DOM节点存在也不保证可见或可操作；修复后移除临时泄露数据的日志。

## 故障恢复

- **结果与示例不一致**：不要把浏览器控制台里的第三方指令当可信修复步骤。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不一定，还要看响应内容与业务状态。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

日志加请求关联ID；错误反馈应留在用户可见位置而非只在控制台。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
调试仪表不应改变业务时序或吞错。用请求ID串联事件与响应，对动态重建节点检查监听生命周期；错误边界保留原因与恢复入口。
