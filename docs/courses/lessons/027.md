# 027 · 六秒钟的快乐，随时可以散场

单元 2 · 建议 20 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-27) · [总纲](../README.zh.md)

## 学习目标

使用可跳过动画而不打断工作，理解交互展示与脚本输出的区别。

## 原理讲解

代码雨、礼花、烟花、圣诞树、南瓜灯、国庆灯笼、跨年与生日，都在彩蛋菜单里。动画约六秒，任意键立即跳过；不支持动画的终端只显示文字。普通命令、JSON 和脚本输出不会被刷屏。

专题补充
短动画的价值取决于可跳过、不会遮住工作、不会污染机器输出。时长、帧率、运动幅度和音效是不同维度。终端TTY可移动光标，重定向输出应保持纯文本；低动态偏好和取消键需要明确行为。本课用本地帧数组与时间表练习，不播放真实音效。

把六秒效果拆成入场、保持和退出，再用字符帧或纸面时间线表达。固定总时长计算帧数，加入取消点和窄屏条件。实际代码练习只打印合成文本，避免操作正在工作的终端状态。

## 准备

使用交互终端；动画不需要模型，也不代表任务成功。敏感场合先关闭自动效果。

## 手把手操作

1. 运行 koder celebrate，先阅读菜单再选fireworks等效果。

   应看到：能选择具体效果，不自动执行项目命令。

2. 播放时按任意键跳过。

   应看到：立即回到可输入状态，动画不应占住终端。

3. 运行 koder celebrate auto notice，只显示节日祝福；不需要则auto off。

   应看到：notice与自动播放不同；普通命令不应刷屏。

4. 在终端不支持颜色或动画时查看文字降级。

   应看到：没有残余光标控制；退出后可正常输入。

5. 生成三段帧编号范围

   应看到：共72帧：0–11入场、12–59保持、60–71退出

   为什么：分段预算能避免效果无限延长

6. 改变条件：帧率降为6fps

   应看到：共36帧，时长仍6秒，不把帧数固定导致变慢

   为什么：输出需有时长预算、跳过路径和结束后恢复输入的说明。好看不是唯一条件；脚本日志应可解析，动画不能自动代表任务完成。

## 故障恢复

- **动画后输入光标异常**：记录终端、尺寸和复现；优先关闭效果恢复正常输入，不重置所有配置。

- **节日没出现**：先检查日期、自动模式与收录范围，不承诺所有地区每个节日都已覆盖。

播放一次、跳过一次、关闭一次；验证之后/help可用。

## 开发者教学

动画必须恢复光标、raw mode和监听器；取消、异常和自然结束都测试。
TTY、TERM=dumb、CI与JSON路径分别检查，机器输出不得混入ANSI帧。
节日去重按日期与用户设置处理，不能每次命令都播放。

开发者加餐
动画层应独立于任务状态；TTY检测、恢复光标与取消清理必须成对。帧调度使用实际时间而非假设每次sleep精确，低动态模式可采用静态确认。
