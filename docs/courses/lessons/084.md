# 084 · 浏览器预览：打开页面不等于运行正确

## 学习目标

完成「浏览器预览：打开页面不等于运行正确」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

预览分静态文件、开发服务器和部署环境。静态HTML可能直接打开，模块加载和API请求通常需要HTTP环境。开发服务器启动后要核对端口和实际URL；打开旧标签并不能证明看到的是最新文件。验收应记录源码版本和预览地址。

专题补充
预览是对某一份文件、某个服务和某个URL的观察。打开浏览器标签不能证明它对应刚修改的源码。静态文件、开发服务器和部署页面的资源解析与路由条件不同，排错应从实际地址和响应开始。

记录工作目录、启动入口、实际URL和页面标记，再核对资源请求。先验证首页，再走内部链接与刷新；浏览器缓存和多个端口应作为明确变量处理。

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「浏览器预览：打开页面不等于运行正确」，可与本课示例对照；无无关真实资料。

2. 按项目README启动

   应看到：只启动自己的服务。

3. 记录输出中的地址

   应看到：不猜端口。

4. 打开并检查一个新改动

   应看到：确认不是缓存或旧站。

5. 结束后关闭自有服务

   应看到：不影响别人的端口。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「浏览器显示与当前工作区产物对应。」逐项对照，不把未执行项填成通过。

7. 对照端口与服务工作目录，记录差异

   应看到：当前标签不是新内容证据

   为什么：页面可打开与源码匹配是不同检查

8. 改变条件：正确目录服务在3001

   应看到：打开实际3001再核标记，不猜默认端口

   为什么：检查标题、最近修改标记、控制台、关键请求与真实交互。旧标签、旧服务或缓存页面都可能看似正常；一次HTTP成功也不能证明所有资源与业务状态正确。

## 故障恢复

- **结果与示例不一致**：不要通过杀掉所有node进程解决端口冲突；选择空闲端口或定位自有进程。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

预览生命周期要绑定任务所有者；关闭等待应有界且记录真实终态。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
预览入口应有清楚版本标识，开发服务器只绑定授权范围。保留服务所有权与停止方式；不要为了看页面启动不明脚本或修改全局浏览器设置。
