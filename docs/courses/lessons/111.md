# 111 · 并发测试：找共享状态而不是多开进程

## 学习目标

完成「并发测试：找共享状态而不是多开进程」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

并发故障往往来自共享文件、全局变量、锁和默认会话。测试要让两个操作在关键点交错，而不是随机睡眠等待偶发。用屏障控制顺序，检查每个结果属于哪个任务。并发数应适度，不能影响同机其他工作。

专题补充
并发测试要安排两个操作在共享状态的关键点交错。多开进程或增加随机sleep只能提高碰撞概率，难以稳定解释失败。版本、锁、幂等占位与任务身份是本组的主要共享边界。

画A/B时间线，在读后写前放可控屏障。分别释放并观察结果与状态，确保每个任务使用自己的输入、资源和回执；测试数量保持有限。

```text
A读取版本1→B修改为版本2→A尝试提交→应检测冲突

补充案例：复现丢失更新
count=0；A读0，B读0，A写1，B写1

可复制的离线 Node 样例（仅计算合成数据或内存时序）：
(async()=>{let count=0;let releaseA,releaseB;const gateA=new Promise(r=>releaseA=r),gateB=new Promise(r=>releaseB=r);const increment=async gate=>{const read=count;await gate;count=read+1;};const a=increment(gateA),b=increment(gateB);releaseA();await a;releaseB();await b;return {actual:count,expected:2,lostUpdate:count!==2};})().then(value=>console.log(JSON.stringify(value)));
```

这是受控交错，不依赖机器快慢。

## 故障恢复

- **结果与示例不一致**：只把测试跑100次不能证明没有竞态；先理解冲突窗口。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

锁生命周期要覆盖实际临界区，过期回收需要存活和所有权证据。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
并发控制应覆盖检查与变更的原子边界。锁顺序、范围和释放都要明确；单线程异步也会在await之间交错，不因只有一个进程就免疫竞态。
