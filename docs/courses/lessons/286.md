## 学习目标

完成“给换电脑准备一个学习包”：选出可迁移文件，写 README 描述打开顺序和依赖；解释基准与变式的结果。

## 原理讲解

学习环境有三个独立对象：接收键盘的终端、解释命令的 Shell，以及 Koder 内创建的练习目录。会话进度是记录，源文件是作品；记录能恢复并不表示临时文件还在。课程阅读、脚本教练、自己的模型任务也有不同成本。先建立能够定位和搬走的学习成果，之后每次排错才有可靠起点。

本案例的关键推理：迁移的是学习材料，环境配置与授权需要在新机器单独建立

操作方法：用一张两列索引把“屏幕显示的名称”映射到“实际对象”。终端命令只在 Shell 输入；聊天中的斜杠操作只在 Koder 输入。对目录先取绝对位置，再看文件内容；对课程先标阅读或实操，再记录产物。示例中的路径是合成数据，动手时应替换成自己的练习目录。

### 跟做 2：先预测再操作

将本课输入逐项编号。执行前先写一句预期，再按本课任务操作一次。需要点击或审批时，记录选项名称与选择理由；无操作环境则只完成推演栏。

检查点：实际输出与事前预期分开，拒绝或取消也有明确结果。

### 跟做 3：读回产物

不要只看最后一句回复。打开实际文件，或重新读取目标状态，记录与要求对应的行、字段或画面。临时目录退出后可能被清理，需要留存时按教练提示保留。

检查点：作品路径可找到；模型陈述与文件内容能相互核对。

### 跟做 4：独立再做一遍

只替换题目指定条件，保留原结果。用自己的话解释哪些步骤保持、哪些步骤改变。请同学从记录中复做，不替对方补隐含步骤。

检查点：变式有独立结果；接手者不用猜目录或输入。
