# 178 · 毕业项目设计：选一个真实但有界的问题

单元 12 · 建议 30 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-178) · [总纲](../README.zh.md)

## 学习目标

完成「毕业项目设计：选一个真实但有界的问题」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

毕业项目应同时练习任务定义、实现或写作、验证和交接。选题可以是小网站、待办应用、办公内容包或本地Skill，不必做庞大平台。先限定对象、产物和非目标，再分阶段。缺少账号或设备时把相关部分列成可演练接口，不伪造完成。

专题补充
毕业项目的价值在于完整解决有界问题并可交接，而非堆技术名词。最小成果应有真实使用路径、可观察验收和明确限制；范围太大使核心路径也难完成。非目标保护时间预算，阶段交件保护中断后的恢复，替代方案则保留学习价值而不伪造外部效果。

从一个真实问题选最小闭环，写用户、输入、产物和非目标。将工作分成能保存成果的阶段，并给每阶段独立验收；评估环境与数据缺口后缩范围或安排离线替代，不把缺设备当全部项目不能开始。

## 准备

先完成第177课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。账号、图形操作和外部写入须另有可用环境与授权；没有条件就记录NOT_RUN。

## 从文件开始跟做

本课工作目录：`Koder Projects/lesson-0178`。交件：可维护的版本化项目，保存到 workbook.md 或本课指定文件。

1. 下载本课工作簿，或用离线教材的 academy-practice.mjs 创建自有目录；把本课合成输入保留在 input.txt。
2. 在 workbook.md 的“操作前的预测”写出预期，然后完成：完成「毕业项目设计：选一个真实但有界的问题」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。。
3. 按下面的方法保存实际步骤与结果，先不复制参考答案。
4. 只改变这项条件：提交提案与项目地图，列3条明确非目标。。保留基准，再独立完成变式。
5. 用自评表和课堂参考核对，说明证据缺口；有实际作品时保留可编辑文件。

### 跟做 1：固定交付对象

从本课输入确认仓库、分支、版本、文件与目标用户。先读当前状态，明确哪些改动属于本次，保留未提交或其他人的工作。

检查点：源码版本、安装包和官网内容有可核对的关联。

### 跟做 2：在副本完成变更

按本课操作修改文档、代码或发布资料，查看完整差异。GitHub 令牌只用既有凭据入口；课程练习不默认推送真实仓库。

检查点：改动范围具体，可审查；草稿与已公开状态分开。

### 跟做 3：核对交付链

逐层检查源码、测试、打包文件、安装启动与公开下载。本课只做文档或推演的层保持相应标记，不把一个环节成功扩成全链通过。

检查点：版本与哈希能对应实际下载内容，平台差异有单独记录。

### 跟做 4：让下一位接得住

按给定变式更新相关文件并重验。写清恢复版本、回退方法、已知限制和下一任务；用新目录按 README 再走一遍。

检查点：接手者能修改、验证和恢复，不依赖作者口头记忆。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 本次版本与范围固定
- 差异和来源完整可审查
- 交付链各层证据分别成立
- 变式更新全部受影响文件
- 回退与接手说明可执行

### 开发者复盘

发布采用固定产物与可回退部署记录。包校验、安装、公开链接和真实平台分层；更新不能删除历史或 UNKNOWN 回执。保留失败证据，避免通过覆盖同版本文件掩盖差异。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「毕业项目设计：选一个真实但有界的问题」，可与本课示例对照；无无关真实资料。

2. 选一个小场景

   应看到：避免目标无限扩大。

3. 定义最小成果

   应看到：可打开或运行。

4. 安排阶段检查

   应看到：每阶段保存产物。

5. 确定评分证据

   应看到：不是只靠自评。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「提案能在现有环境完成核心路径。」逐项对照，不把未执行项填成通过。

7. 选报名说明→人数整理→负责人草稿的闭环

   应看到：提案有三个核心产物和明确使用者

   为什么：完整小路径比许多半成品更能检验能力

8. 改变条件：用户最急是活动取消通知

   应看到：改主路径围绕取消信息与草稿，其他管理功能延期

   为什么：提案应在现有环境完成页面、表格与草稿；支付、真实登录、自动发信不进入当前验收。每阶段至少有具体文件或可观察结果，不能只有任务列表。

## 故障恢复

- **结果与示例不一致**：不要把“以后支持所有软件”写成当前毕业验收。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

提交提案与项目地图，列3条明确非目标。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不是，完整、可验证和可交接更重要。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

基线固定后增量实施；保护其他任务与用户已有工作。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
提案记录baseline、userJourney、inputs、artifacts、milestones、acceptance与excludedScope。变更请求写影响后再纳入；本地fixture、原生设备和外部账号验收分别安排。不同作品用不同质量指标，不统一只看代码行数。
