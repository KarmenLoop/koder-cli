# 160 · 自主学习：经验需要证据与适用条件

单元 11 · 建议 30 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-160) · [总纲](../README.zh.md)

## 学习目标

完成「自主学习：经验需要证据与适用条件」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

一次成功不一定能归因于某种方法。经验记录应包含适用情境、改动、证据、正反结果和失效条件，允许没有可采用条目。用户偏好、任务事实和工作方法分开，避免把偶然结果固化成全局规则。学习开关与操作权限也独立。

专题补充
学习不是把一次成功写成永久规则。经验必须说明在哪种情境有效、相对什么基线、代价和失效条件。方法B可能更快但漏相关资料，适合问题可定位的任务而非未知分布的探索。成本、正确性与完成时间需要分别测量，不能由一个指标推导另一个。

选择有基线的具体任务，事前写预测与评价口径，再比较候选方法。记录输入、方法变化、结果、成本和失败；只有证据支持才形成有条件经验，缺对照或外部变化过大时保留NO_ENTRY。

## 准备

先完成第159课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。账号、图形操作和外部写入须另有可用环境与授权；没有条件就记录NOT_RUN。

## 示例与解读

```text
经验：cue、lesson、evidence、outcome、version、expiry；证据不足：NO_ENTRY

补充案例：预测先写：避免事后讲故事
合成实验：方法A先读全部20份文档，方法B先建问题清单再读相关5份。任务1两者都答对4/5问题，A用时12分钟、B7分钟；任务2关键答案藏在第18份，A答对5/5、B3/5。没有付费token数据。两个任务材料固定，模型设置相同。
本课条件：准备比较A与B但还没看结果
```

不把模型自评当真实执行证据。

### 跟做 1：画出能力链路

按本课情境列出 CLI、Skill、工具、MCP server 与真实目标。标明谁提供说明、谁执行、谁授权、谁保存回执。

检查点：能解释 Skill 被找到不等于工具已运行。

### 跟做 2：先查现有能力

检查本地目录和已连接工具，缺项再按既有权限查官方说明。记录来源、版本和适用平台，不直接执行教程里的任意脚本。

检查点：复用已有入口，网络、安装和桌面授权各自核对。

### 跟做 3：用最小目标验调用

先做一个有明确输入与输出的合成任务。MCP 分别检查握手、工具列表、调用和结果；子 Agent 分别检查任务归属、结果和取消。

检查点：工具声明、调用成功和真实外部效果不会混成一个状态。

### 跟做 4：变更后重验边界

按本课变式修改环境、权限或能力选择，检查拒绝与恢复路径。经验候选只记录实际证据，不把一次自评直接变成默认规则。

检查点：原 Core 的权限、预算与取消继续生效。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 工具链各层职责清楚
- 来源与适用条件可核对
- 最小调用有输入输出证据
- 缺权、缺驱动或取消有正确处理
- 能力改进保留原执行与权限边界

### 开发者复盘

为协议输入、工具结果、断开、取消和重连分别写断言。子任务共享父预算和授权，结果必须保留完整回执或可读取引用。JIT/经验层只调整受控配置，不修改凭据、权限或成功判据。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「自主学习：经验需要证据与适用条件」，可与本课示例对照；无无关真实资料。

2. 选择一个已验证小任务

   应看到：有基线可比较。

3. 记录具体方法变化

   应看到：不是“做得更好”。

4. 核对结果与成本

   应看到：含失败和无法归因。

5. 限定适用条件

   应看到：不自动推广所有任务。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「不把模型自评当真实执行证据。」逐项对照，不把未执行项填成通过。

7. 写效率与漏证据两个预测及指标

   应看到：计划同时测时间、答对数与遗漏来源

   为什么：事前标准能减少只挑好结果的偏差

8. 改变条件：看到任务1后才定成功标准

   应看到：保留探索性质，不能把事后选择当预注册验证

   为什么：任务1只能支持相同正确数下耗时较少；任务2显示召回代价。不能报告费用下降或普遍更优；综合建议必须包含补充检索与失效条件。

## 故障恢复

- **结果与示例不一致**：不要把用户秘密或完整邮件写进经验库。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 作业

写一条可采用经验和一条NO_ENTRY，解释证据差异。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不足，需要对照、适用条件和回归证据。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

复用原growth/experiences存储，采用走受控比较与回退。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
经验记录包含cue、methodDiff、baselineId、evidenceIds、outcome、contextVersion和expiry。采用与存储依赖现有受控机制；当前宿主若无持久经验owner，应记录缺口而非另建隐形全局库。
