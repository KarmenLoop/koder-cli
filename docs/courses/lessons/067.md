# 067 · 取消与超时：两条不同的控制路径

## 学习目标

完成「取消与超时：两条不同的控制路径」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

超时是时间预算到达，取消是用户或上层明确停止。两者可以共用AbortSignal，但日志要保留原因。超时不证明外部操作没有发生，尤其是写请求已发送之后。可取消函数还需要释放监听器、文件句柄和子进程，而不是只让界面停止转圈。

专题补充
取消表达上层希望停止，超时表达时间预算耗尽。二者可能都使用AbortSignal，但原因、提交状态和恢复方式不同。可取消函数既要响应停止信号，也要交代已经完成的效果和仍待关闭的资源。

先画准备、运行、提交、收尾四段，标出不可逆提交点。对每段注入取消，分别检查是否启动依赖、是否保留回执、是否完成自有清理。截止时间要从同一预算计算，重试不能每次获得完整新时长。

## 故障恢复

- **结果与示例不一致**：不要通过终止整台机器的同名进程实现取消；只管理本任务拥有的资源。 先保存原始错误，再从第一次偏离预期的步骤定位。

## 开发者教学

计时器应清除，取消监听应解除；保存真实回执优先于汇报已停止。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
监听器及时解除，定时器在完成时清除。取消应管理任务拥有的资源，不按进程名称终止无关进程。无法证明结束时报告未确认状态；先保存真实结果再更新界面状态。
