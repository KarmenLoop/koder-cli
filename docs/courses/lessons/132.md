# 132 · 编辑与润色：每轮只解决明确问题

[课堂](../index.zh.html#lesson-132) · [总纲](../README.zh.md)

## 学习目标

完成「编辑与润色：每轮只解决明确问题」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

润色可以改善结构、语气和节奏，但应保留事实与任务约束。先做内容编辑，再做句子编辑，最后校对错字与格式。每轮说明改变了什么，避免用户说“更简洁”后模型把必要风险和行动步骤一起删掉。例如用户要求“语气更自然”，可以调整过渡和长句，不应新增销量或删掉尚未验收的说明。用逐段差异表标出事实是否改变，比仅比较总字数更容易发现问题。

专题补充
编辑的顺序决定返工量：先解决事实和逻辑，再调整段落，最后修句子与标点。语气改变不应偷偷改变承诺强度。每次修订要能回答一个明确问题，例如读者何时能行动、哪句重复、哪项保证无依据。保留前后稿有助于看见变好之处及新引入的问题。

先改事实与承诺，再改结构，再改句子、语气和标点。每轮只解决已标注的问题，记录有意义的前后变化；最后回最初brief核对受众、行动和不能丢失的限制。

### 跟做 1：先建事实表

逐条读取本课材料，建立“编号、原文或数据、出处、可支持的结论、不能推出什么”五列。区分历史功能、版本增量、判断和待核实信息。

检查点：每项重要陈述都有依据，缺材料不会被写成新增功能。

### 跟做 2：围绕读者排结构

用一句话写读者读完后应做什么，再安排论点、证据、限制和行动。介绍、更新邮件、对比与压缩稿使用不同结构。

检查点：段落承担不同功能，不靠同义反复凑字数。

### 跟做 3：成稿后反向核对

将正文的数字、产品名、定价、版本和比较结论逐一连回事实表。按本课要求计算正文长度，文件正文与聊天收尾分开。

检查点：删掉无据归因；保留不确定性，但仍交出读者能用的稿件。

### 跟做 4：做受控改稿

只引入给定变式，检查受影响句子和来源。压缩时先删重复，再缩例子，不能新增前稿没有的事实来补流畅度。

检查点：改稿前后事实集合可对照，解释内容取舍而不只说“润色”。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 事实可追溯且不编造
- 结构符合读者及使用场景
- 论点有材料和具体含义
- 长度、语气与任务要求匹配
- 变式或压缩未引入无据新事实

### 开发者复盘

把主交付文件作为长度与事实检查对象。保存来源与前稿的路径或摘要哈希；检测明确增量句与来源范围是否匹配。语法顺畅不能替代事实准确，不用模型自评分作为唯一质量证明。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「编辑与润色：每轮只解决明确问题」，可与本课示例对照；无无关真实资料。

2. 圈出最影响理解的问题

   应看到：不同时改所有维度。

3. 按目标润色

   应看到：例如减少术语。

4. 对照事实清单

   应看到：没有新增承诺。

5. 读一遍最终稿

   应看到：检查连接和重复。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「修改可解释，原任务与来源没有丢失。」逐项对照，不把未执行项填成通过。

7. 逐个核对日期、容量和满意保证，先删错再写顺

   应看到：交事实修订稿与三处依据

   为什么：只换形容词保留错误日期→先处理改变读者决定的错误

8. 改变条件：改成“即将开放”是否足够

   应看到：仍可能暗示确定性，应写条件确认后公布日期

   为什么：用户要求自然后新增“永久免费”→回到事实表，语气编辑无权补价格或政策。

## 故障恢复

- **结果与示例不一致**：不要每轮从零生成一篇新文章，导致已确认内容漂移。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

多轮会话应继承原受众、长度、事实来源和交付格式。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
用editPass、targetIssue、before、after、factIds和reason记录有意义修改。可自动扫描新增数字、日期和绝对词，辅助发现事实漂移。不要仅按修改比例评分：一个准确的日期修正可能比大规模改写更重要。
