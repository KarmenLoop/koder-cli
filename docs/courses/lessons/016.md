# 016 · 安装、更新和换引擎

单元 2 · 建议 40 分钟（含自行练习） · 0.4.16 配套教材

[课堂](../index.zh.html#lesson-16) · [总纲](../README.zh.md)

## 学习目标

正确安装和更新，确认启动的确是新版，保留用户配置与恢复路径。

## 原理讲解

想把 Koder 装到别的电脑上？先阅读使用许可与授权说明，再按对应系统的命令安装：缺少运行时会下载 Node.js，安装包校验 SHA-256。安装后运行 setup 和 learn。
Windows XP、7、8 没法直接装：Node.js 22 最低要求 Windows 10，XP 连连接大模型接口需要的 TLS 1.2 都不支持。想在老电脑上用，可以用 PuTTY 之类的工具 SSH 登录另一台装了 Koder 的电脑，或者在手机上通过聊天软件网关给 Koder 发任务。
安装版每次进入交互对话都会后台检查新版，运行中每六小时检查一次。等任务、排队输入和草稿都处理完，再自动安装、校验并恢复会话。换了使用许可就停下来，请你先读清楚。想自己掌握节奏？输入 /update auto off；重新开启用 /update auto on，或直接说“开启自动更新”，当前窗口立即检查。忙时可继续输入引导；空行按 / 选择草稿，Tab 填入。用 koder logs --tail 100 排查本地错误。更新也懂排队，不会抢你的键盘。
默认使用内置 Koder 原生接口。备用引擎内部保留，默认关闭并置灰，正常使用无需安装或开启它。先检查当前模型与协议；网络错误不会偷偷切换引擎、密钥或计费地址。

专题补充
安装、配置和项目文件属于不同生命周期。新版压缩包下载成功不代表终端正在运行新版；PATH、启动器和current指向都可能影响实际入口。更新需要校验、空闲切换和恢复路径。本课分析安装清单与版本输出，不下载、安装或切换本机版本。

从启动命令向后追踪实际文件，再对比其版本、平台和包清单。先保护用户工程与配置，区分检查更新和安装更新。故障时记录当前可运行入口与候选状态，不先卸载或删除数据。

## 准备

记录系统、架构、当前版本和命令入口。使用官网或官方GitHub下载；具体安装脚本见INSTALLATION，不照搬别的终端语法。

## 手把手操作

1. 先运行 koder version 和 koder update status，记录安装位置与更新策略。

   应看到：分清系统入口、版本目录与数据目录；多份安装可能指向旧版。

2. 阅读许可与安装说明，选择对应系统安装器；更新先运行 koder update --check。

   应看到：检查动作不等于已安装；下载失败保留阶段和错误。

3. 确认后运行 koder update；让当前任务按提示保存并切换，不强杀其他任务。

   应看到：下载、校验、安装、入口核验分别完成；未明结果不能标成功。

4. 新开终端运行 koder version、koder doctor，再查看原项目与配置。

   应看到：新入口确实启动目标版本，项目与凭据仍在；实际问题保留日志后排查。

5. 画入口解析链并找实际启动文件

   应看到：当前运行仍旧版，下载存在不是切换证据

   为什么：命令解析顺序决定启动哪个文件

6. 改变条件：新终端PATH已指/apps/new

   应看到：重新读版本与路径确认，不能沿用旧窗口结果

   为什么：验收要对同一入口重新开终端读取版本并核对应文件。源码、下载包、安装树和运行进程各自记录，任一成功不能替代全部平台通过。

## 故障恢复

- **自动更新说还需手动**：查看安装所有权、路径与具体错误；必要时使用同一官方安装器覆盖，不手删配置。

- **PowerShell策略拦截**：按安装文档使用对应启动器；不全局设置Unrestricted，不关闭系统保护。

## 开发者教学

验收矩阵分CMD、PowerShell5.1、macOS与目标架构；无Node冷启动要隔离PATH，不卸载用户Node。
校验包SHA、文件清单、旧→新更新和EOF退出；保留原超时与失败。
Windows Server runner可提供原生证据，但不能冒充Windows10/11客户端GUI验收。

开发者加餐
更新器应校验完整包与许可状态，等待任务、队列和草稿空闲再切换。配置迁移需要保留旧值与恢复入口；内部引擎选择不应被更新失败偷偷改为备用。
