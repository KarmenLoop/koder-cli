# 094 · 鉴权与授权：知道是谁还不够

单元 7 · 建议 30 分钟（含自行练习） · 0.4.15 配套教材

[课堂](../index.zh.html#lesson-94) · [总纲](../README.zh.md)

## 学习目标

完成「鉴权与授权：知道是谁还不够」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

鉴权确认身份，授权确认该身份能操作哪个对象。用户登录成功并不表示能编辑任何人的待办。每个对象访问都应核对归属或角色，不能只在列表页过滤。教学使用假账号A/B与合成数据，重点验证越权被拒绝。

专题补充
鉴权回答是谁，授权回答这个身份能否执行这项操作。用户A与B都合法登录，仍不能互读私有待办。课程使用合成身份与资源，不读取真实账户；重点是每个入口的对象归属与角色决策。

先建主体、动作、资源、上下文四元组，再写允许与拒绝矩阵。列表、单项、修改、删除和批量入口分别验证；不要只在列表做过滤。

## 准备

先完成第93课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。需要运行脚本时先核对本机运行时；不为阅读课程自动安装任何软件。

## 示例与解读

```text
用户A读取A的待办：允许
用户B直接请求A的id：拒绝
未登录请求：按接口契约拒绝

补充案例：建立对象权限矩阵
t1属于A；身份A、B、匿名；动作读取

可复制的离线 Node 样例（仅计算合成数据或内存时序）：
(async()=>{const todo={id:"t1",owner:"A"};return ["A","B",null].map(actor=>({actor,allowed:actor!==null&&actor===todo.owner}));})().then(value=>console.log(JSON.stringify(value)));
```

三种情况分开测试，不用真实账号。

## 手把手操作

1. 写下本课目标、当前工作区和预期产物。保留练习原件，在副本操作。

   应看到：目标聚焦「鉴权与授权：知道是谁还不够」，可与本课示例对照；无无关真实资料。

2. 建立A/B合成身份

   应看到：各有独立对象。

3. 测试自己的对象

   应看到：正常读取。

4. 直接猜另一个对象ID

   应看到：仍被拒绝。

5. 检查错误响应

   应看到：不泄漏对象内容。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「三种情况分开测试，不用真实账号。」逐项对照，不把未执行项填成通过。

7. 填三格允许结果 将上述完整程序保存为自有目录的 case.mjs，运行 node case.mjs；先独立预测输出，再与固定输出对照。

   应看到：A允许，B拒绝，匿名按身份契约拒绝
   Node 固定输出：&#91;{"actor":"A","allowed":true},{"actor":"B","allowed":false},{"actor":null,"allowed":false}&#93;

   为什么：合法身份不等于资源所有者

8. 改变条件：t1设为公开

   应看到：读取规则变化，但修改权限仍需单独定义

   为什么：检查未登录、同所有者、其他所有者与角色边界。拒绝后确认没有数据变化，正例也必须工作；错误响应需遵循对象信息披露策略。

## 故障恢复

- **结果与示例不一致**：不要把“按钮隐藏了”当成服务端授权。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 自查与参考答案

至少提交明确产物、关键步骤记录和一项失败或边界检查。结合本课判断题核对：不能，攻击者仍可直接调用接口，服务端必须检查。 对真实设备或外部服务没有执行的部分写NOT_RUN。

## 开发者教学

授权在最终业务操作前执行；批量接口逐项验证范围。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
授权尽量靠近受保护查询与提交，避免先取全部再过滤。角色来自可信身份来源，不能接受客户端自报；缓存权限时要考虑撤销与版本。
