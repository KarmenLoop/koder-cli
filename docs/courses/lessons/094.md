## 学习目标

完成「鉴权与授权：知道是谁还不够」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

鉴权确认身份，授权确认该身份能操作哪个对象。用户登录成功并不表示能编辑任何人的待办。每个对象访问都应核对归属或角色，不能只在列表页过滤。教学使用假账号A/B与合成数据，重点验证越权被拒绝。

专题补充
鉴权回答是谁，授权回答这个身份能否执行这项操作。用户A与B都合法登录，仍不能互读私有待办。课程使用合成身份与资源，不读取真实账户；重点是每个入口的对象归属与角色决策。

先建主体、动作、资源、上下文四元组，再写允许与拒绝矩阵。列表、单项、修改、删除和批量入口分别验证；不要只在列表做过滤。

## 示例与解读

```text
用户A读取A的待办：允许
用户B直接请求A的id：拒绝
未登录请求：按接口契约拒绝

补充案例：建立对象权限矩阵
t1属于A；身份A、B、匿名；动作读取

可复制的离线 Node 样例（仅计算合成数据或内存时序）：
(async()=>{const todo={id:"t1",owner:"A"};return ["A","B",null].map(actor=>({actor,allowed:actor!==null&&actor===todo.owner}));})().then(value=>console.log(JSON.stringify(value)));
```

三种情况分开测试，不用真实账号。

### 跟做 1：写出数据与调用者

从题目列实体、字段、约束和调用身份。区分公开数据与用户私有数据；先用合成样本推演，再选择本课要求的内存、数据库或 HTTP 层。

检查点：每次读写都能说明对象属于谁，以及由谁允许。

### 跟做 2：固定一次操作的契约

列前置状态、请求、成功返回、失败返回和持久化位置。对于缓存、事务或幂等，写出键包含的维度和有效期。

检查点：同一 URL 不被默认当成同一用户数据；重复写不靠缓存冒充幂等。

### 跟做 3：跑正例再跑拒绝例

实现或分析本课操作，检查本人合法请求，再构造他人、坏输入、重复请求中的适用项。记录状态和数据是否变化。

检查点：拒绝不仅有错误消息，还应没有越权写入或泄露。

### 跟做 4：验证变式与恢复

改变题目指定条件后重做。对未知写入先查询结果；对迁移说明前后结构及恢复约束。当前仅为内存例子时如实标注。

检查点：能区分逻辑通过、HTTP 可用、持久化有效和生产可用。

## 故障恢复

- **结果与示例不一致**：不要把“按钮隐藏了”当成服务端授权。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

授权在最终业务操作前执行；批量接口逐项验证范围。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
授权尽量靠近受保护查询与提交，避免先取全部再过滤。角色来自可信身份来源，不能接受客户端自报；缓存权限时要考虑撤销与版本。
