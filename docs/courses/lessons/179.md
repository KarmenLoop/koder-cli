# 179 · 毕业项目实施：检查点、证据与复盘

## 学习目标

完成「毕业项目实施：检查点、证据与复盘」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。

## 原理讲解

实施阶段按最小闭环推进：先做核心路径，再补边界，最后做体验与交接。每阶段记录实际产物，遇到问题保留失败并定位，不用整项目推倒重来。编程和写作采用不同质量标准，但都要求事实、范围和验证一致。

专题补充
实施的可靠性来自小闭环：明确输入、产生文件、独立核预期、保存证据。失败保留能说明修复针对什么，需求与环境改变也需记录。检查点不仅是文件备份，还包含输入版本、状态与下一步；让别人能恢复是交付质量的重要部分。

固定本轮目标和基线，先做最小可用路径，再补反例与体验。每阶段保存文件、输入身份与实际检查，失败先定位再改；需求变化只影响相关产物，恢复从可信检查点开始而不是重建整个项目。

## 准备

先完成第178课。使用自有Koder Projects练习目录和合成数据；阅读示例不会执行命令。账号、图形操作和外部写入须另有可用环境与授权；没有条件就记录NOT_RUN。

```text
本课条件：只有需求卡与合成数据
```

## 从文件开始跟做

本课工作目录：`Koder Projects/lesson-0179`。交件：可维护的版本化项目，保存到 workbook.md 或本课指定文件。

1. 下载本课工作簿，或用离线教材的 academy-practice.mjs 创建自有目录；把本课合成输入保留在 input.txt。
2. 在 workbook.md 的“操作前的预测”写出预期，然后完成：完成「毕业项目实施：检查点、证据与复盘」的操作练习，能够解释结果、诊断常见问题并提交可核对的作业。。
3. 按下面的方法保存实际步骤与结果，先不复制参考答案。
4. 只改变这项条件：交阶段产物、检查日志和一次失败到修复的过程。。保留基准，再独立完成变式。
5. 用自评表和课堂参考核对，说明证据缺口；有实际作品时保留可编辑文件。

### 跟做 1：固定交付对象

从本课输入确认仓库、分支、版本、文件与目标用户。先读当前状态，明确哪些改动属于本次，保留未提交或其他人的工作。

检查点：源码版本、安装包和官网内容有可核对的关联。

### 跟做 2：在副本完成变更

按本课操作修改文档、代码或发布资料，查看完整差异。GitHub 令牌只用既有凭据入口；课程练习不默认推送真实仓库。

检查点：改动范围具体，可审查；草稿与已公开状态分开。

### 跟做 3：核对交付链

逐层检查源码、测试、打包文件、安装启动与公开下载。本课只做文档或推演的层保持相应标记，不把一个环节成功扩成全链通过。

检查点：版本与哈希能对应实际下载内容，平台差异有单独记录。

### 跟做 4：让下一位接得住

按给定变式更新相关文件并重验。写清恢复版本、回退方法、已知限制和下一任务；用新目录按 README 再走一遍。

检查点：接手者能修改、验证和恢复，不依赖作者口头记忆。

### 本课交件自评

每项 0–2 分：缺失或错误 / 有结果但缺依据 / 结果与依据齐全。

- 本次版本与范围固定
- 差异和来源完整可审查
- 交付链各层证据分别成立
- 变式更新全部受影响文件
- 回退与接手说明可执行

### 开发者复盘

发布采用固定产物与可回退部署记录。包校验、安装、公开链接和真实平台分层；更新不能删除历史或 UNKNOWN 回执。保留失败证据，避免通过覆盖同版本文件掩盖差异。

工作簿结构检查只能提示哪些栏目未填；正确性仍须核对本课输入、结果、变式和参考答案。

2. 固定本轮目标

   应看到：后续补充有记录。

3. 实现最小路径

   应看到：真实保存文件。

4. 跑正反例检查

   应看到：保留首个失败。

5. 整理复盘

   应看到：说明取舍与未验。

6. 整理本次实际结果与仍未确认的内容，把证据链接到作业。

   应看到：记录与「中途停止也有可恢复成果，完成状态可核对。」逐项对照，不把未执行项填成通过。

7. 做能显示三活动和总数的最小页面，再核40

   应看到：真实文件可打开且数据可对照，不先扩复杂账户系统

   为什么：早期闭环暴露数据到展示问题，比先写大量框架更有效

8. 改变条件：页面只能显示静态合成值

   应看到：明确静态范围，若任务要求导入数据需下一步接真实本地输入

   为什么：应保留50与预期40的失败、修复后40及去重规则；木工暂停进入页面和草稿。README补打开说明后才能称交接内容齐，仍不能称云部署或邮件完成。

## 故障恢复

- **结果与示例不一致**：不要把AI最终自评当第三方质量评分；证据不足就保留待验。 先保存原始错误，再从第一次偏离预期的步骤定位。

- **当前环境不能完成真实操作**：完成资料阅读、合成演练和验收计划，标明缺少的账号、运行时或设备。不要伪造回执，也不要为了过课扩大授权。

## 开发者教学

任务输入、模型设置、源码和证据版本关联，便于复现。
实现前固定输入、输出、错误与权限契约。为本课关键边界设计一个应通过与一个应拒绝的用例。
交付时记录源码/配置版本、实际命令、退出码、产物及回退方式；静态检查不替代真实账号或设备验收。

开发者加餐
用checkpointId、sourceHash、inputHash、testArtifacts与nextAction关联。自动测试验证明确契约，人工检查负责内容和可用性；两者不可互换。原始失败不删除，后续通过要与修复后的版本绑定。
