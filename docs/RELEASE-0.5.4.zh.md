# Koder CLI 0.5.4

本版让思考强度按实际模型适配，并在回复达到服务商输出上限时保留已生成内容。子任务正确继承所选强度；符合条件的长回复可以继续生成，不重复工具操作。

## 按模型提供思考档位

强度选择器同时检查模型 ID、官方接口与请求协议，再列出原生档位。代理接口或相似型号名称不会自动套用官方服务的设置。

例如 MiniMax M3.1 Flash 在受支持的 Chat/Messages 接口提供 low、medium、high、xhigh、max，不提供关闭思考。GPT-6.1 Sol 有五个原生档位，较早的 OpenAI 型号则有不同列表。Claude、Gemini、DeepSeek、GLM、Kimi、Grok、Qwen 使用各自核实过的协议映射。原来待验证或不可用的预设保持原状态。完整限制和官方来源见[模型强度指南](MODEL-EFFORT-AND-OUTPUT.zh.md)。

支持的显式选择才覆盖模型原配置。不支持的选择给出诊断，已有模型强度则保留原值。底栏区分已核实的档位、尚未核实具体值的“已有模型配置”和“服务商默认”。旧 deep/standard/fast/off 别名在存在有效映射时继续兼容。

子任务显式指定优先于父任务；未指定时继承父任务的显式选择。两边都没有选择时，保留子模型自己的默认值。更换子模型会重新检查支持能力；不支持继承档位时报告原因，不发送无效字段。

## 达到输出上限后保留正文

Koder 先保存可见正文片段，再结算用量。服务商明确返回输出上限、已有可续接正文且没有未完成工具调用时，同一任务最多自动发起两次纯文本续答。

续答仍受取消与费用预算约束，且不提供工具。续答中意外返回工具调用会被拒绝；被截断的工具参数不会执行。配置费用预算时，用量未知会停止续答；结算失败也会停止。未配置费用预算时，缺失用量仍标为未知，不记录成零。

会话保存与重新打开保留正文片段的关联。重开会话不会自动重启生成。两次续答后仍受限时，已生成内容继续保留，并说明剩余限制。

上下文窗口不足与输出截断分别诊断，不会通过续答路径反复重发超长上下文。提高思考强度可能消耗更多推理/输出预算；本地调大数值不能扩容模型真实上限。

## 使用方法

1. 安装更新后运行 `koder --version` 核对版本。
2. 在会话中打开 `/effort`，选择列出的档位，再用 `/model show` 检查。
3. 用 `koder context status` 或 `/context` 查看窗口、单次输出上限和压缩设置。
4. 遇到限制时，先读已保存正文及具体原因，再继续剩余工作。不要为恢复答复而重复已完成或结果未核实的操作。

[手把手指南](MODEL-EFFORT-AND-OUTPUT.zh.md)说明默认值、子任务继承、接口支持、输出上限与恢复方式；原有[会话快捷键](SESSION-DOCK.zh.md)和[上下文控制](CONTEXT-CONTROLS.zh.md)继续可用。
