# 命令未执行：如何看原因与继续任务

适用修复：0.4.14-candidate.4，包含 candidate.3 的修复。先运行 `koder --version` 确认实际启动的版本；源码或候选包存在不代表当前终端已升级。此候选未替换正式下载源。

## 这次为什么会一直显示未执行

截图中的 PowerShell 文件搜索使用 `-ErrorAction SilentlyContinue`。旧实现把这类读取也当成“屏蔽写入错误”：即使命令退出码为 0、进程已退出，仍生成 UNKNOWN 回执。后面的 shell 请求因此被原有对账保护拦下。终端又只显示工具输出第一行，具体原因不易看见。

修复后，只识别有限的纯读取管道：显式 `-NoProfile -Command`，读取命令接已知筛选命令，不含脚本块、变量求值、分号或其他命令。正常退出时显示 `SHELL_READ_PARTIAL`，说明被屏蔽的读取错误可能导致漏项，后续任务可以继续。未知脚本、写入、真实超时、后台进程或清理不确定仍保留 UNKNOWN。

## 看到真正的结果未知时

1. 看黄色说明里的原调用编号，以及 `COMMAND_TIMEOUT`、`ERRORS_SUPPRESSED`、`DETACHED_PROCESS` 等原因。
2. 核对退出码、进程清理状态和本次批准的等待时间。退出码 0 不能单独证明安装、发送或写入成功。
3. 让 Koder 用 `read_file`、`list_dir` 或 `search` 读取已存在的日志和目标文件。不要重跑原命令、换后台方式或换工具重复操作。
4. 若只读证据仍不足，Koder 会说明卡点；连续两次请求被拦的操作后结束本轮，保留已完成结果。脚本模式返回 exit 3，不误报 API 断网。
5. 用户核实实际状态后，另发一条明确指令，只处理剩余工作。运行中的“继续”引导仍属于原回合，不会清除待核实状态。无需删除会话或旧回执。

旧版本保存的 UNKNOWN 不会被自动改成成功。缺少详细原因的旧回执显示 `LEGACY_UNCONFIRMED_RESULT`。

## 卡住时如何核对预览

`workspace_preview` 在结果待核实时仅暴露 `status` 和 `discover`。`status` 返回当前进程已拥有的预览状态：如果已经启动，会返回已有地址；如果没有，则返回 `not-running`，不会伪造地址或悄悄启动。`discover` 读取项目入口与现有脚本，返回静态目录、开发脚本候选或未就绪状态，不执行脚本。它拒绝目录链接越出项目读取配置。

`start`、`open`、`stop` 仍被拒绝，即使模型忽略工具列表直接请求也不会执行。读到一个目录、脚本或已有 URL 不代表前次未知命令成功；已有地址也不代表页面已经应用最新修改。

在运行中输入“发预览给我”时，引导仍可被接收，但终端会同时显示 `SHELL_RECONCILIATION_REQUIRED` 与“仍属当前回合，不会解除待核实保护”。这条信息经本地会话和 agentd 原 IPC 传递，不增加另一套执行器。核实目标状态后，等本轮结束再发新的明确指令。新消息本身不是业务成功证明，旧回执继续保留；没有增加让模型自报成功就解锁的动作。

## 找项目文件时

工作区内 `list_dir` 和 `read_file` 支持相对路径及位于当前工作区内的绝对路径。查找其他已授权目录时，Agent 可使用 `search` 的 `scope: "home"` 和具体 `path`。该工具仍要求原有 `files.search` 授权；授权不会自动增加。

例如把范围缩小到目标项目，避免从整个 C 盘开始。遇到 `DumpStack.log.tmp` 一类被系统占用的后代文件，搜索记录跳过项并继续，显示 `SEARCH_PARTIAL`。根目录无法访问、权限被撤销、路径身份变化或用户取消时仍停止，不把失败显示成完整搜索。

`skill_read` 找不到名称时会返回原 ID，并引导 `skill_catalog` 查询实际可用 ID。它不会猜另一个 Skill、自动下载或假装已加载。截图未给出缺失 Skill 的准确 ID，因此不能据此断言某个内置包已损坏。

## 后台邮箱提示

`MAIL_CHECK_FAILED: NETWORK` 表示后台邮箱检查失败，与当前编程任务分开。同类错误在成功恢复前只提示一次，监控仍会重试。用 `koder mail status` 查看配置状态；不要把邮箱密码或客户端授权码贴到聊天。本次修复针对重复提示，不代表真实 163 网络或投递问题已验收通过。

## 在候选包中检查

解压候选包后，在其 `koder-cli` 目录执行：

```text
node bin/koder.mjs --version
node docs/shell-recovery-check.mjs
```

检查器只使用自有临时目录和脚本化模型，不调用真实模型、邮箱、通知或管理员权限，不覆盖已安装版本。Windows 上额外执行真实 PowerShell 只读查询和后续 `echo`；其他系统如实输出该项 `NOT_RUN`。输出 JSON 保留每项结果。此检查不代表 Windows-MCP 图形操作、安装更新或全部终端/IME 已验收。

回退时切回保留的旧 runtime，保留配置、历史和 UNKNOWN 回执。候选附带的安装脚本仍遵循既有下载源，不能仅凭脚本文件名认为它会安装这个本地候选。
