# Koder CLI 0.5.15

本候选改进网站交付和邮箱诊断，并包含任务模型选配、本地遥测开关及统一打包清单。正式发布等待第一方更新地址的公网核验；已公开的 0.5.14 下载文件保持不变。

## 网站交付

`workspace_preview start` 可以通过原命令审批启动项目已有的 Node 后端或 npm 开发脚本。Koder 等待真实本机 HTTP 响应，并托管自有进程；模型继续工作时预览保持运行。停止、取消、启动失败或宿主断开时清理自有进程，不停止其他服务。清理无法确认仍记为结果未知。

识别后端时优先于静态 HTML，已有预览面板会切到实际后端。需要 API 的项目不能用纯静态页面冒充完整交付。`selftest` 等常规自检脚本只有真实成功退出并完成清理才计入验证；追加 echo 掩盖退出码不算通过。最终测试应放在文件修改和预览检查之后。

真实 MiniMax-M3 测试生成了本地书店网站，实际询问需求、选择设计方向、运行后端并提供预览。另行浏览器操作核验了筛选、预约提交、刷新后保留和取消；网站自检通过 33 项。多次模型回合仍有测试预算中断或最终交付检查未通过，失败记录保留；这些结果不能解释为一次完成率、质量评分、手机无障碍或正式部署已验收。

## 邮箱诊断

在实际绑定邮箱的电脑运行：

```text
koder mail doctor --json
```

报告只读本地绑定、发件能力、后台监控阻碍和结果未知的发件数量，不拉取或发送邮件，不包含邮箱地址、授权码、主题、正文或回执编号。`koder mail monitor status --json` 保持单一 JSON；后台服务运行与邮箱监控实际开启分别判断。

专用 163 测试邮箱在 Windows beta 机。本候选的 Mac 验证没有访问该邮箱，真实发件、收件、后台扫描和可见提醒仍为 **NOT_RUN**。SMTP 接受不等于对方收到，系统提交通知不等于用户看到。

## 其他已接入项与边界

- 按任务难度在已配置模型及其支持的思考强度中选择，保留手动覆盖、取消和费用预算。
- 本地遥测默认开启，可在 Setup 持久关闭；不自动上传云端，不强制联网激活。
- 无头交付检查准确路径、真实文件和测试回执；合格 skip 或未完成仍不记成功。
- 全平台、macOS、Linux 包保留各自支持的功能及现行 Skill；平台包不重复携带其他系统二进制，旧教程导出保留在源码历史，当前教程和许可证仍随包提供。
- 保留凭据输入、Ubuntu、权限和未知结果核对。macOS 完整锁屏组件仍是未签名候选。

发行附件 `ACCEPTANCE-RESULTS.json` 区分源码测试、实际安装包、真实模型和未执行平台项目。Windows 实机验收继续由 beta 专员负责；本次不部署公司官网。
