━━ Lesson 3 of 30 · Configure a model: give Koder a brain ━━
  Tip · The model page now discovers current account IDs automatically. Choose Current account models to select one; refresh never switches it for you. A listing is not a tool-call test: run koder model test --tools. Automatic discovery can be disabled, or use koder model refresh manually.
Coach › Koder can't think on its own; it needs a model. The easiest way is the settings screen:
    koder setup
        pick a provider and model with the arrow keys or mouse, paste the key; it can even open the key page
Coach › Prefer commands? Put the key in an environment variable and save only its name:
    echo 'export OPENAI_API_KEY=sk-your-key' >> ~/.zshrc
        into zsh's config (macOS uses zsh); every new terminal sees it
    export OPENAI_API_KEY=sk-your-key
        this window only
    koder model set --preset chatgpt --key-env OPENAI_API_KEY
        a preset; only the variable name is saved
    koder model set --preset local --model qwen3:8b
        local Ollama, no key
    KODER_MODEL=… KODER_BASE_URL=… KODER_API_KEY=… koder review
        environment variables, handy in CI
  Tip · koder model presets lists the available presets; koder model show prints the current setup with only the last four characters of the key.
  (whispering) Careful typing keys into commands: your shell history (~/.zsh_history, ~/.bash_history) remembers better than your ex. Paste it in koder setup instead: only the last four show, and it skips shell history, but the key is stored in plaintext in local configuration. Environment-setting commands may enter history too; redact keys before sharing.
Coach › Today the practice project uses the coach model, so this lesson is look-only. Set up a real one after you graduate.

━━ Lesson 7 of 30 · Slash commands: gears, brakes and undo ━━
Coach › A Skill is a working guide. Koder can read Codex, Cursor and WorkBuddy SKILL.md packages and their resources on demand; scripts keep normal Koder approvals. Find one with /skills list, select it with /skill name and clear it with /skill clear. Host-specific tools still need setup.
Coach › Lines starting with / are slash commands. They control Koder itself and never reach the model.
    /mode plan
        plan mode: read-only, proposes a plan
    /mode code
        code mode: states a plan, then edits
    /yes
        toggles auto-approve; the prompt gains a !
    /new
        starts a fresh session
    /lang zh
        switches to Chinese, /lang en switches back
    /review  /fix  /test  /scan
        run those commands inside the chat
    /help  /learn  /exit
        commands, this tutorial, quit (Ctrl+D works too)
  Try it · Type /mode plan to switch to plan mode  →  /mode plan
  Try it · Now type /yes to turn on auto-approve  →  /yes
  Try it · Good. Type /yes again to turn it off  →  /yes
Coach › Koder is running a command you regret. Fastest fix?
    1. Press Ctrl+C to cancel the turn
    2. Unplug the network cable
    3. Shout 'stop' at the screen
  Answer: 1。Right. Ctrl+C is the emergency brake; Ctrl+D is a polite goodbye.
Coach › Study guide · Allow 30 minutes including practice, not a runtime deadline

━━ Lesson 8 of 30 · Read-only questions, pipes and scripts ━━
Coach › Just want answers without anything being touched? Use ask. It can list, read and search, but cannot edit or run commands.
  · Hands-on: ask anything; the coach reads package.json with read-only tools and answers. No approvals needed, since nothing can change.
Coach › In scripts, Koder behaves like any other command-line tool:
    git diff | koder ask "summarise this change"
        piped input is attached as extra material
    cat error.log | koder ask "what does this error mean"
        feed it a file
    koder run --yes --json "fix the lint errors" | jq -r .type
        --json prints one event per line for jq (brew install jq)
    echo $?
        the exit code of the last command
Coach › Exit codes: 0 done; 1 cancelled or a check failed; 2 a usage or model configuration problem.
  (whispering) Exit code 2 means 'check your setup', not 'it didn't try hard enough'.

━━ Lesson 9 of 30 · Code review with context ━━
Coach › review looks beyond the diff: it reads rule files such as AGENTS.md, recent commits and where changed functions are called, then lets the model verify with read-only tools.
  · Demo: the coach adds a discount function that yields fractional cents, then runs the real review pipeline, printing severity, file, line and a suggestion.
Coach › Each finding has a severity (high, medium, low), file, line and suggestion. Common forms:
    koder review
        review uncommitted changes, else the current branch
    koder review --base main
        compare with main
    koder review --format markdown --out review.md
        a comment ready for the PR
    koder review --fail-on high
        exit 1 on high findings, for CI
    koder review --fix --check "npm test"
        review, fix and test in one go
  · You can let Koder apply the fix, again with a diff and a y.
  (whispering) Being caught by Koder is fine. Being caught by your users in production is not.
Coach › Study guide · Allow 35 minutes including practice, not a runtime deadline
        Goal: Get actionable review findings and prevent an unparsed JSON review from passing a CI gate.
  Tip · Before you start: Prepare a small, explainable change in a test repository; define the scope when there is no repository or diff.
Coach › Hands-on steps · These are optional instructions, not automatically executed account connections, sends or publications.

           Check: Findings refer to the actual diff and explain location, trigger, impact and a remedy.
Coach › 2. Reproduce a finding before requesting the smallest fix.
           Check: Do not rewrite everything based on a suggestion; mark unconfirmed findings for investigation.
Coach › 3. For automation run koder review --format json and capture stdout, stderr and exit code.
           Check: Check parseability, parsed status and exit code; an empty-repository error must not pass.

━━ Lesson 10 of 30 · Fix until green: fix --check ━━
Coach › fix is a loop: run the check, hand failures to Koder, re-run, until it passes or attempts run out (3 by default).
  Tip · This time I'll press y for you; just watch it go round by round.
  · Demo: a check.mjs tests a count function; Koder gets it wrong once and right the second time, showing 'attempt 1/3' and finally 'Check passed'.
  (whispering) It missed the first time. Don't laugh; have you ever got it right first time?
    koder fix --check "npm test"
        fix until the tests pass
    koder fix "the home button does nothing"
        no check command: fix once from the description

    koder celebrate birthday --date 03-14
    koder celebrate birthday forget
  Tip · Birthday settings are not automatically included in model requests or sync. Information you type in an ordinary message still follows that model conversation’s normal data rules.
Coach › Study guide · Allow 20 minutes including practice, not a runtime deadline
        Goal: Store minimal birthday information only by explicit choice, with review and removal.
  Tip · Before you start: Practice with a fictional month/day. No birth year, age or ID is needed; mentioning someone else is not consent to record yours.
Coach › Hands-on steps · These are optional instructions, not automatically executed account connections, sends or publications.
Coach › 1. Read koder help celebrate for birthday commands and date format.
           Check: Use current help rather than guessing syntax.
Coach › 2. Explicitly say “Remember my birthday is March 14” and inspect the response.
           Check: Only the allowed month/day is saved, not an inferred age or identity.
Coach › 3. Inspect status, change the practice date using the lesson commands and inspect again.
           Check: Stored value matches the response without enabling learning or sync.
Coach › 4. Remove the synthetic birthday after practice; choose automatic greetings independently.
           Check: Removal and disabling animation differ; no fake profile data remains.
Coach › Troubleshooting
  Tip · Another person’s birthday was recorded → Correct it explicitly and verify the stored value.
  Tip · The date remains after disabling effects → Animation preferences and the stored date are independent.
Coach › Assignment: Set, inspect and remove a fictional date and record the final state.
        Acceptance: The practice date is removed and no year or extra personal data was added.

━━ Lesson 29 of 30 · A birthday song, and a language you choose ━━
Coach › Music and IP country lookup are off by default and confirmed separately. Enabled birthday music opens at most one automatic browser tab when you use chat that day. The local melody needs no sign-in. If autoplay is blocked, press Play. Closing the page does not affect work.
    koder celebrate music on
    koder celebrate music off
    koder celebrate locale --language en
    koder celebrate locale --language auto
    koder celebrate locale --ip
  Tip · Your chosen language comes first, then explicitly enabled local language counts. IP is only a weak hint. Country lookup exposes your public address to ipapi.co; an external music service receives its own visit data. Enter skips each choice.

0.5.1: Context limits and automatic compaction
1. Open koder setup → Context and output, or enter /context in chat. Use the actual endpoint limits for the model window and output ceiling. The model, endpoint and credentials are retained; example values cannot increase the provider's actual limits.
2. koder context set --trigger-percent 85 --target-percent 60 --keep-turns 6 changes compaction preferences. Defaults are on, an 80% trigger, a 60% target and four preferred recent turns.
3. koder context off / on controls automatic compaction. koder context reset restores only compaction defaults, retaining model limits and Headroom settings. Recent turns remain subject to the model window.
4. /context status --json shows the current chat's last request estimate, including input, tool definitions and output reserve. These are not billed tokens. Settings commands do not call a model.
5. With compaction off, Headroom and necessary protocol restoration remain independent. A request that cannot fit the hard window reports CONTEXT_BUDGET_EXCEEDED and retains disk history, original receipts, UNKNOWN protection, cost controls and cancellation rules.
Full walkthrough: docs/CONTEXT-CONTROLS.en.md


0.5.3: Native capabilities and MCP boundaries
1. Run koder mcp capabilities --json to inspect bounded coverage from Koder implementations, third-party runtimes and remote services. This inventory starts no MCP host, contacts no account and grants no permission.
2. In your project, run koder reverse status or koder reverse project ./src --json. Replace ./src with your JS/TS source directory. The Agent can also use native code_graph for imports, imported_by and symbols, then read the source to check the candidates.
3. Native code_graph reuses the Koder Reverse Worker without starting another MCP service, installing a graph database or executing target code. It provides bounded JS/TS file-level lexical navigation, not a complete call graph. Python and advanced Cypher remain with optional CodeGraphContext.
4. Use koder mcp presets --json for external presets and koder mcp doctor codegraph for launcher checks. A found launcher does not verify its version, behavior or desktop permissions. Windows-MCP, REA, SolidCraft and the official SDK retain their authors and licenses; remote services still require account authorization.
5. The 23 related local tests passed, including CLI run→scripted model provider→native Worker→read_file→model continuation. No paid model or Windows GUI was run in this round. These results do not establish complete replacement of CodeGraphContext, Windows-MCP, REA or SolidCraft.
