Koder CLI tutorial (text edition)
Run koder learn in a terminal to practise in a sandbox as you read.
This edition is written for macOS Terminal; for another system: koder learn --print --os powershell|cmd|mac|linux

━━ Lesson 1 of 30 · Welcome to Koder boot camp ━━
Coach › Hi, I'm the Koder coach. Across 30 lessons we'll take Koder from first launch to graduation, inside a throwaway practice project.
  · The tutorial creates a practice project in your temp folder: a small cart app with a planted bug, deleted when you finish.
  · Lesson 1 detects PowerShell, CMD, macOS or Linux and writes every command for it; you can switch with a number.
Coach › No model setup and no cost: the one doing the work is me, the 'coach model', with a pre-written script and limited acting talent. The edits and commands are real though, through the same kernel Koder always uses.
  Tip · Controls: Enter = next; b = previous lesson; q = quit any time (progress is saved); a number = jump to that lesson.
  Tip · Copy and paste with ⌘C and ⌘V. In a terminal Ctrl+C means cancel, not copy.
  Tip · Commands hard to remember? Run koder setup (or /setup in a chat) any time and set language, model and colours with the arrow keys or the mouse.
  (whispering) Relax. There are no exams here, only Easter eggs.

━━ Lesson 3 of 30 · Configure a model: give Koder a brain ━━
Coach › Koder can't think on its own; it needs a model. The easiest way is the settings screen:
    koder setup
        pick a provider and model with the arrow keys or mouse, paste the key; it can even open the key page
Coach › Prefer commands? Put the key in an environment variable and save only its name:
    echo 'export OPENAI_API_KEY=sk-your-key' >> ~/.zshrc
        into zsh's config (macOS uses zsh); every new terminal sees it
    export OPENAI_API_KEY=sk-your-key
        this window only
    koder model set --preset chatgpt --key-env OPENAI_API_KEY
        a preset; only the variable name is saved
    koder model set --preset local --model qwen3:8b
        local Ollama, no key
    KODER_MODEL=… KODER_BASE_URL=… KODER_API_KEY=… koder review
        environment variables, handy in CI
  Tip · koder model presets lists the available presets; koder model show prints the current setup with only the last four characters of the key.
  (whispering) Careful typing keys into commands: your shell history (~/.zsh_history, ~/.bash_history) remembers better than your ex. Paste it in koder setup instead: only the last four show, and it skips shell history, but the key is stored in plaintext in local configuration. Environment-setting commands may enter history too; redact keys before sharing.
Coach › Today the practice project uses the coach model, so this lesson is look-only. Set up a real one after you graduate.
  · You can run koder model presets right there to list them.

━━ Lesson 4 of 30 · First task: read the diff, decide ━━
Coach › cart.mjs forgets to multiply by quantity, so the test keeps failing. Let's have Koder fix it.
Coach › In the default interactive mode Koder shows the diff before editing: red lines starting with - go away, green lines starting with + come in. In this lesson it writes only after y; other answers cancel. --yes auto-approves ordinary edits.
  (whispering) Reading a diff is like reading a check-up report: green is new muscle, red is trimmed fat. Make sure nothing vital got cut before you sign.
  Tip · When Koder asks 'Accept this edit?', try typing n first to enjoy changing your mind; it will propose again, and then type y.
  · Hands-on: type a task, the coach proposes an edit; reject once with n, accept with y, then see the file change.
Coach › Practice asks at each step so you can see the controls. Normal use defaults to smart approval: low-risk commands and ordinary project edits run automatically. Sensitive prompts offer Always allow. Use /permissions execution status to inspect, ask for ask mode, or reset to revoke all settings.

━━ Lesson 5 of 30 · Command approval: run tests, stop shady ones ━━
Coach › After editing you'll want to run the tests. Running project code asks by default; low-risk checks such as node --version run automatically.
  Tip · Rule of thumb: allow it if you understand it, it stays inside the project and it can be undone. rm -rf, curl … | sh, git push --force: verify the source and exact effects before allowing them. Reject unknown scripts. Check official installers, licenses and verification information too.
  (whispering) Approve commands with the same care you give a food-delivery bill.
  · Hands-on: the coach asks to run node test.mjs (allow it), then a curl … | sh (reject it; even if you slip, the coach blocks it).
Coach › Command output goes back to the model as is, so it sees the test results and decides what to do next.

━━ Lesson 6 of 30 · Choices: Koder asks you too ━━
Coach › When a decision is yours, Koder stops and asks a multiple-choice question. Type the number and press Enter; a bare Enter cancels the turn.
  (whispering) Never answer 'whatever'. 'Whatever' is the hardest dish to cook.
  · Hands-on: the coach asks about a service fee with three options; answer with a number, or press Enter to cancel.

━━ Lesson 7 of 30 · Slash commands: gears, brakes and undo ━━
Coach › Lines starting with / are slash commands. They control Koder itself and never reach the model.
    /mode plan
        plan mode: read-only, proposes a plan
    /mode code
        code mode: states a plan, then edits
    /yes
        toggles auto-approve; the prompt gains a !
    /new
        starts a fresh session
    /lang zh
        switches to Chinese, /lang en switches back
    /review  /fix  /test  /scan
        run those commands inside the chat
    /help  /learn  /exit
        commands, this tutorial, quit (Ctrl+D works too)
  Try it · Type /mode plan to switch to plan mode  →  /mode plan
  Try it · Now type /yes to turn on auto-approve  →  /yes
  Try it · Good. Type /yes again to turn it off  →  /yes
Coach › Koder is running a command you regret. Fastest fix?
    1. Press Ctrl+C to cancel the turn
    2. Unplug the network cable
    3. Shout 'stop' at the screen
  Answer: 1。Right. Ctrl+C is the emergency brake; Ctrl+D is a polite goodbye.

━━ Lesson 8 of 30 · Read-only questions, pipes and scripts ━━
Coach › Just want answers without anything being touched? Use ask. It can list, read and search, but cannot edit or run commands.
  · Hands-on: ask anything; the coach reads package.json with read-only tools and answers. No approvals needed, since nothing can change.
Coach › In scripts, Koder behaves like any other command-line tool:
    git diff | koder ask "summarise this change"
        piped input is attached as extra material
    cat error.log | koder ask "what does this error mean"
        feed it a file
    koder run --yes --json "fix the lint errors" | jq -r .type
        --json prints one event per line for jq (brew install jq)
    echo $?
        the exit code of the last command
Coach › Exit codes: 0 done; 1 cancelled or a check failed; 2 a usage or model configuration problem.
  (whispering) Exit code 2 means 'check your setup', not 'it didn't try hard enough'.

━━ Lesson 9 of 30 · Code review with context ━━
Coach › review looks beyond the diff: it reads rule files such as AGENTS.md, recent commits and where changed functions are called, then lets the model verify with read-only tools.
  · Demo: the coach adds a discount function that yields fractional cents, then runs the real review pipeline, printing severity, file, line and a suggestion.
Coach › Each finding has a severity (high, medium, low), file, line and suggestion. Common forms:
    koder review
        review uncommitted changes, else the current branch
    koder review --base main
        compare with main
    koder review --format markdown --out review.md
        a comment ready for the PR
    koder review --fail-on high
        exit 1 on high findings, for CI
    koder review --fix --check "npm test"
        review, fix and test in one go
  · You can let Koder apply the fix, again with a diff and a y.
  (whispering) Being caught by Koder is fine. Being caught by your users in production is not.

━━ Lesson 10 of 30 · Fix until green: fix --check ━━
Coach › fix is a loop: run the check, hand failures to Koder, re-run, until it passes or attempts run out (3 by default).
  Tip · This time I'll press y for you; just watch it go round by round.
  · Demo: a check.mjs tests a count function; Koder gets it wrong once and right the second time, showing 'attempt 1/3' and finally 'Check passed'.
  (whispering) It missed the first time. Don't laugh; have you ever got it right first time?
    koder fix --check "npm test"
        fix until the tests pass
    koder fix "the home button does nothing"
        no check command: fix once from the description
    npm test 2>&1 | koder fix
        feed the failure straight in

━━ Lesson 11 of 30 · Flows and CI: agents in formation ━━
Coach › Put review, tests and fixes into one flow file and run the same thing locally and in CI. Here's a small one; let's run it:
  · Demo: a four-step flow: tests, a check, an ask step summarising them with {{step.output}}, and a celebration that runs only when the check passed.
    type
        shell, run, ask, review, fix or test
    when
        unit.failed, count.passed, always, failure
    {{step.output}}
        reuse an earlier step's output
    parallel
        run read-only steps side by side (shell, ask, review)
    approve: auto
        auto-approve, for CI
  Tip · Shell steps run through sh here; on Windows the same flow goes through CMD. For a flow that runs anywhere, stick to node, npm and git, like the node -e celebration above.
Coach › koder ci init writes a GitHub Actions workflow: every PR gets reviewed and commented on; comment /koder fix and it fixes and pushes back. Only repository members count; strangers can shout all they like.

━━ Lesson 12 of 30 · MoA: several models think together ━━
Coach › On hard problems one model can get stuck. MoA (Mixture of Agents) lets a few reference models advise first; the current model reads their advice privately, then acts.
    koder model add reference --preset custom --base-url https://your-provider.example/v1 --model YOUR_MODEL --key-env MODEL_API_KEY
        register reference models; as many as you like
    koder moa set --refs reference
        create a MoA preset
    koder --moa "refactor payments and add tests"
        run a task with MoA; /moa toggles it in a chat
    koder moa set --fanout every_step
        references are asked once per user turn by default; every_step asks each step, sharper and pricier
Coach › Can MoA reference models edit your files directly?
    1. No. They only advise; the aggregator acts, with your approval as usual
    2. Yes, the more the merrier
    3. Only the README
  Answer: 1。Right. References hold no tools at all; they can't even read a file.
  (whispering) MoA is like a meeting: everyone may speak, one person decides, and that person still has to ask you.

━━ Lesson 13 of 30 · Chat apps: command Koder from your phone ━━
Coach › Koder connects to Feishu, WeCom, WeChat, DingTalk, Telegram, Slack, Discord and WhatsApp. Each adapter needs the platform account and authorization. Follow setup and inspect its actual state; the WeChat flow depends on the service. Live-account acceptance remains pending for this preview; this tutorial does not connect.
    koder gateway setup feishu
        connect Feishu (wecom, dingtalk work the same way)
    koder gateway setup weixin
        configure WeChat through the available account flow
    koder gateway start --background
        receive messages in the background
    koder gateway status
        which platforms are online
    koder gateway pair K7Q2MX
        approve a new user
  Tip · Feishu, WeCom, DingTalk, Slack and Discord use long connections and need no public URL; the WhatsApp Cloud API needs the local port exposed through a tunnel.
  Tip · After koder gateway start --background the bots survive closing the terminal; when the Mac sleeps, so do they.
Coach › A stranger messages your bot on WeChat. What happens?
    1. They get a pairing code; only after you run koder gateway pair can they use it
    2. The bot starts editing code for them
    3. The bot cheerfully sends them your keys
  Answer: 1。Right. Direct messages need pairing by default and groups are off; before edits or commands it still asks in the chat and waits for a 'yes'.
  (whispering) Now you can fix bugs from the sofa. Whether that counts as overtime is up to you.

Coach › Installed copies check for updates in the background during interactive chats, at most once every six hours.     koder update auto off
    koder update --check
    koder update
Coach › Koder uses its built-in native adapters. The internal fallback is disabled and gray by default; ordinary use needs no extra engine. Check the selected model and protocol first. A network error never silently changes the engine, key, or billing endpoint.
    koder engine list
    koder model show
    koder engine use koder

━━ Lesson 17 of 30 · License and optional consent ━━

Coach › Permissions and data guide
        
        License: personal, noncommercial local use is free; commercial use and organizational deployment require separate written authorization, and the personal license grants no proprietary development or code-modification rights. New Koder-owned distributions use proprietary Koder-EULA-1.1; third-party and legacy GPL rights remain intact. Acceptance licenses the software and enables none of the optional capabilities below. Read: koder eula. Explicitly accept: koder eula accept.
        
        Model and network: tasks, selected file contents, retrieved memories and tool results may be sent to your configured model/API. Provider charges apply. A local model must actually be installed and running; selecting a preset does not make offline inference available. Use --key-env for a variable reference. A key pasted into provider configuration is stored locally in plaintext even when the display masks it.
        
        Computer scope: file read/write/search, network, browser, desktop, channel attachments and skill updates are checked separately. Full work mode selects visible disk roots, subject to actual operating-system permissions and capabilities. Review the executable, roots and remote actors before typing GRANT. Agreement acceptance or --yes grants no computer authority. koder permissions revoke withdraws future Koder computer-tool grants on this device; revoke OS permissions in system settings separately. Completed writes or sends are not automatically undone.
        
        Cross-device memory service: your configured Core endpoint
        After login, this account’s default shared space can synchronize conversations and memory across linked terminals, channels and devices. All members of a linked group can use linked private-chat memory; replies posted to the group are visible to its members. Link only conversations intended for sharing. Model API keys and computer grants are not memory-sync data. Sign out here: koder account logout. Forget the shared space: koder memory forget. Sign-out does not delete server copies; offline devices apply deletion after reconnecting.
        
        Preference learning
        Off by default. Extract communication preferences, explicit likes and work background from authorized conversations, retain their sources, and use them in later answers. A drink wanted today should not automatically become a permanent preference; inspect, correct or remove records.
        Turn off: koder memory learning off
        
        Daily state
        Off by default. Separately allow summaries of today’s mood, temporary needs and circumstances as short-term context. This is independent of lasting preference learning and does not diagnose a condition.
        Turn off: koder memory daily-state off
        
        Skill evolution
        Off by default. Allow skill-improvement candidates from authorized tasks and feedback, retaining provenance, checks and rollback records. This does not permit self-elevation, arbitrary software installation, changes to system security or bypassing tool approvals.
        Turn off: koder memory evolution off
        
        Proactive service and reminders
        Off by default. Allow greetings, work questions and reminders based on confirmed background, and associate your reply with the original question. Default quiet hours are 22:00–08:00 local time. Current terminal reminders need a running process and a compatible Core service. This does not authorize automatic messages to contacts or groups.
        Turn off: koder memory proactive off
        
        Daily reflection needs authorized sources, the relevant opt-ins, a valid account and a compatible Core host. The default model-call budget is four per day, using your configured API or local model and potentially incurring charges. A waiting-host or credential state means reflection has not completed. Turning learning off stops the corresponding future use; it does not erase history. Manage records with profile forget or memory forget.
        
        Local storage: new Windows memory prefers a writable D drive, falling back to a writable per-user location on C. Existing and explicitly configured locations are retained. Memory, installation and credential locations differ; inspect memory status / memory personalization status. Manually edit or roll back the assistant style without granting authority. Normal uninstall keeps configuration; --purge separately removes configuration. External memory and server copies need separate handling.
        
        Applications and MCP use the selected service’s API key or browser authorization. That service receives data submitted through the connection and sets its own fees and terms. Chats and agents in the same configured profile can reuse a connection; external writes still require tool approval. A stdio MCP server starts a local program. Imports are disabled by default; enable or test starts a connection. Use koder apps disconnect <id> or koder mcp disable <id> to stop use; revoke access with the provider to invalidate its tokens.
        
        Changing choices: the four optional features do not enable one another. Type ENABLE to turn one on, DISABLE to turn it off, and SAVE for a manual style edit. Read-only help and koder learn --print are available before agreement acceptance. Native Windows, live channels and multiple physical devices remain unverified for this preview; rely on observed connection states and results.
