# 让 Agent 调整自己的界面

本功能允许 Agent 根据当前用户的要求，调整 Koder 的界面和任务模板。修改的是本机配置中的受支持字段，内核、工具实现和权限规则不由这个接口改写。无需读取私有源码，也不会安装另一个宿主或重复添加 Skill。

本页对应 Koder CLI 0.6.1；安装后的 `koder help` 中应包含 `interface` 命令。旧包没有该命令时，不能仅凭本文认为已经支持。

## 直接描述想要的调整

进入 `koder` 或 `koder chat`，例如输入：

> 把 Koder 自己的界面改成青绿色、直角边框和紧凑布局；状态栏保留模型、状态、快捷键和上下文。再加一个“发布前检查”模板，包含读项目、运行测试、核对交付三步，每步写清验收点。直接应用。

Agent 使用同一条 `cli_interface` 工具链：读取当前配置 → 提出候选并返回终端预览与差异 → 应用该候选。要求“先看方案，不要应用”时，只应停留在候选。明确要求直接应用时，不需要再询问同一项许可。

可调整的项目：

| 项目 | 支持值或范围 |
| --- | --- |
| 主题 | `auto`、`dark`、`light`；显式 `KODER_THEME` 环境变量仍优先 |
| 强调色 | 蓝、紫、青绿、琥珀、玫瑰；使用预设可读配色 |
| 边框 | 圆角、直角、简洁；保留窄终端和 ASCII 回退 |
| 密度 | 紧凑或舒适；排队摘要分别最多显示 1 或 3 条预览，完整队列用 `/queue` 查看 |
| 状态栏 | 调整已有槽位顺序；通过 Agent 改槽位时须保留模型、状态和快捷键 |
| Todo | 默认展开或折叠；原有快捷键仍可用 |
| 任务模板 | 最多 20 个，每个 1–8 步，每步包含指令和验收点 |

模板是当前用户可编辑的普通任务草稿，不是高于用户的指令或可执行插件。它不能授予邮箱、电脑、发布或管理员权限。选择模板只填入输入框，编辑后仍需按回车提交；原有排队、引导和取消规则不变。

新增模板按 ID 合并，其他模板会保留。同 ID 更新原模板；删除必须在候选中明确列出 `removeWorkflowIds`，不会因为只提交一条新模板就清空已有列表。

## 找到新增模板

在空输入框按 `/`，或使用 `/prefill`，选择新模板；也可直接输入模型返回的模板 ID，例如：

```text
/prefill flow-publish-check
```

当前聊天会在工具应用成功后刷新外观，保留草稿和排队内容。其他窗口在下一任务重新加载配置。终端颜色能力不足时会使用原有回退，不声称所有终端有相同像素效果。

## 查看、关闭与回退

在系统终端运行：

```sh
koder interface status
koder interface off
koder interface on
koder interface rollback
```

聊天内使用 `/interface status`、`/interface off`、`/interface on`、`/interface rollback`。Setup 的“会话界面”中有“界面与任务模板”，可直接切换组装开关、强调色、边框和密度。

关闭后，Agent 不能继续提出或应用新界面候选；已有外观和模板保留。回退仍可用。工具最多保留最近 5 次应用前的界面快照，回退只恢复界面字段，不覆盖模型、邮箱、取消、预算或其他配置。

如果另一个窗口在候选生成之后改了界面，应用或回退会返回 `CLI_INTERFACE_CONFIG_CHANGED`。重新读取当前状态再生成候选，避免覆盖别人刚保存的设置。它不表示外部命令结果未知，也不会触发命令重放。

候选也可用 `koder interface preview <候选ID>` 查看，用 `koder interface apply <候选ID>` 应用。`--json` 返回结构化状态。候选未应用前不会改变正在使用的外观。

## 框架扩展与内核边界

这条能力只组装已经提供的界面槽位和任务步骤。没有任意 JS/Python 扩展、动态导入、任意文件路径或修改内核的字段。缺少底层工具、组件或新平台能力时，应明确说明需要产品实现，不能把一份模板称为新增了工具。

Agent 的组装接口限本机 CLI 任务；远端 gateway、ACP、agentd 服务任务、工作区隔离或只读模式不能通过它修改本机界面。取消、费用预算和原工具审批继续生效。普通用户对本机文件的系统权限，以及独立的既有维修功能，属于各自原有边界；本功能不宣称把用户电脑上的安装目录变成物理不可写。

## 网站与应用设计的改进

0.6.1 强化现有设计链路：先明确受众、主任务、页面结构和约束，再确定字体、间距、布局、组件状态、图像与动效。新建或大幅改版按原流程比较三种结构方向；小修、已有选定方向或用户明确缩小范围时保留原规则。

三份布局不能只改配色。`project_visuals audit` 读取当前项目实际源码，将文件路径、字节数、SHA-256 与待复核问题写到 `koder-delivery/<id>/design-audit.json`。交付结构图会附带这份检查，但结构图不是网站本身，不能代替真实预览。

源码检查不会给审美打分，也不把“未发现信号”判为功能失败。外部样式或框架可能承载相应实现。Agent 应核对问题、修改后重查，再在已授权浏览器中检查桌面/手机布局、主操作、键盘焦点和状态反馈。没有实际浏览器操作时，视觉与交互验收保持 `NOT_RUN`，不能声称已经完美适配所有平台。

小上下文模型按阶段获得设计工具，完整列表仍可通过已有工具目录发现；不会把所有设计资源重复塞入每轮上下文。
