# 编程与撰写指导

本页介绍0.4.1 更新。它保留 candidate.3 的交付检查，并在原有模型请求中加入与当前任务相关的工作方法。现阶段不宣称模型评分已经提升。

## 编程任务

修 bug 时重视复现、根因和相关调用；性能优化关注实际瓶颈、行为一致和前后测量；重构保留返回值、顺序、错误、取消和副作用；集成任务检查真实接口与失败路径。网页任务考虑信息层级、交互、窄屏和键盘操作，静态页不会被强加后端。

简短请求可以直接进入实现，不要求每个任务先写长计划。用户明确要求的鉴权、存储和接口不能用假按钮或 mock 页面冒充完成。已有源码、权限、预算和取消规则继续生效。

## 撰写任务

普通文稿会围绕读者、用途、事实和下一步行动组织。邮件、方案、改写、对比、更新说明和压缩稿分别采用适合的指导。改写须保留原意、限制条件和有依据的事实；不会为了显得具体而编造日期、价格、数字或承诺。

“改得更专业一些”等短续答可承接最近的相关用户要求；新任务优先。助手或工具文字不能建立新任务或授予权限。指导内容有长度上限，不把原始对话拼成系统指令。

内置 Humanizer 保留原来的固定上游版本和 MIT 声明。本次修复的是技能目录描述及英文改写匹配，未冒称上游技能更新。

## 发版来源

来源检查现在识别正式版、候选版和 preview 版本。变更记录的标题必须对应目标版本；其他版本正文提到它，不会被算成该版变更。子标题仍归属当前版本，下一版本或同级附录会结束当前范围。运行包信息只能证明版本身份，不能证明新增功能。

## 验收边界

这些指导复用原有模型请求，正常最多增加 1,800 字符、紧凑模式最多 800 字符，因此会增加少量输入 token，但不新增模型或工具调用。原交付检查的修复预算仍按原规则运行，没有新增引擎、评分模型、记忆库或权限入口。

本地测试检查真实 CLI 发出的请求、来源解析、任务切换和权限边界；使用固定回复的测试不能证明真实文稿或代码变好。原 C01–C07、W01–W05 短提示仍须在同模型档复测，才能对外宣称评分提升。安装更新和 Windows 图形操作另行验收。另见[当前任务交付说明](TASK-DELIVERY.zh.md)。
