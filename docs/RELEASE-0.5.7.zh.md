# Koder CLI 0.5.7

本次修复邮箱会话所有权与锁竞争：同一会话并发打开时复用一个邮箱实例；关闭一个后台会话不会关闭其他会话的邮箱。后台检查遇到正在执行的邮箱操作会跳过本次检查，前台操作可等待并取消；同类错误不会在同一监视器中反复刷屏。

绑定时验证只读收件箱访问；对话查信默认刷新。发件补充 Date 邮件头，明确被 SMTP 拒绝的请求可在重新批准后重试。提交后确认丢失仍保留 UNKNOWN，不自动重发；SMTP 接受不等于对方已收件。

同时修复网站交付检查误扫自动生成的布局评审页、沿用已确认布局仍要求重选的问题，以及“不发邮件”误选办公模式、隐藏代码工具的问题。Todo 负责人填写错误时会说明有效值。项目自己的 verify/check 验证脚本现在可凭真实成功回执计入交付检查；源码已验证无需修改时，允许保留测试和文档修复，不强迫制造无关代码改动。成功验证后继续只读检查时，若完整快照证明工作区文件内容、权限与身份均未改变，可保留验证结果；扫描不全、后续写入、失败和 UNKNOWN 仍须重新验证。明确的无修改说明可使用“未做任何修改”等自然表达，仍须有实际读源、工作区未变和测试通过证据。被拒绝而未执行的命令不再误算成修改。

升级：运行 `koder update`，再用 `koder --version` 核对 `0.5.7`。新装使用本次 Release 的 Windows PowerShell/CMD 或 macOS shell 安装器。详见[邮箱使用与排查](MAIL-RECOVERY.zh.md)。

验收分层：自动化回归、打包运行与隔离 macOS 更新结果在 `ACCEPTANCE-RESULTS.json`。真实 MiniMax-M3 已用于多步审计、网站流程及原生邮件工具调用；长任务及网站流程包含恢复续跑，保留此前失败记录和测试驱动限制，不宣称一轮盲测通过或模型质量评分提升。需求问答使用预先声明的脚本测试用户回答，不代表真人设计确认。邮件采用合成账号和本地 TLS 服务器，未验证真实 163 服务商投递。Windows 实机、MCP 图形操作和系统通知显示由 beta 专员继续验证；macOS 锁屏原生组件仍是未签名候选。本轮只更新 GitHub，官网未改。

前台查信不再提前消耗待提醒问询及每日额度；后台读取通知遇到锁竞争时保留已生成问询，后续继续交付。修复任务中的“若无需修改”等条件句不会再把整轮误判成只读。

明确只读的网站核验不再被误判为修改任务、强求源码变化；条件式修复仍须提供交付证据，禁止修改某个文件也不会取消其余修复范围。
