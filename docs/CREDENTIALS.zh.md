# 账号、密码和令牌：输入与使用教程

**首次执行任务前：**运行 `koder login`，通过系统浏览器或二维码完成设备授权，详见 [KARMEN 登录教程](ACCOUNT-LOGIN.zh.md)。KARMEN 会话、模型 Key、邮箱和电脑权限分别配置；没有登录会话的无头任务返回 `LOGIN_REQUIRED`。

适用版本：Koder CLI 0.5.14。Ubuntu 24.04 和 26.04.1 Desktop amd64 使用相同流程。

## 先确认进入了正确版本

在 Ubuntu 终端执行：

```bash
export PATH="$HOME/.local/bin:$PATH"
koder --version
koder
```

版本应为 0.5.14 或后续版本。`koder` 会进入对话；`koder activate` 只启动后台服务。旧版出现“轻量 CLI 不收集账号密码”时先运行 `koder update`，退出并重新打开会话。

## 支持什么

| 用途 | 输入位置 | 实际用途和保存位置 |
| --- | --- | --- |
| 邮箱账号和授权码 | CLI 专用隐藏输入 | 验证 IMAP/POP3 与 SMTP 后存入既有受保护邮箱存储；不会因此自动发邮件或开放模型阅读 |
| GitHub 令牌 | CLI 专用隐藏输入 | 验证并写入既有受保护 GitHub 连接；上传和编辑项目仍是后续操作 |
| 模型 API Key | CLI 专用隐藏输入 | 写入指定已配置模型的本地配置文件，权限 0600；不是密钥环加密存储，需另跑连接测试 |
| 网站/应用账号密码 | CLI 专用隐藏输入 | 当前任务中的临时加密句柄，用于 Ubuntu 可识别的登录控件；不建立通用永久密码库 |
| Ubuntu 管理员密码 | 系统 sudo 提示 | sudo 自己读取本机终端；Koder 不保存、不转发该密码 |

“支持输入”不代表任何服务都能用普通密码登录。需要 OAuth 的 Outlook/Microsoft 365、验证码、硬件密钥等仍遵循服务自身的登录流程。

## 在对话中绑定邮箱

1. 输入：`帮我绑定 163 邮箱，随后检查收件是否正常。`
2. Koder 显示用途和服务名。输入 `use` 允许进入本次凭据输入；直接回车取消。
3. 在“账号”提示处输入完整邮箱地址，在“邮箱客户端授权码”提示处输入客户端授权码。内容隐藏，不进入普通聊天历史。
4. 使用前还会显示接收、发送服务器和端口，例如 `imap.163.com:993`、`smtp.163.com:465`。确认无误后输入 `use`。
5. 只有收发连接实际验证通过才报告绑定成功。失败时保留原因码；不会循环使用同一凭据。
6. 运行 `koder mail status` 检查状态。阅读邮件内容、发送邮件、后台监控分别使用既有授权入口。

也可以直接运行 `koder mail setup 163`。QQ、Gmail、126、iCloud、阿里企业邮箱、Spacemail 使用既有预设；自建服务使用 `koder mail setup custom` 并核对服务商公布的 TLS 设置。不要把授权码粘贴在普通对话、命令参数或截图里。

## GitHub 与模型密钥

- 对话示例：`绑定我的 GitHub 令牌，先不要上传项目。` 按隐藏提示输入令牌，并确认 `https://api.github.com`。绑定后查看 `koder github status`，再下达具体仓库任务。
- 模型示例：`更新已配置的 default 模型的 API Key。` 确认显示的完整 API 地址和模型配置名称。修改配置不代表当前回合已换模型，也不代表远端测试成功。重新选择模型或开启下一会话，再运行 `koder model test`。
- 首次添加模型仍可使用 `koder setup` / `koder model`。不把密钥放在网站页面、项目文件或示例代码里。

## Ubuntu 网站和应用登录

1. 先打开目标应用或网站的真实登录页面。
2. 运行 `koder permissions status`，按既有电脑授权菜单允许目标桌面操作；密码输入本身不会自动开启桌面权限。
3. 在 Koder 对话说：`帮我登录当前页面，密码通过隐藏输入提供。`
4. Koder 先观察实际窗口，识别账号控件和受保护密码控件，再请求凭据。
5. 使用前核对显示的窗口、目标进程和控件。确认后填入；填入回执只代表已填入，尚未证明登录成功。
6. Koder 必须重新观察页面，再继续必要的点击和结果核对。遇到验证码或不支持的控件会明确说明，请在真实页面完成该步骤。

依赖原有 Ubuntu AT-SPI 驱动。没有桌面、没有授权、控件不可访问或快照失效时不会声称已填入。Canvas、自绘登录框、远端嵌入页面不保证支持。普通 `computer_act` 仍不接收密码。Windows/macOS 的普通绑定输入可用，但这次新增的私有 GUI 填充仅接入 Ubuntu 驱动。

## Ubuntu 系统操作

例如：`检查系统时间配置，确实需要管理员权限时再提示我。`

需要管理员权限时，Koder 先展示具体程序绝对路径和参数。输入 `use` 只批准这条操作；随后系统可能显示 `[sudo] password for ...`，在此输入 Ubuntu 本机密码。sudo 通常不显示星号，这是正常的。Koder 不使用 `sudo -S`，不把密码写到 stdin 管道、环境变量或脚本里。验证失败、取消、超时会有状态回执；结果未知时先核对，不自动重跑。

系统仍决定账户是否有 sudo 权限；该功能不会修改 sudoers，也不会把普通用户自动变为管理员。后台 agentd 没有连接前台终端时，不能自行输入管理员密码。

## 取消、过期与后台会话

- 凭据属于当前窗口、当前根任务，有效期 15 分钟；开始新任务、关闭会话或使用一次后失效。
- 拒绝用途确认不会执行操作。隐藏输入时 Ctrl+C、输入结束或任务取消会恢复终端输入区。
- `--yes` 不会自动提供凭据，也不会替用户确认目标。无头/CI/管道模式缺少凭据时明确需要输入。
- agentd 复用同一机制，由连接的前台隐藏输入；断开、取消不继续使用未批准的凭据。
- 绑定完成后的邮箱和 GitHub 凭据遵循各自原有持久存储和解绑流程。模型密钥遵循既有私有配置文件机制。

## 排查表

| 提示 | 处理 |
| --- | --- |
| `LOGIN_OR_SECRET_REQUIRED` | 在交互终端运行；CI 使用已有绑定/环境配置，不靠 `--yes` 提供密码 |
| `LOGIN_HANDLE_EXPIRED_OR_WRONG_TASK` | 重新发起当前任务的隐藏输入，不重用旧句柄 |
| `LOGIN_PRIVATE_FILL_UNAVAILABLE` | 当前驱动没有私有填充能力；直接在真实页面输入 |
| `COMPUTER_PERMISSION_REQUIRED` | 检查电脑授权；不能用账号密码绕过 |
| `COMPUTER_SNAPSHOT_STALE` | 重新观察目标窗口，再确认本次使用 |
| `OAUTH_NOT_CONFIGURED` | 当前服务需要 OAuth，普通密码无法替代 |
| `LOGIN_MODEL_CHANGED` | 模型地址在确认期间改变，重新核对地址再输入 |
| `LOGIN_RESULT_UNKNOWN` / `COMPUTER_ACTION_UNKNOWN` | 先检查连接或页面实际结果，不自动重复提交 |
| `SYSTEM_COMMAND_INTERRUPTED` | 系统命令可能已开始，先只读核对结果 |

验收区分源码测试、隔离 Ubuntu GUI、真实网站/邮箱及物理桌面。真实服务登录结果取决于权限、账号和服务侧验证，不能用测试夹具成功代替。
