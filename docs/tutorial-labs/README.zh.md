# 教学练习文件与实验手册

180课扩展版另见[12单元实验手册](academy-labs.md)。本页保留原30课的8个基础实验，编号与旧教材一致。

适用基线：Koder CLI 0.4.11。文件是本课程专用合成练习，不包含账号、凭据或真实客户数据。先复制到自己的独立项目目录，不直接改安装树。只有普通 Node 程序，没有第三方依赖；运行 Node 练习需要可用的 Node。Koder 自带的交互教练不要求你为这些扩展作业另外安装 Node。

## 实验 1：修复购物车（第1、4、5、9、10课）

1. 复制整个 `cart-lab` 文件夹到 `Koder Projects` 下的测试目录，用终端进入该目录。
2. 运行 `node --test cart.test.mjs`。期望 **2通过、2失败，退出码1**：数量被忽略，750得到350，0件得到200。这是故意植入的教学bug，不是产品验收失败。
3. 先写下根因，再对Koder说：“修复cart.mjs的总价，保留所有测试，按数量计算，运行node --test cart.test.mjs。”需要真实模型配置；未配置可自己修改。
4. 查看差异；只需修复reduce中的计算，不删测试、不硬编码答案。
5. 再运行相同命令。期望 **4通过、0失败，退出码0**。
6. 答案在 `solutions/cart.mjs.txt`，先独立作答再对照。保存修前/修后日志与diff。

## 实验 2：流程失败分支（第8、11课）

1. 在故意有bug的副本里先读 `flow-lab.json`。shell步骤用 `run` 字段，不是 `command`；`when` 引用具体步骤状态。
2. 运行 `koder flow run flow-lab.json`，按提示检查许可/批准。此示例只有本地shell，不调用模型、不发布。
3. 期望unit失败，ready跳过，blocked通过（内部输出 `CHECKS_FAILED`），整体非零。
4. 在修好后的独立副本里执行同一流程；期望unit、ready通过，blocked跳过，整体0。
5. 示例不设置 `continueOnError`，因此unit失败会使流程非零。若设置为true，当前运行时可容忍该步失败并整体返回0；CI关键检查不要设置它。shell也可能有写操作，不能仅因“shell”类型就认定安全。

## 实验 3：标准输入与退出码（第8课）

`node stdin-producer.mjs 250` 输出一行后等待250毫秒才结束。最大允许5000毫秒，非法值退出2。它不调用Koder，也不消费模型额度。

确认生产者后，再在有授权模型的环境测试：`node stdin-producer.mjs 250 | koder ask "总结输入" --stdin`。对照不带 `--stdin` 的显式提示词调用，核查后者不把无关管道内容当输入。命令结束后立刻读取退出码：PowerShell用 `$LASTEXITCODE`，CMD用 `echo %ERRORLEVEL%`，macOS/Linux用 `echo $?`。不要在检查退出码前运行别的命令。

CI消费者不能只检查stdout非空；同时核对退出码、JSON格式与任务要求。没有模型时仅执行生产者检查，并标Koder模型步骤NOT_RUN。

## 实验 4：多项目与多窗口（第2、15、19课）

建立两个独立目录A和B，各放README，使用合成标记 `TRAINING-A-ALPHA` 与 `TRAINING-B-BETA`。分别在目录内开启Koder。A输入标记后，到B问A做过什么，再回A续聊。保留各自路径、会话名和输出；B不应自动获得A的私有任务事实。显式共享笔记另按范围核查。不要拿真实秘密当探针，结束后只清理自己的练习目录。

## 实验 5：应用、邮箱与GitHub（第18、20、21课）

先写计划，只有存在已授权账号/桌面时才执行：

| 场景 | 正例证据 | 负例/恢复 |
| --- | --- | --- |
| Windows-MCP | doctor、实际工具调用、自己测试窗口的读回 | 撤权后不点击；驱动缺失如实说明 |
| 163收发 | 收信状态、最终内容确认、SMTP接受、测试收件箱读回 | 取消不发送；UNKNOWN先核对 |
| GitHub | 绑定身份、选定README、提交SHA、read读回 | 拒绝无写入；分支变化先重读；未知结果reconcile |
| 后台提醒 | enabled/activated/running、检查与通知回执 | 安静时段、日上限与关闭检查 |

发送测试只用自己的测试地址，GitHub仅用私有测试仓库。不得把 `example.com` 占位地址直接当收件人。没有账号/设备就交计划，状态NOT_RUN，不编真实成功。

## 实验 6：撰写质量与来源（第26、30课）

A题：“用中文写Koder CLI产品介绍，约800字，面向技术决策者，保存intro.md。”验收主文件720–880个中文字符附近的目标范围（以具体任务/门禁计数口径为准），覆盖问题、收益、风险、接入、限制和下一步。聊天收尾不是主文稿。

B题：“写一封早期用户更新邮件：preview.22。”不给变更表。先查真实release/CHANGELOG/ACCEPTANCE；没有资料时明确“以下是既有能力说明，不是本版新增”。不得编“本版新增”归因。历史版本不能套用当前0.4.11功能。

C题：把有据比较稿压成短文，保存前稿路径和哈希，逐条核新稿事实是否来自前稿。未知竞品定价不编数字，写公开信息有限或查官方材料。质量验收与API连通性分开；本教程不宣称新的盲测评分。

## 实验 7：网站预览和交件（第6、30课）

让Koder在 `site/` 做三个不同结构的静态方案。先打开预览再选择；在同一聊天使用 `/preview start --directory site`、`/preview status`、`/preview stop`。独立系统终端 `koder preview start --directory site` 是前台服务，用Ctrl+C退出；另一个进程的status不拥有它。

框架应用先阅读项目README启动开发服务器，再连接实际本地URL；不要把程序安装目录或整个用户主目录当预览根。检查手机宽度、焦点顺序、键盘、链接与表单空状态。没有后端的表单须标演示。要求生成 `project-map.html`，其目录、入口、模块和数据流必须来自当前文件。

## 实验 8：交付审计（所有课程）

复制 `acceptance-template.md`，填写版本、范围、前置、实际命令、退出码、证据路径、结论和清理。将本地脚本、真实模型、Windows GUI、真实邮箱/GitHub、公开部署分开。PASS需要已执行证据；FAIL保留原输出；NOT_RUN说明缺什么；UNKNOWN先对账。完成练习不是授权发版。
