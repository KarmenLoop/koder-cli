# Koder 180课 · 12个单元实验手册

[进入课堂](../courses/index.zh.html) · [课程大纲](../courses/README.zh.md) · [验收模板](acceptance-template.md)

每个单元15课，围绕一个连续项目。前几课完成最小可运行片段，中段加入边界，最后一课交件复盘。下面提供准备、执行顺序、检查和开发者加练。示例全部使用合成数据；阅读本文件不会执行任何命令。

## 统一准备：把练习留在自己的目录

1. 将教材ZIP解压，保留`docs`及其子目录。不要直接在压缩包预览里运行脚本。
2. 新建自己的`Koder Projects/academy-work`目录。将需要的练习复制进去；原始教材保留作对照。
3. 运行`koder --version`，将结果记入`learning-log.md`。未安装CLI也能阅读网页课堂；不要把课程候选当成已发布更新。
4. 需要JavaScript实验时，在终端运行`node --version`。示例按Koder当前Node要求（22.21或更新兼容版本）编写。没有Node先读代码，记录“运行未验”，不必为阅读安装软件。
5. `cd`到练习目录后再执行。路径有空格时加引号。Windows PowerShell、CMD、macOS命令不要互相混用；本手册的`node`命令三者相同。
6. 每次记录：输入、输出、退出码、变化文件、未验事项。PowerShell查看`$LASTEXITCODE`，CMD查看`echo %ERRORLEVEL%`，macOS/Linux查看`echo $?`。

学习节奏建议：10分钟阅读，10分钟跟做，10分钟变更输入与复盘。单元项目另留约90分钟，复杂项目可以分几天，不把建议课时当执行时限。

## 单元01 · 第1–15课：第一次可核对的编程任务

**项目：购物车总价修复。** 复制`cart-lab`到工作目录，先阅读README和测试，不先看`solutions`。

1. 在副本运行`node --test cart.test.mjs`。应出现2个通过、2个失败，退出码1；失败正是课程起点，不要删断言。
2. 在Koder任务里要求：“请定位购物车总价与折扣的错误，只修改相关逻辑，保留测试。先说明准备改哪几个文件。”
3. 查看实际差异，确认改动对象是副本。审批时先拒绝一次，检查文件未变；再授权正确改动。
4. 重跑同一条测试命令。通过条件是4个测试全部通过、退出码0，不是模型说“修好了”。
5. 再加入数量0和多商品的输入，自行判断预期值，检查修复没有只写死答案。

**开发者加练：** 比较金额“分”与浮点“元”的处理。为什么折扣后需要明确舍入规则？把这个规则写在接口契约中。

**交件：** 修复差异、红绿两份日志、一个额外边界测试。参考答案在`cart-lab/solutions/cart.mjs.txt`，只在完成独立尝试后比较。

## 单元02 · 第16–30课：配置地图与安全交件

**项目：个人工作台说明书。** 参考已有[基础实验](README.zh.md)，建立`workspace-map.md`，不填写真实密钥。

1. 用`koder help`记录本机实际命令；用`koder --version`记录版本。将“文档有”与“本机可用”分成两列。
2. 用Setup查看模型、会话输入方式和权限，只记录状态及用途，不截图授权码。
3. 将邮箱、GitHub、浏览器、桌面列成四行。每行写明是否绑定、授权范围、一个只读检查、一个需单独授权的写操作。
4. 选择一个未配置功能，练习如何描述缺少条件。写“未绑定/未验”，不要复制别人成功截图当证据。
5. 保存一份可分享的脱敏副本；确认其中没有邮箱正文、Token和个人绝对路径。

**开发者加练：** 画配置→凭据存储→权限检查→执行→回执的关系图。标出哪个环节负责拒绝，哪个环节仅展示状态。

**交件：** 配置地图、权限说明、一个可复现诊断记录。到第30课完成的是基础训练，后面150课继续拓展。

## 单元03 · 第31–45课：可搬迁的终端工作区

**项目：整理一个小报告项目。** 目录包含`input/`、`output/`、`notes/`与README。

1. 在副本写`input/report.txt`，内容使用虚构项目名。用本机Shell列目录和读文件，记录工作目录。
2. 把目录复制到包含空格的路径，例如`academy work copy`，重新运行读文件命令。修正路径引号，不改成依赖旧绝对路径。
3. 将教材的`stdin-producer.mjs`复制到该副本。运行`node stdin-producer.mjs 20`，应输出合成报告并正常退出。
4. 运行`node stdin-producer.mjs 5001`，应退出2且不输出报告；这是边界拒绝演练。不要通过删除上限让它“通过”。
5. 分别打开两个自己的终端，进入两个练习目录，记录当前目录、会话与文件归属。不要操作正在运行其他任务的进程。

**开发者加练：** 区分工作目录、用户目录、配置目录和进程环境。将这些值显式注入测试，避免依赖开发者电脑。

**交件：** 可复制的目录、跨路径运行记录、输入边界记录、两个窗口的任务归属图。

## 单元04 · 第46–60课：把模糊请求变成可执行委托

**项目：同一需求的三版任务卡。** 题目是“做一个读书会报名页面”，事实使用合成活动，未知日期标待确认。

1. 第一版只写题目；第二版补访客、主要动作、内容范围；第三版加入成功标准与不能做的事。比较三版中哪些变化能够被验证。
2. 建立事实表：已给定、待确认、可以默认、禁止假设。把“已经上线”“报名成功”放在必须有回执的一列。
3. 如果有自带Key并愿意调用模型，可在同一模型档位运行其中两版，记录版本、用量、耗时和结果；没有Key则只做任务设计，不能填模型成绩。
4. 练习中途补充一条要求，观察它是融入当前回合还是排队。保留界面提示及任务结果，不以文档声明替代观察。
5. 用“停下”取消自己的演示任务，检查已经完成的文件是否保留、未批准动作是否未执行。

**开发者加练：** 从任务卡提取输入、终局条件、预算、取消和UNKNOWN状态。解释为什么模型选择与执行引擎不是同一个配置。

**交件：** 三版任务卡、对比表、实际执行或NOT_RUN记录、一次取消恢复说明。

## 单元05 · 第61–75课：红绿修复与性能解释

**项目：购物车修复包＋合成汇总性能实验。** 先完成单元01，再复制`academy/benchmark.mjs`。

1. 保留购物车错误基线，从失败断言定位原因。每次只改一个有证据的点，重跑原测试。
2. 运行`node benchmark.mjs`。脚本先验证两种算法结果完全一致，再输出本次耗时。
3. 阅读慢版：每个用户扫描全部订单；阅读快版：先按用户汇总，再查询。分别写出时间复杂度与额外内存代价。
4. 修改副本中的用户数、订单数，保留原文件。重跑并记录机器与数据量；不要把单次耗时比值写成产品性能承诺。
5. 把性能改动做成小差异，并补空数据、重复用户标识等你能够定义预期的边界。

**开发者加练：** 区分优化、重构和修复。只有性能变化时应保持行为契约；修复业务语义则要说明新旧预期差异。

**交件：** 可运行测试、瓶颈解释、测量原文、权衡与回退说明。没有实测时只给复杂度推导。

## 单元06 · 第76–90课：社区读书会报名页

**项目：本地可预览网站。** 教材提供`academy/reading-club.html`最小演示页，双击打开即可；它不会向服务器发送报名信息。

1. 阅读页面与源码，找到语义标题、字段标签、错误区和状态区。点击空表、填写错误邮箱、再填写合成邮箱。
2. 切换“成功演示”“网络失败演示”“结果未知演示”，分别提交。应看到不同文案，失败时姓名和邮箱仍保留。
3. 用相同内容制作海报式、流程式、编辑式三张草图，解释阅读顺序差异。选一案再实现，不只换三种颜色。
4. 只用Tab、Shift+Tab和Enter走完整个表单。缩放文字，检查窄窗口下是否遮挡提交按钮。
5. 接真实后端前保持“本地演示”标记。若以后获准部署，另记录站点、构建产物、预览URL、正式URL及回退版本。

**开发者加练：** 将表单状态画成`idle → submitting → confirmed/failed/unknown`。说明为什么“未知”不能直接重发，为什么前端校验不代表服务端接收。

**交件：** 三案比较、选案理由、可打开页面、状态检查、键盘与三种宽度检查记录。没有账号时不要求上线。

## 单元07 · 第91–105课：有归属检查的待办域

**项目：从业务域扩展到接口设计。** 复制`academy/todo-domain.mjs`和`todo-domain.test.mjs`到同一目录。

1. 运行`node --test todo-domain.test.mjs`，应有6个通过、0个失败，退出码0。
2. 阅读`create/read/complete/list`四个入口，找出身份、标题与所有者的检查位置。
3. 在副本加入“删除待办”功能。先写测试：本人可以删除，他人不能删除，删除后读取失败；再实现。
4. 写一份REST映射表：方法、路径、输入、成功状态、失败状态。不要仅因为域测试通过就声称HTTP服务已可用。
5. 进阶再接SQLite与JWT：保存数据库迁移、鉴权与越权测试。每增加一层都记录真实执行，不能把内存示例叫持久化系统。

**开发者加练：** 讨论不存在与无权访问统一报错的取舍；区分身份认证和对象授权。返回值是副本，尝试修改返回值验证存储不被外部引用改变。

**交件：** 域逻辑测试、REST设计、数据迁移计划。当前教材附带的是内存教学域，不包含已实现JWT、数据库或生产API。

## 单元08 · 第106–120课：让验收能发现错误

**项目：独立检查包。** 使用购物车、待办域和标准验收模板，无需付费模型。

1. 将一条断言故意改错并运行，确认测试能失败；恢复断言。若怎么改都绿，先修测试入口。
2. 写三层清单：纯逻辑、CLI/本地服务、真实账号设备。将每条检查归到一层。
3. 复制自己的练习到新目录再运行。对比是否偷偷依赖旧路径、环境变量或缓存。
4. 人为输入坏参数，记录退出码与错误；不要只检查stdout是否有“成功”。
5. 为Windows、macOS各留一个实际运行栏。仅在本机平台执行就只填该栏，另一栏写NOT_RUN。MCP工具列表出现与图形操作成功也分开记。

**开发者加练：** 给一次偶发失败保留原日志，提出可检验假设，再做有界重复。禁止单纯多跑直到绿后删除失败证据。

**交件：** 测试入口、fixture版本、命令、退出码、失败样本、未验层与恢复方法。

## 单元09 · 第121–135课：有事实来源的内容包

**项目：虚构StudyNote产品的介绍、更新邮件、对比稿与压缩稿。** 读取`academy/source-cards.json`。它是练习素材，不能作为Koder功能或性能证据。

1. 将事实卡分成“给定事实”与“未提供”。写作只引用前者；没有版本变更清单时明确不声称本版新增。
2. 给技术决策者写约800字介绍。先写问题、收益、集成成本和限制四段提纲，再完成正文。
3. 写更新邮件，故意不给新增清单。选择明确披露的写法，而不是将存量功能改称本版新增。
4. 对比练习只比较已给出的事实；价格、竞品能力没有材料时标公开信息不足，不填看似精确的数字。
5. 将对比稿压成短文，逐条核对短文事实是否都在上游稿件里；保存上游路径或内容哈希。

**开发者加练：** 将字数统计对象固定为实际成稿文件，聊天收尾另计。用一篇合格成稿＋短总结复现“量错对象”假红，再给正确判定。

**交件：** 四份文稿、事实对应表、原稿与压缩稿关系、未核实项。自评准确性、读者匹配、结构、可行动性和可追溯性各0–2分。

## 单元10 · 第136–150课：数据、PPT与邮件草稿

**项目：合成订单周报。** 使用`academy/orders.csv`与`academy/mail-samples.json`，不需要绑定真实邮箱。

1. 保留CSV原件，建立清洗副本。按`id`识别重复A3，记录去重规则；不要把缺失金额改成0。
2. 只统计已完成且金额已知的唯一订单。应得1700分，即17.00元；pending的800分不计入，A4缺失金额单列，0金额A5保留。
3. 写一页周报，明确这是不含A4的已知金额小计，不能冒充完整营业额。
4. 用三页PPT表达“发现→证据→下一步”，每页只有一个主结论。图表标明单位、口径和缺失值。
5. 给5封合成邮件分类：真人业务、广告、系统/验证码、可疑内容等；分类有不确定性，记录理由，不自动删除或回复。
6. 起草给负责人发送周报的邮件，收件人用example.com。停在草稿。真实发送必须用获得授权的账号与指定收件人，并读取真实回执。

**开发者加练：** 验证“绑定成功≠SMTP发送成功”“邮件监控运行≠每封立即通知”。设计去重、安静时段、网络失败与重连的可观察记录。

**交件：** 清洗规则、表格、周报、PPT提纲、邮件草稿和分类解释；真实发信与收信默认NOT_RUN。

## 单元11 · 第151–165课：一个可适配的工具Skill

**项目：为购物车练习写一个本地Skill。** 创建自己的Skill目录和`SKILL.md`，先用只读工具学习目录结构。

1. 写清when-to-use、输入、步骤、验证与失败边界。不要要求宿主忽略权限或把课程文档当用户指令。
2. 把示例和测试放在资源目录，正文用相对路径引用。加入一个不存在资源的检查，确认失败提示可理解。
3. 对照Koder当前[可移植Skills说明](../PORTABLE-SKILLS.zh.md)，确认发现路径、frontmatter和资源读取；Codex/Cursor/WorkBuddy来源不能自动证明跨宿主运行通过。
4. 如有本地MCP演示服务，先读工具schema，再进行无副作用调用；命名成功、进程启动、协议握手与真实业务执行分别留证。
5. Windows MCP需要真实Windows图形会话才能验收点击输入。没有Windows时只完成配置核对，明确NOT_RUN。
6. 为JIT或Headroom相关练习保留基线和原始结果，解释工具视图变化如何不改变权限权威；没有对照不能宣称提分或节省比例。

**开发者加练：** 设计一个“工具声称成功但没有产物”的假回执，要求交付检查拒绝它。经验记录允许NO_ENTRY，不能一次成功即自动升级为通用知识。

**交件：** Skill、资源、宿主兼容表、调用日志和权限边界。发布第三方内容前单独检查许可证与归属。

## 单元12 · 第166–180课：协作、发布与毕业答辩

**项目：交付前面任一项目的完整候选。** 可以选报名页、待办域或内容工具；没有GitHub账号仍能完成本地Git练习。

1. 固定基线，读取工作区差异，只提交自己负责的文件；提交信息具体说明行为变化。
2. 如有获准GitHub连接，先读取账号与目标仓库，再进行指定范围修改。上传后读回分支、提交SHA与文件，不能只看本地提交成功。
3. 生成交件目录，包含入口、README、依赖版本、检查、运行说明、许可、限制、回退步骤。秘密和私人数据不入包。
4. 将版本、安装链接、更新说明与教程做对应表。预览部署和正式域名分别检查；没有发布权限保留候选。
5. 制作项目结构图：入口→组件/模块→数据→外部服务→交付物，并标出每条箭头的关系。
6. 答辩用5分钟说明：为谁解决什么、实际完成什么、怎样验证、哪些没做、失败后如何恢复。现场改一个小需求并重新验证。

**开发者加练：** 模拟版本回退只操作自己的练习目录。对并发编辑、外部写入UNKNOWN、安装中断与旧配置兼容各给一条策略，不必伪造真实平台验收。

**毕业交件：** 可打开或运行的项目、源代码、完整讲述、测试记录、结构图、限制与回退。阅读180课或勾选180项不等于通过毕业答辩；用实际交件说明掌握程度。
