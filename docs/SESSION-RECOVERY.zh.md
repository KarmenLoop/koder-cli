# 旧会话恢复与“前次操作结果仍待核实”

适用 Koder CLI 0.5.17 及以上，Windows、macOS、Linux 共用会话逻辑。以下斜杠命令在 `koder >` 输入，不是在 PowerShell 或 Bash 中输入。

## 先确认版本和入口

在系统终端运行 `koder update`，升级后运行 `koder --version`，应为 `0.5.17` 或更高版本。关闭旧 Koder 窗口后重新运行 `koder`；如需指定原会话，使用原工作目录与 `koder chat --session default`。请勿删掉配置或会话文件。更新失败可使用[固定版本安装器](INSTALLATION.md)。

0.5.17 修复旧会话中缺少状态字段的待执行记录：恢复后允许只读核对，不再让 `list_dir`、`read_file` 等诊断因为这条旧记录直接报错。对尚不能证明结果的写入、发送和外部操作，仍保留待核实保护。

## 按步骤解卡

1. **先停止当前回合。** 按 Esc 或 Ctrl+C，等待回到就绪输入行。如果斜杠菜单正在显示，第一次 Esc 关闭菜单，再按一次停止。整行输入 `ESC`、`Escape`、`/cancel` 或 `/stop` 也会按取消处理；空闲时只显示“没有正在执行的任务”，不会再调用模型。
2. **查看待核实项。** 输入 `/reconcile`。输出包括调用编号、工具名和原因码。此命令只读取会话，不执行模型任务。
3. **核对实际目标。** 根据原调用和回执检查文件、进程、预览或远端服务状态。可以先请求只读检查；日志入口为 `koder logs --tail 100`。例如写文件要查看实际内容，发邮件要核对服务端记录，不能仅凭模型说“已经完成”。未知外部结果不要重复发送。
4. **记录人工核对。** 只有完成核对后，才输入 `/reconcile checked <调用编号>`，将尖括号及其内容替换为第 2 步显示的完整编号。一个命令仅处理一个编号；编号错误会报错并保留输入窗口。
5. **另发明确的新任务。** 例如“已核对现有文件，接下来只检查 Downloads 内的大文件，先不要删除”。确认不会自动续跑或重放旧命令，也不会代替新操作的批准。

确认记录持久保存，重开会话后仍在。原始 UNKNOWN 回执不会被改写为成功。`/reconcile` 没有待核实项时，无需确认，可直接提出新任务。后台 agentd 会话使用同一入口；无需关闭常驻服务。

## 不同提示如何处理

| 提示 | 含义和处理 |
| --- | --- |
| `LEGACY_PENDING_STATE_MISSING` | 旧记录缺少状态；新版允许诊断，仍需核对原操作。 |
| `INTERRUPTED_EFFECT_REQUIRES_REVIEW` | 进程中断留下未确认操作；查看原目标后再记录核对。 |
| `ERRORS_SUPPRESSED`、超时或进程清理未知 | 退出码或部分输出不足以证明副作用完成；保留原回执，勿自动重试。 |
| `RECONCILIATION_CALL_NOT_FOUND` | 编号不在当前待核实列表；重新输入 `/reconcile` 查看。 |
| `RECONCILIATION_TASK_BUSY` / `AGENTD_TURN_BUSY` | 当前仍在执行；先停止或等结束。运行中的 steer 补充不能解除保护。 |
| `RECONCILIATION_INTERACTIVE_REQUIRED` | `run --json`、脚本或 `--yes` 不能冒充人工核对；回到交互会话操作。 |

## 取消的边界

取消发生在工具真正发出之前时，新版记录“未执行”，不会再留下一个假的 UNKNOWN 锁。工具已经发出后，取消不等于撤销文件写入或远端提交；仍需查看回执和目标状态。晚到的模型回复不能在取消后启动工具。

会话、文件和历史回执均保留。取消不会清除旧操作证据，人工核对不会授予电脑权限。普通句中的 `escape this string` 或 `Explain ESC` 仍是正常任务。

## 验证范围

本版运行了隔离会话、928 条历史恢复、磁盘状态工具投影、取消时序、持久化和 agentd 本地通信回归。Windows 10/11 真实终端及用户原始会话的验收仍由 beta 专员执行；不把本机模拟结果写成 Windows 实机通过。
