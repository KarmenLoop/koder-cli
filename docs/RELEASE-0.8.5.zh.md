# Koder CLI 0.8.5

[English](RELEASE-0.8.5.md) · [简体中文](RELEASE-0.8.5.zh.md)

**已于 2026 年 11 月 3 日发布。** Koder CLI 0.8.5 已在官网发布，正式切换与 18 项定向 HTTPS 检查已核对。精确的 [Windows Server 2022 / Node 22.23.4 实测](https://github.com/KarmenLoop/koder-cli/actions/runs/41622933939)七项存储/账号检查全部通过。完整下载、续传、更新链路及公网 macOS 安装由产品负责人分别验收；独立官网 PUBLIC414、真人与原生桌面结果另列。

## 修复内容

- **Linux 先检查存储工具，再打开授权页。** 缺少 `secret-tool` 时直接报告原因。工具可以启动仍只返回 `not-probed`，不代表 Secret Service 已解锁；登录还必须完成受保护写入与读回。
- **临时身份核对失败保留原账号。** HTTP 429/503 或 HTML 网关错误被归为服务故障，不会仅凭这类响应认定凭据损坏。
- **取消与替换登录保留可核实的恢复路径。** 读凭据时取消不会触发刷新。新凭据写入后读回失败，会尝试在同一把锁内恢复并核实旧记录；无法验证恢复时明确报错，不宣称旧会话仍可用。
- **多窗口续期等待原操作完成。** 最多等待 45 秒，期间可以取消。`LOGIN_BUSY` 表示稍后重试，不需要删除活锁或账号文件。
- **Linux 按完整 UTF-8 解码凭据。** 中文和 emoji 跨管道分块时仍能正确读回；非法字节以 `INVALID_UTF8` 拒绝。已过期的保存授权不能启动任务，跳过远程核对的路径也不例外。

领取或轮换令牌的响应中断后，可能无法确认服务端是否已消费令牌，客户端不会盲目重放。模型、电脑权限、项目及原有 79 个 Skill 身份保留。私有内核有实现改动，不能描述为与 0.8.4 逐字节相同。

## 重新登录前先检查

```sh
koder --version
koder account status --json
koder account doctor --json
```

[登录教程](ACCOUNT-LOGIN.zh.md)说明浏览器授权、取消、换号与故障恢复。存储检查不代表身份已验证。账号网页由原负责人独立部署，CLI 包和隔离账号联测都不能证明生产页面已更新。保留原终端，浏览器或系统不能聚焦时手动切回。
