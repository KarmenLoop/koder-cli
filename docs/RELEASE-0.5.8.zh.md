# Koder CLI 0.5.8

后台邮件问询提醒在通知暂不可用、达到当天提醒上限或守护进程重启后，可以从已有持久记录恢复。继续使用原通知账本去重，已处理的旧提醒不会挡住后面的新提醒，也不会重复占用邮箱问询额度。

发件后未收到 SMTP 确认时，原有“不确定”回执现在会保留到 Agent 任务结果：任务返回未完成、退出码 3，不能误报发送成功，也不自动重发。服务器接受邮件与收件人真正收到仍分别记录。原生工具错误保留诊断原因码。

网站三稿比较之后，在终端问题里真实选择的方向可以由 `project_visuals select` 记录。只接受当前任务、当前三稿之后的回答，选项需以对应稿完整名称开头；旧回答、冲突、组合或否定答案不能冒充选择。浏览器选稿和明确委托 AI 选择的原流程保留；选稿不授权部署。

预览状态、打开和停止操作现在明确以当前进程为范围。另一个进程拥有预览时返回 `not-owned` 和外部状态未知，不会误说网站已经停止。Todo 版本冲突会告诉模型当前版本与重新读取的方法，避免盲目重试覆盖已有修改。

Ubuntu 使用完整运行包，新增 AT-SPI 控件驱动，接入原电脑授权和执行审批。X11/Wayland 使用同一套控件操作路径，不冒充像素截图或锁屏操作。验收矩阵覆盖 24.04 x64/ARM64，以及隔离的 24.10 用户空间；依赖、功能保留与验收边界见 [Ubuntu 说明](UBUNTU.zh.md)。

明确续接当前网站时会沿用可重新核验的源码证据；根任务绑定的完成状态可随会话持久保存。“不要重做”不再被误判成改版。请求同时提到浏览器观察和本地代码验证时，保留正常执行工具，不误切到缺少 shell 的应用操作配置。

## 安装与更新

Windows 使用本 Release 附带的 PowerShell/CMD 安装器，macOS/Ubuntu 使用 shell 安装器。已安装用户运行 `koder update`，完成后运行 `koder --version`，应显示 `0.5.8`。参见[安装说明](INSTALLATION.md)、[邮箱收发及恢复](MAIL-RECOVERY.zh.md)、[网站交付流程](website-delivery.md)、[任务结果与退出码](task-results.md)。

## 验证范围

附件 `ACCEPTANCE-RESULTS.json` 将源码回归、实际包内检查、隔离 macOS 更新及 MiniMax-M3 真实调用结果绑定到本版安装包。长任务完成了 33 次模型请求，生成的审计结果经过独立校验。邮箱使用真实模型和原生收件、阅读、发件工具，连接本地 TLS 测试服务器；模拟丢失确认的发件只接收一次。网站记录自动设计流程、测试用户回答、源码、选稿和预览检查。保留首轮失败，这些记录不作为盲测能力分数。

Windows 10/11 安装、GUI/MCP 与通知显示交给 beta 专员验收。真实 163 账号认证及收件人送达、Linux/macOS 通知实际显示、已签名的 macOS 锁屏操作未由本轮本地检查证明。提交系统通知不等于用户已经看到。仅更新 GitHub，生产官网不改动。

原 BYOK、Skills、权限、取消、费用预算、工作区隔离和未知副作用不重放规则保留；工具步数默认不设固定上限。
