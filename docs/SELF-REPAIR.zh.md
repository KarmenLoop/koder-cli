# 本机代码自修复（0.5.20 候选）

这项能力让 Koder 在本机生成、测试并启用自身功能模块的代码补丁。它与经验学习共用当前任务和模型预算，但授权单独保存。经验学习默认开启；执行新代码的自修复默认关闭，需要本机所有者明确开启。

## 开启、使用和撤回

1. 安装包含此功能的候选包，运行 `koder --version` 核对版本。此文档不表示候选已进入稳定更新渠道。
2. 运行 `koder setup`，选择“本机代码自修复”，阅读源码进入所选模型、执行代码和验证范围的说明，再选择“允许本机功能代码自修复”。也可以明确运行以下命令：

   ```sh
   koder self-repair on
   koder self-repair status --json
   ```

3. 在本地 `koder` / `koder chat` / `koder run` 描述 Koder 自身的错误，说明重现步骤、预期结果与实际结果。例如：“Koder CLI 的上下文用量显示遇到缺失诊断参数会抛出 TypeError，请用本机自修复检查，保留正常输入结果。”不用提供密码或 API Key。
4. 任务中的 `cli_repair` 工具先查询授权、允许修改的路径，再读取实际源码和 SHA；模型提交小补丁和结构化用例，宿主在两个独立子进程里验证旧版失败、新版通过，并保留已通过的回归用例。
5. 只有验证通过的候选可以启用。看到 `CLI_REPAIR_APPLIED` 表示补丁已保存，**下次启动**生效。当前回合不换代码、不重放已执行的任务。正常结束当前任务，再重新运行 `koder`。
6. 如需撤回：

   ```sh
   koder self-repair rollback
   koder self-repair off
   ```

   `rollback` 下次启动恢复发行包原代码；`off` 同时关闭后续自修复授权。二者在补丁未加载的恢复入口执行，关闭授权后仍能回退。macOS/Linux 也可用 `KODER_LOCAL_REPAIR=0 koder` 临时绕过补丁；PowerShell 用 `$env:KODER_LOCAL_REPAIR='0'; koder`，之后删除该环境变量恢复正常判断。

## 本版范围

`status` 的 `repairablePaths` 是实际允许列表。本版开放 7 个模块：上下文用量、上下文建议、任务质量提示、颜色、主题、启动图形、终端边框。邮箱协议、执行循环、权限、取消、费用、凭据、验证器、更新器及自修复控制器不在自动改写范围内。这些模块的问题仍需正式产品补丁，不能声称本机已自行修好。

任务中出现已识别的 CLI 内部错误，或用户明确要求修复 Koder 时，会自动给模型提供自修复工具和流程。普通项目任务不额外暴露此工具。未开启时它只报告授权状态，不因 `--yes` 自动取得授权。工作区交付契约不能借此修改工作区之外的 CLI；只读任务不能启用补丁。远程 Gateway / ACP / agentd 作业不能通过此入口改写本机安装。

每回合默认最多提出 2 个修复候选。所有模型步骤使用原任务的取消信号和金额预算，不额外启动学习模型、后台修复线程或付费子任务。它不训练基础模型，不保证考试满分，也不把缺题干、错误凭据或上游故障当作程序缺陷修补。

## 用例与证据

原生工具使用 JSON 文本保存用例类型，避免服务商把数值误变成字符串：

```json
{
  "path": "src/context-usage.mjs",
  "export": "contextUsage",
  "argsJson": "[]",
  "expectedJson": "{\"ratio\":1}"
}
```

`test` 使用精确 JSON 结果比较，数字 `1` 与字符串 `"1"` 不相等；失败回执包含有界的实际值、期望值和原因码。新增用例必须至少有一项在旧代码失败，候选全部用例及保留回归都须通过。仅添加注释、测试一直通过，不能当作修复证据。每个改动模块必须有用例。

测试进程不继承 API Key、Cookie、代理密码或 `NODE_OPTIONS`，限制文件读取，不授予文件写入、子进程与原生扩展权限，并有超时与取消。Node 权限机制用于防止误操作，[官方明确它不是恶意代码隔离环境](https://nodejs.org/docs/latest-v22.x/api/permissions.html)。启用后的补丁是本机可执行代码，拥有所属 CLI 进程能力；允许路径列表不是沙箱，也不能证明代码没有隐蔽行为。测试通过只证明这些用例，不代表全产品或全部平台验收。

## 储存、更新和故障恢复

补丁保存在 `KODER_CLI_HOME/self-repair/state.json`（默认 `~/.koder-cli/self-repair/state.json`），含当前、上一份和待验证候选。最多保存变更文件与有限回执，不复制整套安装包，不注册重复 Skill。发行包文件保持不变；启动加载器在原模块 URL 替换验证后的代码字节，原相对依赖与资源地址仍有效。

补丁绑定当前源码、原文件 SHA、修改后 SHA 和验证回执。正式升级、源码变化或补丁损坏会使旧补丁停用并使用原代码。若带补丁启动时有异常冒泡至 CLI 启动入口，记录 `CLI_REPAIR_START_FAILED`，下次启动停用同一补丁；当前任务不会自动重试。所有运行期故障、宿主崩溃和卡死并非都能由启动入口捕获；这时使用 `off`、`rollback` 或环境变量恢复，不要把本能力理解为无条件自愈。

| 原因码 | 含义与处理 |
| --- | --- |
| `CLI_REPAIR_DISABLED` | 本机所有者尚未授权，先在 Setup 开启。 |
| `CLI_REPAIR_PROTECTED_PATH` | 路径不属于本版允许修改模块；保留诊断，走产品更新。 |
| `CLI_REPAIR_NOT_REPRODUCED` | 旧版本用例未失败，不构成修复证明。 |
| `CLI_REPAIR_REGRESSION_FAILED` | 候选仍有失败，先核对实际值和期望值。 |
| `CLI_REPAIR_ATTEMPT_LIMIT` | 本回合候选次数用尽，保留证据并结束修复。 |
| `CLI_REPAIR_BASE_CHANGED` | 原版本已变化，旧补丁不再生效。 |
| `CLI_REPAIR_START_FAILED` | 带补丁启动失败，同一补丁已隔离，原代码可继续启动。 |
| `CLI_REPAIR_TASK_SCOPE` | 当前任务限定工作区，不能修改 CLI。 |

`status --json` 显示本机回执。补丁不自动上传到 GitHub、官网或云端；发行升级仍走独立发布流程。真实模型及各平台验收结论见同版验收记录，未运行的真机项目保留 `NOT_RUN`。
