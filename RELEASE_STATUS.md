# Koder CLI 0.5.9

The bundled Personal Agent Growth method is updated to [0.4.3](https://github.com/KarmenLoop/personal-agent-growth/releases/tag/v0.4.3). Native Agent tasks load a bounded, hash-checked source excerpt by default, including tasks without learning keywords. The original 61 core resources remain available through the Skill reader. Source-read metadata identifies the version, source commit and loaded ranges; it is not a model tool-call or learning-success receipt.

Learning stays on the existing Markdown runtime. `learning_read pack` now supplies typed write examples and current evidence references. Invalid writes explain how to recover without weakening scope, revision or hash checks. A completion proposal remains pending verification. The bundled portable Python host and SQLite examples are reference material; Koder does not run them or create a second learning store.

Under small context budgets, complete saved constraint and prohibition sections take priority over optional status and history. Partial memory is labeled as partial, and omitted sections remain retrievable. Current input, protected tool receipts and the model's input/output limit still apply. The native read-only `delivery_check` remains callable when resuming a code task, even without a website-creation keyword; directory discovery no longer advertises this tool while hiding its schema. Read-only continuation requests introduced by a colon no longer trigger a source-change requirement.

## Use and controls

Run `koder growth status` and `koder learning status` to inspect the bundled method and local task memory. `koder growth off` disables the method and learning path; `koder learning off` disables task-memory access independently. Existing off choices, no-memory mode and account/workspace/session isolation remain effective. See [the learning guide](docs/MARKDOWN-LEARNING.en.md) and [method integration](docs/AUTONOMOUS-LEARNING.md).

Windows, macOS and Ubuntu 24.04 use the same complete runtime. Run `koder update`, then check for `koder 0.5.9`. Fresh Ubuntu machines may lack `curl`; the [Ubuntu guide](docs/UBUNTU.md) now includes package-manager prerequisites and a download-to-file installation path. Installer or model credentials are never part of learning records.

## Evidence and limits

The release attachment `ACCEPTANCE-RESULTS.json` records source regression, exact-archive checks, isolated upgrade validation and bounded real-model exercises separately. It retains earlier failed attempts, including malformed learning writes, missing post-edit validation and a continuation that misrouted the delivery checker through Apps. Do not interpret these exercises as a blind quality score or a guarantee that every model will choose the right tool.

The pinned source remains AGPL-3.0-only with its license, notices and source link. Original provider/BYOK routing, budgets, cancellation, approvals and UNKNOWN-effect handling remain in force. Method loading adds no independent model request, background process or default comparison run. Normal task inference still uses the configured provider and budget.

Physical Windows, Ubuntu GNOME and visible notification acceptance remain separate device checks. Prior 0.5.8 Ubuntu X11/Wayland CI evidence is retained as baseline evidence, not relabeled as a new runtime pass. Signed macOS locked-screen operation remains an unsigned candidate. This release updates GitHub only; the production website is unchanged.
